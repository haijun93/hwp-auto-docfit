# Flutter 100% 전환 설계

작성: 2026-10-13 · 대상 브랜치: `alpha` · 목표 릴리스: 1.75

## 목표와 현재 상태

앱에서 사용자가 직접 보고 조작하는 모든 화면을 Flutter로 옮긴다. HWP/HWPX 처리와 한/글 COM 자동화는 Python에 남기되, Tkinter는 화면·대화상자·클립보드·파일 선택을 제공하지 않는 내부 호환 계층으로 축소한 뒤 제거 가능성을 별도 판단한다.

현재 Flutter Web은 문서 선택·작업 방식·진행·결과, 서식 선택/관리, 빠른 설정을 제공한다. Tk 창이 남은 주요 영역은 전체 설정, 세부 작업 수치 조정, 상세 작업 로그, 서식 프로필 세부사항·구조 검토, 텍스트 입력·붙여넣기, 문서 검토·교정·아웃라이너·작성 도구, 원본/결과 비교, 종료·오류 확인창이다. 기존 pywebview HTML 화면도 Flutter 빌드가 없을 때 대체 화면으로 선택된다.

따라서 Flutter 소스만 일부 작성하거나 기본 화면에서 Tk 창을 열도록 두는 것은 100% 전환 완료로 보지 않는다. 전환 완료는 아래 목록의 모든 사용자 경로가 Flutter 화면에서 수행되고, 테스트 중 사용자가 보는 Tk `Toplevel`이 하나도 뜨지 않는 상태다. 운영체제 파일 선택 대화상자는 Flutter 화면에서 시작해 결과를 받는 OS 공용 대화상자로 허용하되, 별도 Tk 창은 금지한다.

## 화면별 이관 목록

| 영역 | 현재 구현 | 전환 목표 / 합격 조건 |
|---|---|---|
| 주 작업 흐름 | Flutter 네 단계 화면 | 파일·폴더·텍스트 입력, 카드/단계/쪽 범위, 취소·진행, 결과 열기/탐색기까지 Flutter로 끝남 |
| 빠른 설정 | Flutter 서랍 일부 | 작업로그·검수 파일, 완료 창, 항상 위 표시 이관됨. 나머지 전체 설정 값·초기화·업데이트 확인도 Flutter에서 조작 |
| 세부 작업 | 선택 화면 일부는 Flutter, 상세 수치 창은 Tk | 모드별 순서·설명·기본값·숫자/목록 수치 옵션을 Python 스키마로 받아 Flutter에서 변경·저장 |
| 작업 기록 | 버튼이 Tk 로그 `Toplevel`을 열음 | Flutter 로그 창에서 갱신·검색/복사·지우기(작업 중 금지) 수행, 로그 본문은 일반 상태 폴링에 포함하지 않음 |
| 서식 관리 | 목록/이름 변경/삭제 등 Flutter, 분석 상세 창은 Tk | 이름·기관·서식 필드의 상세값, 구조 검토, 충돌·저장 오류·삭제 확인 모두 Flutter에서 처리 |
| 문서 입력/도구 | 일부 도구 메뉴가 Tk 창 연결 | 텍스트 붙여넣기, 문서 검토, 맞춤법/공공언어, 아웃라이너, 작성 도우미, Markdown·고급 도구를 Flutter 페이지/다이얼로그로 제공 |
| 결과/검토 | 기본 결과는 Flutter, 비교·세부 검토/종료 확인은 Tk | 원본·결과 비교와 결과 설명을 Flutter에서 제공. 오류·중단·종료 확인도 Flutter로 표시 |
| 실행/폴백 | Flutter Web→pywebview HTML→Tk UI 선택 | 배포 빌드는 Flutter 자산을 필수 검증하고 Flutter 렌더링 실패를 감지해 안전한 오류 화면을 제공. HTML/Tk 화면을 묵묵히 주 화면 대체로 쓰지 않음 |

## 권장 구조

```text
Flutter UI (상태·폼·탐색·다이얼로그·클립보드)
        │ 명시적 JSON 명령/응답, 버전 있는 스키마
        ▼
DesktopWebBridge (명령 허용목록, 입력 검증, 작업 잠금)
        │ Tk 스레드에는 기존 호환 변수/작업 큐만 안전하게 전달
        ▼
Python 문서 처리·설정·COM 서비스 (UI 위젯에 의존하지 않도록 단계적으로 분리)
```

- Flutter가 UI 상태의 소유자이며, 화면은 `get_state` 스냅샷과 작업 이벤트를 기반으로 그린다. 긴 본문·대량 로그는 별도 `get_log` 등 온디맨드 호출로만 전달한다.
- Python API는 읽기/쓰기·도구 명령을 분리하고 이름·타입·범위를 allowlist로 검증한다. pywebview에는 `DesktopWebBridge`의 UI 명령만 공개하고 `gui`, Tk 객체, COM 객체를 노출하지 않는다.
- 설정 변경은 기존 저장·검증 함수를 호출하여 값의 의미를 유지한다. 양방향 동기화에서 Flutter 폴링 결과가 사용자의 편집 중인 값을 덮지 않도록 revision/version을 포함한다.
- 처리 중 금지된 설정과 위험 명령은 Flutter에서도 비활성화하고 Python 브리지에서도 다시 차단한다(화면 검증만 신뢰하지 않음).
- 작업 취소·오류·시간초과는 구조화된 `ok/error/code/message` 응답을 사용하며 Python traceback, 문서 본문, 민감 경로는 기본 UI/로그에 과다 노출하지 않는다.

## 단계별 실행 계획

1. **사용자 창 인벤토리와 브리지 계약**: 모든 `Toplevel`, 메뉴, 대화상자, 파일 입출력 경로를 매핑한다. API 스키마, 상태 전이, 작업 중 잠금, 오류 코드를 문서화한다.
2. **작은 반복 화면 제거**: 로그 보기/복사/지우기와 설정의 단순 옵션을 Flutter로 옮긴다. 기존 설정의 저장·작업 중 잠금을 회귀 테스트한다.
3. **전체 설정·세부 단계**: 간격/서식/문서/고급/기록 카테고리를 Flutter 페이지로 옮긴다. 체크박스뿐 아니라 숫자·텍스트·색상·목록 입력, 빠른 프리셋, 기본값 초기화, 업데이트 확인을 포함한다.
4. **서식 프로필 편집**: 예시 분석 결과·서식 구조를 필드 기반 JSON으로 보내고, 대표값/표 칸(A1/A2 등) 편집·검증·저장·미리보기를 Flutter로 옮긴다.
5. **문서 도구와 보조 창**: 텍스트 입력, 검토, 교정, 아웃라이너, 작성 도우미, 비교 보기, 오류/종료 확인을 각각 Flutter 화면으로 전환한다. 도구별 기존 동작을 독립 회귀시험한다.
6. **기본화·잔여 Tk 제거**: alpha 패키지에서 Flutter 자산 생성·무결성을 필수로 하고 런타임에서 Flutter UI를 선택한다. 사용자 작업 흐름 중 Tk 창이 뜨지 않는 Windows 실기기 테스트를 거친다. 과거 HTML/Tk 전체화면 폴백은 제거하거나 개발자 전용 진단 모드로 격리한다.
7. **1.75 승격 게이트**: 전체 Python/Flutter 테스트, Windows + 한/글 COM 사용자 흐름, 설정·문서·로그 보존 검사, 접근성/화면 크기 검사, 전체 UI parity 체크리스트 완료, 정식 Beta 대비 품질 및 성능 비저하 비교, 코드 리뷰와 실행파일 해시 확인을 모두 통과해야 한다. 미통과면 1.75 태그·배포를 하지 않는다.

## 시험 및 완료 기준

- Flutter `dart analyze`, `flutter test`, Release Web build 통과.
- Python 브리지 단위 시험에서 모든 허용 명령·입력 오류·작업 중 잠금·설정 저장을 검사.
- 화면 폭 420px/1024px 이상, 키보드 전용, 200% DPI와 긴 문구·빈 목록·오류·장시간 작업 상태를 확인.
- Windows 자동 스모크에서 Flutter 자산 로드, 파일 선택→작업 시작→중단/완료→결과 열기, 설정 저장, 로그 복사, 서식 분석·편집을 수행하며 Tk `Toplevel`이 나타나면 실패.
- 테스트 문서는 사본으로만 사용한다. 실제 COM 시험 전·후 입력 SHA-256 동일성을 확인한다.
- 최종 Beta 비교는 이전에 만든 `scripts/compare_versions_pc.py`로 동일 PC/동일 입력을 교차 반복한다. 속도 향상을 요구하지 않고, 품질 하락은 0건, 성능은 반복 쌍의 차이와 신뢰구간으로 비저하만 판정한다. UI 전환이 원인인 별도 UI 응답성/시작 메모리 측정도 기록한다.
