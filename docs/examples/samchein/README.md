## 무엇을 보여 주나요?

실제 앱의 문서 처리 함수를 한/글 자동화 환경에서 실행하고, 결과를 한/글 자체 PDF 출력으로 얻어 안내 영상에 넣었습니다. 화면 기록 도구를 사용할 수 없어 **실제 클릭 화면 대신 결과 기반 안내 애니메이션**을 제작했습니다. 문서의 전후 모습을 임의로 그리거나 생성형 이미지로 바꾸지 않았습니다.

TXT에는 글꼴·쪽 설정이 없습니다. 비교의 ‘전’은 앱이 TXT를 작업용 HWPX로 변환한 직후입니다. 두 작업은 같은 원문의 독립 사본으로 실행했으며, 자간 정리 결과에 한 번에 적용을 이어서 실행한 것이 아닙니다.

| 항목 | 자간 정리 | 한 번에 적용 |
|---|---|---|
| 작업 선택 | 자간 정리 | 한 번에 적용, 기본 보고서 서식 |
| 옵션 | 기존 자간 초기화 켬, 표 제외 끔 | 자간 포함 켬, 표 제외 끔, 페이지 맞춤 제외 끔 |
| 결과 이름 | 삼채인(자간조정).hwpx | 삼채인(일괄적용).hwpx |
| 실제 쪽 수 | 2 → 2 | 2 → 3 |
| 처리 시간 | 약 2분 3초 | 약 5분 35초 |
| 주요 변화 | 개요의 갈라진 단어 모으기 | 제목·개요·일반 표 생성, 기호별 서식·배치 정리 |

시간은 이 PC에서 한 번 측정한 문서 처리 시간이며 영상 제작 시간은 제외했습니다. 성능 보장이나 두 기능의 일반적인 속도 비교가 아닙니다. 실행 당시 앱 표시 버전은 **1.69 Beta 18**(배포 커밋의 코드)입니다. 기록의 코드 SHA-256은 본체 파일 기준이며 전체 작업 트리의 해시는 아닙니다.

## 영상 순서대로 따라 하기

| MP4 시간 | 자간 정리 | 한 번에 적용 |
|---|---|---|
| 0–6초 | 문서 추가에서 원문 TXT 선택 | 같은 원문 TXT를 새로 선택 |
| 6–12초 | 자간 정리와 옵션 확인 | 기본 서식과 자간 포함 등 옵션 확인 |
| 12–18초 | 정리 시작 후 줄 끝 확인 | 정리 시작 후 제목·개요·표 확인 |
| 18–24초 | 개요 문장 전후 비교 | 보고서 모양 전후 비교 |

자간 정리에서는 `거점(지구)`가 -3%, `수립하여`가 -2% 자간으로 앞줄에 모였습니다. 이 값은 이번 문서에서 앱이 찾은 값이며 사용자가 일괄 입력해야 하는 설정값이 아닙니다.

한 번에 적용에서는 `제목 :`와 `개요 :`를 표로 바꾸고, 박스 문자 표 한 개를 실제 표로 바꿔 총 표가 0개에서 3개가 되었습니다. 첫 쪽 제목 아래 날짜·담당자·전화번호는 기본 양식에서 추가한 예시 값입니다. 제출 전에 실제 값으로 수정하세요.

## 검수 결과와 한계

- 두 실행 모두 결과 HWPX 저장과 한/글 PDF 출력이 완료됐으며 실행 직후 원문 해시가 변하지 않았습니다.
- 자간 정리의 저장 후 단어 검사는 5건, 한 번에 적용은 본문 단어 1건·표 등 내부 단어 2건·쪽 배치 51건을 검사했고 보고된 오류는 0건이었습니다. 문서의 모든 요소를 전수 검증했다는 의미는 아닙니다.
- 최종 보고서의 판정은 두 실행 모두 **‘부분 달성’**입니다. 실행 도우미가 세부 작업 선택 목록을 명시하지 않고 기본 경로를 호출하여, 최종 보고서에 **‘최종 규칙 검수 범위가 확인되지 않음’**이 남았습니다. 점수 100만 보고 완전 검증으로 해석하면 안 됩니다.
- 한 번에 적용의 무결성 검사에는 본문 유사도 **86.9%**와 표 수 **0 → 3** 경고가 있습니다. 별도로 표 칸을 포함한 HWPX 텍스트를 비교했습니다. 공백·박스 선 문자를 제외하면 차이는 제목·개요 라벨 제거와 기본 양식의 날짜·담당자 행 추가였고, 그 밖의 글 내용 변경은 발견되지 않았습니다. 이는 서식·배치 100% 보존을 뜻하지 않습니다.
- 전체 결과 3쪽을 출력 이미지로 확인했습니다. 실제 작업에서는 원문 대조, 숫자·표 셀, 문장 끝, 쪽 나눔을 다시 확인하세요.

결과 HWPX와 원시 로그는 로컬 실행 폴더에 보관합니다. 사용자 이름 등 문서 메타데이터나 로컬 경로가 섞일 수 있어 공개 예제에는 TXT·출력 이미지·요약 기록만 포함합니다.

## 개발자: 예제 다시 만들기

저장소 루트에서 실행합니다. 한/글과 앱의 보안 모듈 등록이 완료된 Windows 환경이 필요합니다. 기존 출력 폴더를 덮어쓰지 않으므로 매번 새 `--out` 경로를 사용하세요. 작업용 사본을 만들며 사용자 원문·저장된 앱 설정은 변경하지 않습니다.

```powershell
.\.venv\Scripts\python.exe scripts/build_readme_demo.py "docs/examples/samchein/삼채인.txt" --out reports/my-readme-demo --mode spacing
.\.venv\Scripts\python.exe scripts/build_readme_demo.py "docs/examples/samchein/삼채인.txt" --out reports/my-readme-demo --mode all
# 아래 패키지는 영상 제작용이며 일반 앱 사용에는 필요하지 않습니다.
.\.venv\Scripts\python.exe -m pip install Pillow pypdfium2 imageio-ffmpeg
.\.venv\Scripts\python.exe scripts/render_readme_demo.py reports/my-readme-demo --output reports/my-readme-demo/media
```

현재 버전으로 재실행하면 서식이나 쪽 수가 바뀔 수 있습니다. 영상의 문구·확대 영역은 이 사례의 결과를 기준으로 작성했으므로 새 출력과 일치하는지 확인한 뒤 게시하세요.
