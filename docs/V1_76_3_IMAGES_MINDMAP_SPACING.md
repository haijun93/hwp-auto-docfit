# v1.76.3 변경 설계·검증

□ 이미지 변환
ㅇ 파일포맷 변환 입력 집합에 BMP/TIFF/GIF 추가. 엔진 고유 지원 집합은 유지.
ㅇ Pillow에서 방향·투명도·프레임을 정규화한 PNG를 kordoc --ocr로 파싱한 후 HWPX 생성.
ㅇ 같은 경로의 기존 결과는 덮어쓰지 않으며 임시 산출물 검증 후 hard link로 게시.
ㅇ PP-OCRv5 det/한국어 rec/사전의 SHA256은 kordoc 4.21.30 상수와 일치시킴.
ㅇ onnxruntime-node 1.30.0 및 sharp 0.35.5를 별도 lockfile로 고정. Windows x64 바이너리만 배포.
ㅇ 모델·라이선스를 빌드 시 포함. 실행 시 KORDOC_OFFLINE=1 및 내장 모델 캐시 사용.
ㅇ 동일 kordoc 버전의 이전 런타임은 bundle_revision 비교로 OCR 포함본으로 교체.

□ 마인드맵
ㅇ 나무 데이터에 position 및 edge 메타데이터 보존. 화면·SVG·PNG가 같은 좌표 사용.
ㅇ 최초 드래그 시 전체 현재 배치를 고정하여 다른 가지가 자동 이동하지 않도록 처리.
ㅇ 부모 변경 시 자식·후손 유지, 자기 자신/후손 연결 차단. 연결선만 삭제해도 가지 유지.
ㅇ 깊이 자체에는 고정 제한 없음. 메모리·화면 보호를 위한 가지 300개 및 출력 크기 제한 유지.

□ 자간
ㅇ 기존 경로는 서식 불일치 문장에만 마무리 작업을 예약했음.
ㅇ unify_spacing이 켜져 있으면 서식 통일 후 기존 본문 전체 자간·단어 분리 및 짧은 줄 함수를 실행.
ㅇ 표 자간 사용 설정이 켜진 경우에만 컨트롤 영역도 검사. 쪽 맞춤 전에 실행.
ㅇ 기존 알고리즘의 한/글 실측·시도 한도·실패 복원·쪽 범위 로직 재사용.

□ 검증
ㅇ Python 전체 1,220개: 실패 0, 조건부 제외 5 (Linux).
ㅇ Flutter 71개 및 JS 모델 20개 통과.
ㅇ 브라우저 실제 마인드맵 드래그·중첩 가지 생성·연결선 편집·저장/복원·PNG 출력 통과.
ㅇ Windows CI에서 EXE 실제 창 버전, 별도 ZIP 없는 런타임 설치 및 실제 한국어 이미지 OCR→HWPX를 필수 검사.
ㅇ 실제 한/글 2020 문서의 조판 결과·OCR 정확도 전수 평가는 별도 실기기 검증 대상.

□ 배포 경로
ㅇ OCR 포함 EXE가 Git 파일 제한을 초과할 수 있으므로 릴리즈 빌드에서 draft 자산으로 업로드.
ㅇ 저장소에는 build-source.txt, build-delivery.json, SHA256SUMS, windows-ui-smoke.json만 기록.
ㅇ 태그 작업은 빌드 출처·소스 차이·draft 대상 커밋·다운로드한 EXE 해시를 검증한 후 게시.
