# Alpha 4 재검토 — 개선사항

검토 기준: `07ceecb`(1.74 Alpha 4). 작업 트리는 검토 시작 시 깨끗했다. 기존 실패·오류 22개 해결은 유지되지만, 전체 시험 통과가 모든 입력의 내용 보존과 Windows 실동작을 보장하지는 않는다. 이번에는 변경된 숫자 위계 문법·실제 변환 진입점·설정 서비스·시험 기반을 집중 확인했다. 코드를 수정하지 않고 임시 자료로 재현했으며 전체 시험은 반복하지 않았다.

## P1 — 숫자 위계 문법이 버전·소수를 삭제 (새로 재현)

근거: `docfit_core/ai_answer.py:31`, `:91`, `:158`와 앱 `hwp-auto-docfit.py:18248`.

```text
입력:
1.74 버전을 사용합니다.
2.50 금액입니다.

looks_like_ai_answer → True
ai_answer_to_outline_text →
□ 버전을 사용합니다.

□ 금액입니다.
```

Alpha 4의 소수점 번호 지원이 `1.1` 목차와 `1.74` 버전/수치를 구분하지 못한다. 두 줄이면 자동 판별 조건까지 만족하므로 실제 텍스트 변환 경로에 도달한다. 숫자 삭제는 일반 파일에도 영향을 줄 수 있다. 단순히 숫자 정규식을 넓히는 대신 부모 목차·주변 형제·제목 문맥에서 계층 번호라는 증거가 있을 때만 제거해야 한다. 모호하면 숫자를 보존한다. 버전·소수·금액·날짜와 진짜 `1. → 1.1 → 2.` 계층을 함께 회귀시험에 추가해야 한다.

## P1 — 코드 인덱스와 민원 안내 문장 손실 (잔여 문제 재확인)

`pasted_text.py:137`은 inline code 보호 전에 숫자 출처를 제거한다. `clean_pasted_text("`items[1]`")`의 결과는 여전히 `items`다. `ai_answer.py` 전체 정규화도 코드 블록 분리 전에 출처/HTML 태그를 처리한다.

또한 `## 안내\n- 정비를 추진합니다.\n\n더 궁금하신 사항은 담당자에게 문의해 주세요.`에서 마지막 문의 문장이 사라진다(`ai_answer.py:203`). 민원 공문 본문과 AI 후속 제안을 문자열 일부만으로 구분하기 어렵다.

코드·수식·URL 보호 범위를 먼저 분리하고, 공문 붙여넣기에서는 본문 보존을 기본으로 해야 한다. 후속 제안 삭제는 별도 선택/명확한 문맥에 한정한다. 원문 인사·담당자·날짜·전화·본문의 유효 문자와 수치를 비교하는 시험이 필요하다.

## P1 — 설정 서비스 간 동시 갱신 유실 (이번에 실제 재현)

근거: `docfit_app/settings_service.py:14`의 잠금은 인스턴스별이고, 앱 `hwp-auto-docfit.py:5094`의 전체 저장 경로는 여전히 직접 덮어쓰기다.

같은 임시 설정 파일에 SettingsService 두 개를 만들고 Barrier로 두 read-modify-write를 겹치게 했다. 하나는 `a=True`, 다른 하나는 `b=True`를 추가했다. **두 요청 모두 성공했지만 최종 파일은 `{"base":true,"b":true}`로 `a`를 잃었다.** 실제 앱이 반드시 이 경쟁을 일으킨다는 뜻은 아니지만 서비스가 경로 단위 동시 쓰기를 보장하지 못함을 확인했다.

공유 저장 서비스를 단일 writer로 연결하고 같은 정규화 경로의 갱신을 직렬화해야 한다. 기존 전체 저장도 최신 파일에 필드 변경을 적용하는 공통 경로로 통합한다. 원자 교체는 파일 손상을 막지만 동시 갱신 유실을 막지는 못한다. 두 성공 요청의 변경과 준말·다른 설정이 모두 남는 시험을 추가한다.

## P1 — snapshot 입력 제한 누락 (코드상 여전히 미수정)

`docfit_core/fidelity/package.py:66,134`은 여전히 파일 전체를 읽고 제한 없는 압축 해제를 한다. 일반 HWPX 검증의 크기·개수·압축률 정책과 일치하지 않는다. 이전 압축률 재현은 기존 보고서에 있으며 이번에는 코드 변경 여부를 확인했다. 공통 안전 정책을 snapshot load/read에도 적용하고 최대 해제 길이·동일 자료 검증을 보장해야 한다.

## P2 — 굵은 본문을 제목으로 승격

`ai_answer.py:167`은 굵게만 작성된 문장을 제목으로 본다. `**안녕하십니까.**\n\n**감사합니다.**`는 `□ 안녕하십니까.`와 `□ 감사합니다.`가 된다. 서식 기호 제거 자체는 성공하지만 문장의 기능을 정확히 분류한 것은 아니다. 문장 종결·길이·문맥을 고려하고 원문 제목/본문 역할이 불명확하면 본문으로 보존한다.

## P2 — GUI CI가 실제 화면 시험을 수행했는지 강제 확인 필요

Alpha 4의 실제 GUI 재현으로 기존 22개 전부 통과한 결과는 유효하다. 다만 `tests/gui_support.py:17`은 모든 TclError를 skip으로 바꾼다. 새 CI에서 TkDND 라이브러리 호환 문제가 나도 GUI 시험이 skip되어 성공할 수 있다.

CI에서 먼저 실제 TkDND root 생성/파괴를 검사하고 실패하면 job을 실패시킨다. 원래 22개 시험은 skip 0을 별도로 확인한다. headless 개발 실행에서는 의도한 GUI skip을 유지하되 CI의 실제 GUI 보장은 따로 강제한다. helper가 root.destroy 시 예약 콜백을 취소하는 것은 직접 root를 파괴하는 시험의 정리 책임이며, 실제 앱 종료/지연 요청 시험을 대신하지 않는다.

## P2 — 미완료 기능과 최적화

- 직함·콜론·이름 의미단위는 아직 실제 자간 조정 경로에 연결되지 않았다. `과(동)장: 홍길동`·`팀장: 이순신`·`주무관: 홍당무`의 내부 줄 경계를 전부 시험하고 쉼표/전화/다음 담당자에서 병합을 막아야 한다.
- Flutter 전체 설정/서식 상세/문서 검토 이관과 Tk 독립 서비스 계층은 아직 부분 구현이다.
- ZIP 중복 이름 집합 재생성, 중복 CRC 검사, 매초 전체 상태 재생성은 이전 보고서의 최적화 항목으로 남아 있다. 이번에 개선율을 측정하거나 수정하지 않았다.

## 권장 순서

1. 버전/소수의 번호 오인과 본문 손실부터 수정한다.
2. 설정 저장 단일화와 snapshot 안전 정책을 적용한다.
3. 실제 GUI 실행을 CI에서 강제하고 Windows 실문서 검증을 수행한다.
4. 직함·이름 의미단위 및 Flutter 잔여 기능을 구현한다.
5. 동일 문서 코퍼스에서 I/O·UI 비용을 측정한 뒤 최적화한다.

이번 새 재현은 기존 통과 시험에 없는 입력/동시성 사례다. “기존 22건 해결”과 “제품의 남은 결함 없음”은 별도의 판단이다. 공개 main은 변경하지 않았고, Windows COM·WebView2·EXE는 이번 리뷰에서 실행하지 않았다.
