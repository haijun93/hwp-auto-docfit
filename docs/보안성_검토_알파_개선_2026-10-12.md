# 보안성 검토 반영 — 알파 개선 설계와 평가 (2026-10-12)

기준: `docs/보안성_검토_최고수준_2026-10-12.md`의 S1~S9. 이번 변경은 최신 `github/alpha`에서 분리한 작업 트리에서 적용했다. 사용자 문서는 열거나 변경하지 않았다.

## 적용한 설계

| 항목 | 변경 | 효과와 한계 |
|---|---|---|
| S2 HWPX ZIP | `open_hwpx_safely()`를 공용 읽기 경계로 추가했다. 메인 앱의 HWPX 읽기 호출과 분석·검수·교정·서식 모듈에서 열기 전에 기존 항목 수, 압축률, 총 해제 크기, 경로·링크 및 CRC 검사를 거친다. 쓰기용 ZIP은 그대로 둔다. | 입력 처리 약 30개 경로에서 개별 실수로 검증을 빠뜨릴 가능성을 줄였다. 상한을 넘거나 손상된 아카이브는 내용 읽기 전에 거부한다. 전체 CRC 검사를 수행하므로 큰 HWPX는 이전보다 읽기 전 검증 시간이 늘 수 있다. 미리보기 썸네일은 본문 HWPX가 아닐 수도 있어 별도의 미리보기 전용 경로로 유지했다. |
| S3 kordoc | 설치된 kordoc을 우선 사용한다. 설치본이 없을 때 `npx` 다운로드는 기본 차단하고, 사용자가 `DOCFIT_ALLOW_NPX_DOWNLOAD=1`로 명시 동의한 경우에만 고정 버전 실행을 허용한다. 허용 경로에는 `--ignore-scripts`를 추가했다. | 앱 실행 중 원격 npm 패키지를 묵시적으로 받아 코드 실행하는 경로를 기본값에서 제거했다. 명시 허용 경로도 전이 의존성을 lockfile/hash로 고정한 것은 아니므로 공급망 위험이 완전히 없어지지는 않는다. |
| S7 WebView 파일 브리지 | 한 번에 전달하는 경로를 최대 100개, 경로 문자열을 32,767자로 제한한다. 심볼릭 링크를 거부하고 실제 경로를 resolve하며, 일반 파일은 지원 확장자만 통과시킨다. 폴더 선택은 기존 동작을 유지한다. | 브리지 입력 폭주·임의 파일형식 전달·링크 경유를 제한한다. 경로는 로컬 UI와 운영체제 사용자 권한 범위에서만 의미가 있고, Windows 재분석 지점 등 모든 파일시스템 특수 사례를 완전히 차단했다고 보지는 않는다. |

## 이번 변경으로 완료하지 않은 항목

- **S1 높음 — 업데이트 신뢰근원 분리:** 현재 SHA-256은 실행 파일과 같은 릴리스 계정에서 얻는다. 독립 서명 키/Authenticode 서명 검증은 키 보관·서명·회전과 배포 절차가 함께 필요해 미구현이다. 기존 해시 검증만으로 계정 탈취 위험까지 막는다고 볼 수 없다.
- **S4 — 업데이트 교체 스크립트:** 업데이트 코드가 사용자 쓰기 가능 위치의 `.ps1`을 실행하는 구조는 이번 변경에서 바꾸지 않았다. `-EncodedCommand`로 바꾸려면 Windows PowerShell에서 다중 PID 인자 바인딩과 롤백까지 실동작 검증이 필요하다.
- **S5 — 빌드 공급망:** GitHub Actions의 SHA 고정, 완전한 해시 잠금 의존성, SBOM/attestation은 미적용이다. 현재 `requirements.txt`가 전이 의존성을 고정하지 않아 일부 버전만 임의로 고정하지 않았다.
- **S6 — CSP:** pywebview 브리지의 스크립트 주입·통신 정책과 Flutter 화면을 함께 검증하지 않고 CSP를 적용하면 UI를 깨뜨릴 수 있어 미적용이다.
- **S8:** 검토 당시 확인된 `NamedTemporaryFile(delete=False)`는 `finally` 삭제 경로가 이미 있다. 이번에는 변경하지 않았다.
- **S9:** 보안 DLL의 전체 출처·공급자 서명 증거를 별도 확보하지 못해 출처 정보를 추정해 기록하지 않았다.

## 검증 및 개선효과 평가

- 새 회귀시험: HWPX 안전 열기의 정상/쓰기 차단 1건, kordoc 자동 다운로드 기본 차단 및 명시 허용·스크립트 차단 2건.
- 집중 회귀시험: 관련 9개 시험 모듈, **86개 통과** (Python 3.14 로컬 환경; Windows 한/글 COM 실사용은 검증하지 않음).
- 정적 확인: `py_compile` 대상 앱·브리지·HWPX·업데이트 모듈 통과, `git diff --check` 통과.
- `hwp-auto-docfit.py`는 CRLF **25,934줄 전체를 유지**했다.
- 전체 테스트 `python -m unittest discover -s tests`는 별도로 실행 중이다. 결과를 확정하기 전까지 전체 회귀 통과로 표기하지 않는다.

## 후속 우선순위

1. S1: Ed25519 공개키 내장 서명 메타데이터 설계와 서명키 운영 결정, 서명 검증 시험. Authenticode는 인증서 취득·서명 배포 권한 결정이 선행돼야 한다.
2. S4: PowerShell 5.1과 Windows 업데이트 실환경에서 `-EncodedCommand` 호출·인자 escaping·PID 대기·교체/롤백을 시험한 뒤 사용자 쓰기 가능 스크립트 제거.
3. S5: CI 의존성 해시 잠금 파일과 action SHA 고정, 쓰기 권한을 빌드/게시 작업으로 분리하고 provenance 산출.
4. S6: pywebview와 Flutter 양쪽의 실제 CSP 위반 로그를 수집한 후 최소 정책 적용.
5. S9: DLL 원본 저장소/라이선스·공급자 서명·SHA-256을 확인해 출처 문서화.
