# 핫픽스 전 배포 다운로드 중지

사용자 지시: GitHub·GitLab 저장소는 공개로 유지하고 배포 파일 다운로드를 중지한다.

- GitHub: 공개 릴리즈 26개를 초안으로 전환. 첨부파일·릴리즈 설명은 삭제하지 않고 보존한다.
- GitHub: Actions를 저장소 설정에서 비활성화해 재배포를 중지했다. 기존 EXE 빌드 아티팩트 193개를 삭제했다(원래 아티팩트 복원 불가, 소스에서 재빌드 필요). 남은 아티팩트 4개는 보안 검사 SARIF이며 프로그램 배포 파일이 아니다. 실행 중인 워크플로는 없었다.
- GitLab: 로그인된 프로젝트 관리 화면에서 Releases를 Only Project Members로 제한하고 CI/CD 및 Package registry를 비활성화했다. 공개 저장소 자체는 유지한다.
- 양쪽 최신 릴리즈 EXE 및 GitHub 기존 26개 릴리즈 EXE의 비로그인 HEAD 요청은 404였다.
- GitLab main의 저장소 직접 배포 EXE도 별도 커밋 `18b3f96`으로 제거했고 raw/main EXE의 비로그인 HEAD 요청은 404였다. GitHub main에는 해당 EXE가 없다.
- 양쪽 README 공지를 게시했다. 웹사이트 소스의 다운로드 버튼도 비활성화했지만 CI/CD를 중지했으므로 기존 Pages의 재배포 완료를 뜻하지 않는다. 기존 페이지 버튼이 가리키는 릴리즈 다운로드는 차단돼 있다.

## 중요한 한계

공개 Git 이력의 과거 EXE blob·태그 직접 다운로드는 남는다. 이력 재작성·강제 푸시 또는 저장소 비공개 전환 없이 이를 완전히 차단할 수는 없다. 사용자는 비공개 전환을 원하지 않았다. 기존에 내려받은 파일, 외부 복제본 및 이미 발급된 일시 다운로드 URL도 회수할 수 없다.

## 재개 절차

핫픽스를 검증하기 전에는 Actions/CI/CD를 임의로 재활성화하거나 이전 릴리즈를 공개하지 않는다. 핫픽스 빌드가 필요할 때만 통제해서 빌드를 재개하고, 검증한 새 릴리즈만 게시한다. 이전 릴리즈 일괄 공개는 하지 않는다. GitLab 기능·접근 범위와 README/웹사이트 공지를 함께 검토한다.

릴리즈/아티팩트 메타데이터의 로컬 백업과 HTTP 검증 기록은 `scratch/download-hold-20261016/`에 보관한다(토큰 없음).
