# 1.80.10 알파: 항목기호 뒤 HWPX 탭 인식 개선

- 원본 ‘1. 보고서_예시.hwpx’와 수작업 결과 ‘2. 보고서_예시_사용자 수정파일.hwpx’, ‘수정 전후.hwpx’를 읽기 전용으로 비교했다. 사용자 원본은 변경하지 않았다.
- 원본의 항목기호 문단 33개에 hp:tab이 있었다. batch_format.plain_text와 _문단_일반글은 자식 제어 요소가 있는 문단을 보수적으로 제외하므로 33개 모두 순수 XML 일괄 서식 대상에서 빠졌다. 일반 t.text만 읽는 경로에서는 탭 뒤 tail도 누락될 수 있었다.
- 새 marker_spacing은 본문 직속 항목 문단의 기호 직후 구분자만 U+0020 1개로 정리한다. Run의 글자 모양 참조와 본문·본문 내부 탭·표·필드를 보존한다. 새 작업용 사본을 먼저 검사해 생성하고, 서식 적용/한 번에 적용/서식 통일은 이 사본으로 연다. 자간/쪽 맞춤 전용 모드에는 문자 정리를 추가하지 않는다.
- 실제 원본 사본에서 33개 문단을 정리했고 기호 문단의 hp:tab은 33→0개, 순수 일괄 서식 가능 문단은 0→29개였다. 나머지 4개는 본문 내부의 다른 인라인 요소를 보존하여 기존 COM 경로로 처리한다. 정상 원본 파일 SHA-256은 변경되지 않았다.
- 수작업 예시에도 본문 없는 기호/탭 줄 2개가 있으므로 전체 수작업 파일을 무조건 불변 규칙의 정답으로 보지 않는다. 표·그림·줄 배치까지 수작업 결과와 100% 같다고 주장하지 않는다.
- 2026-10-25 규칙에 맞춰 기호 뒤 여는 낫표의 ‘빈칸 없음’ 예외를 폐기했다. 기호 앞 ㅁ/□ 0개·ㅇ/○ 1개·- 3개는 분석 관찰값과 분리해 실행 규칙/프로필 적용 시 우선한다. *·**는 기존 부모 연동 규칙을 유지한다.
- 테스트 대역의 빈 가짜 HWPX는 새 전처리 I/O를 모킹하여 기존 파이프라인 순서 검사의 경계를 유지했다. 새 전처리 자체는 실제 ZIP/XML 사본과 인라인 탭·Run/tail·고정폭 공백·재적용·원본/표 보존 시험으로 별도 검증한다.
- 관련 선택 검사 113개 중 112개 통과, Windows PowerShell 통합 1개 조건부 제외. 별도 확장 검사 103개 및 파이프라인/기준 서식 검사 41개도 통과했다. Windows 전용 모듈만 대체하고 실제 Tk는 Xorg dummy 화면에서 실행했다. 최종 전체 결과는 후속 검증 기록을 따른다.
- 이 변경은 알파 소스이며 공개 EXE/태그 배포를 수행하지 않았다. Windows 한/글 2020 COM 실측 및 format_fidelity_pc.py의 예시 전종 재연 검증은 이 Linux 환경에서 실행하지 못했으므로 정식 배포 전 필수 게이트로 남긴다.
