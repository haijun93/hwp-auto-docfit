# K에이전트 설계서 — 초경량·최고속도 상주 프로그램 (K클립보드 + 타임머신 감시)

2026-11-01 사용자 지시: **K클립보드와 타임머신은 초경량·최고속도로 작동하도록 설계하고, 필요하면 기존 exe와 독립된 exe로 만든다.**
결론(설계 제안): **독립된 작은 상주 프로그램 `kagent.exe`(가칭 "K에이전트")를 따로 만든다.** 기존 앱(파이썬+Flutter+WebView2+한/글 COM+Node/OCR 런타임 약 160~220MB)은 화면이 필요할 때만 뜨고, **기록·감시·빠른 팝업은 항상 떠 있는 작은 에이전트가 맡는다.** 이전 설계의 "같은 exe의 `--kclip` 감시 전용 모드"를 이 문서가 **대체**한다.
이 문서는 설계이며 구현·시험·측정 결과가 아니다. 아래 크기·메모리·속도 수치는 **일반적인 경험치(목표)**이고 이 환경에서 측정하지 못했다. Windows PC에서 시제품으로 재야 한다(§9).

## 1. 왜 독립 exe인가 (같은 exe 모드와 비교)

| 항목 | 기존 exe의 `--kclip` 모드 | **독립 `kagent.exe`(제안)** |
|---|---|---|
| 시작 | PyInstaller 단일 파일이 큰 번들을 **임시 폴더에 풀며 시작**(스마트 런처가 캐시해도 수백 ms~초) | 수 MB 이하 단일 파일, **수십 ms** |
| 상주 메모리 | 파이썬 런타임 + 임포트 → 약 20~40MB(실측 필요) | 네이티브 약 **2~6MB**(목표) |
| 업데이트 | 앱 업데이트(160MB+)마다 에이전트도 교체·재시작 | 에이전트 자체만 작게 갱신 |
| 앱이 꺼져 있을 때 | 같은 exe라 앱 파일이 잠기거나 업데이트 충돌 | 앱과 무관하게 계속 동작 |
| 빠른 팝업 | WebView2/Flutter는 포커스를 가져가고 느림(수 초) | **네이티브 작은 창**을 에이전트가 직접 띄움(포커스 안 뺏고 즉시) |
| 보안 심사 | 거대 exe 안에 기능이 섞여 심사 어려움 | 기능이 작아 **감사·서명·허용 목록 등록이 쉬움** |
| 비용 | 낮음 | 새 실행 파일·빌드·서명·설치·업데이트 경로 추가 |

→ "초경량·최고속도"는 **WebView·파이썬을 아예 쓰지 않는 독립 네이티브 exe**가 구조적으로 가장 유리하다. 비용은 새 빌드 경로이며 §7에서 다룬다.

## 2. 구현 언어 후보 (제안: Rust, 대안: C#)

| 후보 | 예상 크기 | 상주 메모리 | 시작 | 새 도구 | 비고 |
|---|---|---|---|---|---|
| **Rust**(`windows-sys`, SQLite 번들) | 약 1~2MB | 약 2~5MB | 수 ms~수십 ms | Rust 툴체인(GitHub Actions `windows-latest`에는 설치돼 있음; GitLab 러너는 확인 필요) | 메모리 안전 — **신뢰할 수 없는 클립보드·파일 데이터를 파싱**하므로 큰 장점, 크레이트 공급망 관리 필요 |
| C++(Win32, MSVC) | 약 0.3~1MB | 약 1~4MB | 가장 빠름 | MSVC(러너에 설치) | 가장 작지만 메모리 안전 위험·유지보수 부담 |
| **C#**(.NET Framework 4.x, `csc`) | 약 50~150KB(CLR은 OS 포함) | 약 8~15MB | 약 50~100ms | **없음**(이미 `launcher/smart_launcher.cs`를 CI에서 빌드 중) | 새 툴체인 없이 가능. SQLite는 네이티브 DLL 필요(OS 내장 `winsqlite3.dll` P/Invoke 가능 — 지원·버전 확인 필요) 또는 자체 저장 형식 |
| Python 최소 구성 | 약 10~20MB | 약 20~40MB | 0.3~1초 | 없음 | **"최고속도" 기준에 미달 — 제외** |

- **제안**: Rust(최소 자원·메모리 안전). **새 툴체인 도입이 어렵다면 C#(csc)**으로 같은 구조를 만들고, 자원 목표는 약간 느슨하게(상주 15MB 이하) 조정한다. 언어 결정은 **0단계 시제품 측정(§9)과 기관 보안 승인 결과**로 확정한다.
- 어느 언어든 에이전트 코드는 **작게**(목표 몇 천 줄), **외부 네트워크 코드 없음**, 의존성 최소·버전 고정·`--locked`/해시 검증, 오프라인 빌드 캐시.

## 3. 역할 분담 (무엇을 에이전트가 하고 무엇을 앱이 하는가)

**에이전트(`kagent.exe`) — 항상 켜져 있어도 가벼워야 하는 일만**
1. 클립보드 변경 감시와 저장(텍스트·HTML·RTF·이미지·파일 목록 — 읽기·해시·중복 제거·압축·DPAPI 암호화·한도 정리).
2. 스크린샷 폴더·타임머신 조사 폴더의 **파일 변경 알림**(`ReadDirectoryChangesW`)을 받아 색인(파일 이름·종류·크기·생성/수정 시각 = 메타데이터만)을 증분 갱신.
3. 전역 단축키(`RegisterHotKey`)와 **네이티브 빠른 팝업**(K클립보드 항목 선택 → 클립보드에 올리고 자동 붙여넣기).
4. 트레이 아이콘(기록 중/일시정지 표시·메뉴: 열기·일시정지·종료).
5. 저장소(SQLite)의 **유일한 쓰기 주체**.

**기존 앱(Flutter+파이썬) — 화면이 필요한 일**
- 관리 화면(검색·고정·설정·큰 미리보기), **타임머신 타임라인·달력·카드**, 썸네일 생성(PIL·pypdfium2·hwpx `PrvImage`·셸 썸네일, 결과를 캐시에 저장 — 에이전트는 이미지 디코더를 갖지 않아 작게 유지), 한/글 연동(그림판·표그림판으로 보내기), 에이전트 설치·설정·갱신 관리.
- 앱은 저장소를 **읽기 전용**으로 열고(WAL이라 에이전트 쓰기와 충돌 없음), 변경 요청(설정·삭제·고정·일시정지)은 에이전트에 **IPC 명령**으로 보낸다.

> 썸네일을 앱이 만들면 앱이 꺼진 동안에는 새 문서의 썸네일이 없다 → 타임머신 화면을 열 때 보이는 항목만 만들면 되고(지연 생성), 에이전트는 메타데이터만 항상 최신으로 유지한다. 이것이 에이전트를 작게 두는 핵심 절충이다.

## 4. 에이전트와 앱의 연결

- **저장소**: `%LOCALAPPDATA%\HwpAutoDocFit\kagent\`
  - `clip.db`(K클립보드 항목), `timeline.db`(타임머신 색인) — **별도 파일**(독립 백업·삭제), SQLite **WAL**, `PRAGMA user_version`으로 스키마 버전 관리, 에이전트만 쓰기.
  - `blobs\`(항목별 압축·암호화 파일), `thumbs\`(앱이 만든 썸네일 캐시, 용량 상한·LRU).
- **IPC**: 현재 사용자 전용 **이름 있는 파이프** `\\.\pipe\kagent-<사용자SID>`(DACL로 같은 사용자만 접근, 원격 접속 거부), 줄 단위 JSON 요청/응답(`status`·`pause`·`resume`·`restore_item`·`delete_item`·`set_settings`·`add_root`·`rescan`·`quit`), **프로토콜 버전**과 에이전트 버전 확인(앱이 더 새 버전이면 에이전트 교체 제안). 에이전트에는 **네트워크 소켓이 없다**(외부 연결 코드 자체를 넣지 않음).
- **암호화**: 항목 payload는 에이전트가 **DPAPI**(`CryptProtectData`, 현재 사용자)로 암호화해 저장. 앱도 같은 사용자 계정이므로 `CryptUnprotectData`로 읽을 수 있어 평문을 파이프로 넘기지 않아도 된다.
- **단일 실행**: 이름 있는 뮤텍스. 이미 떠 있으면 새 인스턴스는 기존에 "열기" 신호만 보내고 종료.
- **상태 공유**: 에이전트가 `status.json`(작은 파일)에 기록 중/일시정지·항목 수·마지막 기록 시각을 주기적이 아닌 **변경 시에만** 갱신 → 앱은 필요할 때 읽어 표시(파이프 연결 없이도 상태 확인).

## 5. 속도 설계 (최고속도)

- **이벤트 구동만**: 클립보드는 `WM_CLIPBOARDUPDATE`, 폴더는 `ReadDirectoryChangesW` 완료 포트 — **폴링·타이머 없음**(유휴 CPU 0%).
- **메시지 스레드는 읽기만**: 클립보드를 연 시간을 최소화(목표 10ms 이하)하고 읽은 바이트를 곧 **작업 스레드 한 개**에 넘겨 해시·압축·암호화·DB 쓰기를 처리(저우선순위, EcoQoS). 연속 복사는 150ms 디바운스.
- **저장 지연 최소**: 텍스트는 **수 ms**, 이미지(1MB)는 PNG 재압축을 하지 않고 이미 PNG면 그대로 저장(DIB만 있으면 간단 압축). DB는 **트랜잭션당 한 항목**·`synchronous=NORMAL`·작은 캐시.
- **빠른 팝업**: 단축키를 누르면 에이전트가 **이미 메모리에 있는 최근 N개 요약(미리보기 문자열·작은 썸네일)**으로 즉시 그린다(목표 **50ms 이내**), 포커스를 가져가지 않는 창(`WS_EX_NOACTIVATE|WS_EX_TOOLWINDOW|WS_EX_TOPMOST`), 키보드로 선택 → 클립보드 복원 → (옵션) 이전 창에 Ctrl+V 입력 합성(`SendInput`). 앱(WebView)을 띄우는 경로는 느리므로 쓰지 않는다. 최근 N개 요약은 시작 때 DB에서 한 번 읽어 메모리에 두고(수백 KB 이하) 이후 변경 때만 갱신.
- **검색**: 팝업 안 검색은 메모리 요약에서 부분 문자열(수천 개까지 수 ms), 앱의 전체 검색은 SQLite 인덱스.
- **타임머신 색인**: 시작 때는 **DB를 열기만** 하고 폴더 변경 알림이 오는 만큼만 갱신. 첫 색인(큰 폴더)은 저우선순위 백그라운드로 청크 처리(목표 10만 파일 5초 안팎·SSD, 실측 필요 — 필요하면 NTFS 변경 저널(USN)은 관리자 권한이 필요해 쓰지 않음), 변경 알림 버퍼 넘침(overflow)이 오면 해당 폴더만 재스캔.
- **일시정지**: 클립보드 리스너·폴더 감시 핸들을 **해제**해 메시지 처리 0.

| 실행 파일 크기 | Rust/C++ 2MB 이하, C# 200KB 이하(+프레임워크는 OS) |
| 상주 메모리(작업 집합) | Rust 5MB 이하(최근 N개 요약 포함), C# 15MB 이하 |
| 유휴 CPU | 0.0~0.1% |
| 시작 시간 | 100ms 이하(로그인 자동 시작은 30~60초 지연) |
| 클립보드 이벤트 → 저장 완료 | 텍스트 20ms 이하, 1MB 이미지 100ms 이하 |
| 클립보드 점유 시간 | 10ms 이하 |
| 단축키 → 팝업 표시 | 50ms 이하 |
| 디스크 쓰기 | 중복 복사 0 바이트, 한도 초과 0건 |
| 24시간 실행 | 메모리·핸들 증가 없음 |
항목당 10MB·총 200MB·기본 50개 등 저장 한도는 `docs/CLIPBOARD_HISTORY_DESIGN.md` §12의 값 유지.

## 7. 설치·시작·업데이트·보안

- **배포**: 에이전트는 **앱 설치 파일에 같이 넣어 두되 사용자가 켜기 전에는 설치·실행하지 않는다**(기본 꺼짐). 사용자가 "K클립보드 켜기"를 누르고 **동의**하면 앱이 `kagent.exe`를 `%LOCALAPPDATA%\HwpAutoDocFit\kagent\`로 **복사(해시 검증)** → 실행. 포터블 사용자도 같은 방식. 제거 = 에이전트 종료 + 폴더 삭제 + 자동 시작 항목 삭제 + (선택) 데이터 삭제.
- **자동 시작**: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`(관리자 권한 불필요), **지연 시작**, 사용자가 끌 수 있음. 서비스·작업 스케줄러·드라이버 사용 안 함.
- **서명**: 새 상주 exe는 백신 오탐(클립보드 감시·전역 단축키 = 의심 패턴)과 기관 SW 허용 목록의 핵심이므로 **코드 서명 인증서 필요**(앞 보안 검토 S1과 같은 사안). 서명이 없으면 SmartScreen·EDR 경고가 날 수 있음을 설계 제약으로 명시.
- **권한·격리**: 일반 권한, 관리자 권한 요구 없음, 파이프 DACL, **네트워크 코드 없음**, 파일 접근은 설정된 폴더와 자체 데이터 폴더만, 개인정보(클립보드 내용·경로)를 로그에 기록하지 않음, 패닉 시 내용 없이 종료 코드만.
- **업데이트**: 앱이 에이전트 버전·해시를 비교해 새 버전이 있으면 **에이전트를 정상 종료 → 교체(`.old` 백업) → 재시작**(앞 업데이트 설계의 SHA-256 검증·복구와 같은 방식). 스키마 변경은 `user_version` 마이그레이션(실패 시 읽기 전용으로 안전 모드).
- **프라이버시 신호 존중**(`ExcludeClipboardContentFromMonitorProcessing`·`CanIncludeInClipboardHistory`=0·`CanUploadToCloudClipboard`=0), 제외 프로그램·패턴, 기록 중 표시(트레이)는 `CLIPBOARD_HISTORY_DESIGN.md` §2·§7과 동일.

## 8. 접근성·한계

- 네이티브 빠른 팝업은 웹 UI보다 **접근성(스크린 리더·고대비·IME 입력)** 구현이 어렵다. 팝업은 키보드 선택·큰 글씨·고대비 색 지원 최소 구현을 하고, **전체 기능은 앱의 관리 화면(접근성 갖춤)**에서도 쓸 수 있게 하여 팝업은 "빠른 길"로만 둔다. 팝업의 검색 입력(한글 IME)은 2차.
- 한/글 같은 앱의 **지연 렌더링 형식**·가상 파일(Outlook 첨부 등)은 1차에서 건너뜀(`CLIPBOARD_HISTORY_DESIGN.md` §2).
- 원격 데스크톱·가상 머신·UAC 높은 권한 창에서 온 복사: 높은 권한 프로세스의 클립보드는 일반 권한 프로세스도 읽을 수 있으나, 높은 권한 창에 **자동 붙여넣기(SendInput)는 차단**된다(UIPI) → 그 경우 "클립보드에 올렸어요, Ctrl+V를 눌러 주세요"로 폴백.
- 에이전트가 허용되지 않는 환경: K클립보드는 **앱이 켜져 있는 동안만** 기록(파이썬 경로 — 기능 축소), 타임머신은 앱을 열 때 증분 스캔(느리지만 동일 기능).

## 9. 시험·측정 계획

- **0단계 시제품(최우선)**: 가장 작은 에이전트(클립보드 텍스트 기록 + SQLite 한 건 + 파이프 `status`)를 **Rust와 C#(csc), 비교용 파이썬 최소 구성** 세 가지로 만들어 같은 Windows PC에서 **크기·시작 시간·유휴 상주 메모리·유휴 CPU·텍스트 1건 처리 시간·1,000건 복사 시 CPU 시간**을 측정하고 결과를 기록 → **언어 결정**. (이 환경에서는 Windows 실행·측정이 불가하므로 PC 작업이거나 GitHub Actions `windows-latest` 러너에서 측정 스크립트로.)
- **자원 시험 도구**: `scripts/kagent_benchmark_pc.py`(유휴 10분, 복사 1,000회 혼합, 중복 복사, 폴더 10만 파일 첫 색인·증분, 24시간 누수) — 앱이 있는 PC와 없는 PC의 시스템 CPU 차이도 비교.
- **단위/통합**: 저장소·한도·중복·암호화 라운드트립(에이전트 언어로 작성한 단위 시험 + 앱 쪽 파이썬이 같은 DB를 읽는 계약 시험 — 스키마 고정 테스트), IPC 프로토콜(버전·권한·잘못된 입력), 제외 신호·자기 쓰기 무시, 폴더 감시 디바운스·overflow 재스캔, 일시정지 시 핸들 해제 확인.
- **보안 시험**: DB를 다른 계정으로 열어 평문 노출 없음, 파이프 접근(다른 사용자·원격) 거부, 에이전트가 네트워크 연결을 만들지 않음(포트·연결 목록 확인), 로그에 내용 없음, 퍼징(클립보드 형식·파일 이름 파서).

## 11. 열린 질문(사용자 확인)
1. **독립 exe 방식 승인**(제안)과 **구현 언어**: Rust(최소 자원, 새 툴체인) / C#(툴체인 없음, 약간 무거움) — 0단계 측정 후 확정해도 되는지.
2. **코드 서명 인증서**를 기관이 지원할 수 있는지(없으면 보안 경고·오탐 가능성을 감수).
3. 기관 PC에서 **상주 프로그램·자동 시작**(HKCU Run)이 허용되는지.
4. 팝업은 1차에 **네이티브 최소 구현**(제안)으로 하고 한글 검색(IME)은 2차로 미뤄도 되는지.
5. 에이전트 데이터 위치(`%LOCALAPPDATA%`)가 기관 정책(프로필 초기화·로밍)에 맞는지.
