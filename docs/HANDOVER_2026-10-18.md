# 인수인계 — v1.78.0 정식 릴리즈 검증

작성일: 2026-10-18

## 현재 상태

- 작업 브랜치: `release/1.78.0` (GitHub 원격에도 생성됨)
- 기준 배포 브랜치: GitHub `main`, 현재 v1.77.0
- 버전: `1.78.0`
- v1.78.0 변경 기능과 릴리즈 노트 초안은 준비되어 있다.
- Flutter·Inno Setup은 PC에 설치되어 있고, 포터블 EXE와 사용자 설치형 EXE의 로컬 패키징이 모두 완료됐다.
- 실제 한/글 PC 회귀시험은 100/100 및 제목 보존으로 통과했고, HWPX 형식 비교 3건은 지정 비교 필드 불일치 0건이다.
- 전체 Python 테스트는 1,293개 통과, 1개 제외. Flutter는 82개 통과, 1개 제외. 웹 편집기 테스트 22개와 HWP 미리보기 테스트 6개 통과.
- 단, 현재 워크플로 변경 전 Windows CI 실행은 포터블 빌드만 포함했다. 설치형 패키지를 추가한 워크플로로 새 Windows CI가 성공하기 전에는 정식 릴리즈하면 안 된다.

## 이번 작업에서 변경한 릴리즈 자동화

- GitHub Windows CI에서 Inno Setup 6 컴파일러를 찾아 설치형 패키지를 추가 생성한다.
- CI 아티팩트와 GitHub 초안 릴리즈에 포터블 EXE와 설치형 Setup EXE를 함께 올린다.
- 체크섬 파일에 두 실행 파일의 SHA-256을 모두 기록한다.
- 태그 기반 게시 워크플로는 설치형 패키지를 포함한 초안인지 확인하고, 체크섬 검증 후 공개한다.
- `release-assets` 생성 단계에서 버전값을 먼저 읽도록 수정했다. 이전 초안에는 스텝 간 셸 변수 공유를 전제한 순서 오류가 있었으나, 수정한 워크플로로는 아직 재실행·검증되지 않았다.

## 남은 절차

1. 변경분의 diff/YAML과 GitHub workflow 결과를 확인한다.
2. `release/1.78.0`에 커밋·푸시하고 Windows CI가 포터블 및 Setup 빌드, 단위 테스트, 표시 창·런타임/OCR 검증을 모두 통과하는지 확인한다.
3. CI가 만든 `release-assets/SHA256SUMS`를 확인하고 두 실행 파일의 다운로드·해시가 초안 첨부물과 일치하는지 확인한다.
4. 릴리즈 문서와 README를 최종 점검한 후, 검증된 커밋만 GitHub `main`에 반영하고 `v1.78.0` 태그를 게시한다.
5. GitLab은 다운로드 중지 때 설정한 Releases 접근 제한이 남아 있다. 먼저 GitHub 공개 릴리즈를 완료한 뒤 GitLab에 백업한다. GitLab 릴리즈/첨부물을 공개로 전환하거나 GitLab 직접 다운로드 링크를 README에 유지할 수 있는지는 별도로 확인하고, 확인 전 공개 제공이라고 표현하지 않는다.
6. `docs/DOWNLOAD_HOLD_2026-10-16.md`에는 v1.78.0만 재개된 사실을 기록한다. 과거 초안 릴리즈는 다시 공개하지 않는다.

## 주의

- 릴리즈 브랜치에서는 각 push가 CI를 다시 실행하고, 성공하면 CI가 `release-assets/` 검증 자료를 커밋한다. 이 자동 생성 커밋도 확인한 후 main에 반영한다.
- 한/글 COM 검증은 사용자 원본이 아니라 복사본으로만 수행한다. 사용자 세션에서 연 한/글 프로세스는 종료하지 않는다.
- `hwp-auto-docfit.py`의 CRLF 줄바꿈을 보존한다.
- 새 버전 게시 승인은 이미 요청받았으나, 위 검증 게이트가 실패하면 게시하지 말고 원인을 먼저 수정한다.
