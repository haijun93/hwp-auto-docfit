설계: `docs/알파_신기능설계_2026-10-11.md`. 측정은 같은 PC에서 번갈아 했다(측정 전 남은 감시 프로세스 정리).

## 1-a. 자간 초기화를 XML에서 (`알파_자간초기화_XML_사용`, 기본 켬) — 합격

'한 번에 적용'에서 자간 초기화를 한/글 문단별 선택 대신 XML 선행 단계 맨 앞에서 한다(`docfit_core/spacing_reset.py`, `자간초기화_hwpx_처리`).
보호 구간(항목기호·라벨)은 한/글 경로와 같은 함수 `자간보호_글자수`로 정한다. 자간 정리 모드·쪽 범위 작업은 예전 방식 그대로.

test4 예시 파일, 기본 설정, 같은 알파 코드에서 플래그만 끄고 켜서 번갈아 2회:

| | 한/글 방식(끔) | XML 방식(켬) |
|---|---|---|
| 1회차 | 244.8초 | 213.6초 |
| 2회차 | 226.9초 | 214.3초 |
| 평균 | 235.9초 | **214.0초 (−9.3%)** |
| 자간 초기화 단계 | 14.5~16.3초 | 선행 단계 안(1초 미만) |
| 최종 검수 점수 | 100 | 100 |
| 결과 본문 글 | 1,255자 | 같음 |
| 글자별 자간 분포 | 0% 1,501자 · −12% 81자 · −10% 76자 … | **완전히 같음** |

- 시험: `tests/test_spacing_reset_xml.py` 6개(보호 구간 유지·run 나누기·숨은 글자 run 건너뜀·표 안 문단·글 보존·처리기).
- 남은 점: 보호 구간에 걸친 컨트롤 run 1개는 건너뛴다(test4에서 결과 차이 없음).

## 1-b. 문두 라벨 굵게·괄호 축소를 XML에서 (`알파_라벨괄호_XML_사용`) — 효과 미미, 기본 끔

판정을 순수 함수 `라벨괄호_계획`으로 떼고, 지금 열린 문서를 HWPX로 저장 → `라벨괄호_hwpx_처리` → 다시 여는 방식(`현재문서_XML단계_적용`).
run 분할·굵게·크기 줄임은 `docfit_core/char_ranges.py`.

| | 한/글 방식 | XML 방식 |
|---|---|---|
| 1회차 | 218.0초 | 218.6초 |
| 2회차 | 214.7초 | 209.1초 |
| 평균 | 216.4초 | 213.9초 (−1.2%, 오차 수준) |

## 1-c. 공백 정규화·문장부호 뒤 공백·문두 라벨/괄호를 XML 한 번으로 (`알파_글규칙_XML_사용`, 기본 켬) — 합격

'한 번에 적용'에서 세 단계(서식통일이 켜져 있으면 라벨/괄호는 서식통일 뒤 예전 경로)를 지금 열린 문서의 HWPX 한 번에 처리하고 다시 연다.
- 글 규칙: `공백규칙_글변환`(10개 규칙을 한/글 경로와 같은 순서), `문장부호뒤공백_글변환`. 글 반영은 `docfit_core/text_edit.py`(차이만, 숨은 글자 요소는 그대로).
- 범위: 한/글 경로의 문단 순회와 같게 **본문과 한 칸 표 안 문단만**(여러 칸 표 안 문단은 손대지 않음, `표안_문단_구분`). 한 칸 표 안 문단은 공백 규칙 일부를 건너뜀.

| | 한/글 방식 | XML 묶음 |
|---|---|---|
| 1회차 | 213.2초 | 194.3초 |
| 2회차 | 213.5초 | 196.0초 |
| 평균 | 213.4초 | **195.2초 (−8.5%)** |
| 결과 | 본문 1,816자 | 글·글자별 굵게·크기 완전히 같음 |

- 고친 점(측정 중 발견): ① 한 칸 표가 있는 문서에서 XML이 꺼져 있던 조건 제거(문단별 판정) ② 여러 칸 표 안 문단(제목 표 담당자 칸 `○○과장`→`○ ○과장`, 머리글 `구  분`→`구 분`)을 건드리던 범위 차이 수정.
- 시험: `tests/test_text_rules_xml.py` 6개, `tests/test_label_paren_xml.py` 7개.

## 1-d. 사용자 서식의 표준서식을 XML로 (`알파_사용자서식_XML_사용`, 기본 켬) — 합격

예시 보고서를 복사한 사용자 서식도 항목기호 문단은 XML 일괄 서식으로 입힌다: 글꼴·크기·굵게·장평, **복사한 문단 모양**(여백·문단 간격·줄간격,
case는 HWPX 값·default는 두 배), **계층 추가 서식**(라틴 글꼴·장평·자간·기울임·밑줄·글자색·음영·정렬·줄 나눔). 취소선처럼 대응이 확실하지 않은
값이 있는 문단과 항목기호 없는 문단(제목·날짜·본문·세트 후속)은 한/글 경로. 내어쓰기와 간격 규칙(제목 뒤·계층 복귀)은 한/글이 이어서 한다.
코드: `docfit_core/batch_format.py`(`char_extra`·`para_extra`), `사용자서식_XML추가값`.

서식 "(서식)10월 확대간부회의_부서명", test4, 번갈아 2회(측정 도구에 `PROFILE` 추가):

| | 한/글 방식 | XML 방식 |
|---|---|---|
| 1회차 전체 | 157.1초 · 96.5점 | **113.9초** · 96.5점 |
| 2회차 전체 | 203.5초 · 100점(이상 회차, 아래) | **163.0초** · 96.5점 |
| 표준서식 단계 | 34.1 / 44.3초 | **11.4 / 27.6초** |
| 결과 | 1회차 | XML 1·2회차와 **글·글자 서식·문단 서식 완전히 같음** |

- 한/글 방식 2회차는 선 문자 표 변환에서 원래 줄이 지워지지 않아(아래 수정) 문단이 62→70개가 된 이상 회차다. 1-d와 무관.
- 시험: `tests/test_profile_batch_xml.py` 3개, `tests/test_batch_format.py` 갱신.

## 같이 고친 결함(v1.73에도 있음)

1. **서식 보관 실패로 문서 처리 전체 중단**: 표 칸 '다음 단어 당김' 중 글자 위치를 확인하지 못하면 예외로 문서 처리가 멈췄다(점수 24.6).
   `단어모드_서식보관`이 None을 돌려 그 줄 조정만 건너뛴다(부르는 곳은 모두 None 처리). 시험 `tests/test_format_preserve_failure.py`.
2. **선 문자 표 변환 뒤 잔여물**: 한/글 범위 선택이 실제로 잡히지 않았는데 실패를 알리지 않아, 표만 들어가고 원래 선 문자 줄 8개가 남았다(검수는 100점).
   지운 뒤 선 문자로 시작하는 줄이 남았으면 문단 단위로 다시 지우고, 끝내 못 지우면 표를 넣지 않고 검수 문제로 기록한다. 시험 `tests/test_box_table_residue.py`.

## 썸네일: 미리보기 그림 없는 예시는 한/글로 첫 쪽 그림 생성

한/글 2018(10.x)로 저장한 HWPX는 `Preview/PrvImage.png`가 없다(`111` 폴더 HWPX 33개 중 3개, 모두 한/글 2018). 미리보기 글(`PrvText.txt`)은
33개 모두 있었지만 서식 정보가 없어 썸네일로 쓰지 않는다. 서식 추가 때와 썸네일 창을 열 때 백그라운드에서 예시 사본을 독립 한/글로 열어
첫 쪽을 그림으로 만들고(`첫쪽_그림_만들기`, 교육부 보도자료 3.7초), 설정 폴더에 `서식예시_<id>.thumb.png`와 예시 해시를 둔다. 예시가 바뀌면 다시 만든다.
- 실측: 한/글 2020 `CreatePageImage`는 쪽 번호 0이 첫 쪽이고, 형식을 png로 줘도 확장자를 .bmp로 바꿔 BMP로 저장한다.
- 시험: `tests/test_format_samples.py`의 `ThumbnailTest`.

## 서식 통일: 글꼴·크기만 맞추기(기본) + XML 표본 조사 (구현, PC 측정 대기)

사용자 결정(2026-10-11): ① 서식 통일은 기본으로 **글꼴·크기만** 맞추고(항목기호·라벨 굵게, 괄호 크기 -2pt 규칙 포함), 카드 옵션
`전체 서식 맞추기`(`unify_full_format`, 세부 작업 `unify_full_format`, 기본 끔)를 켜면 예전처럼 글자색·음영·기울임·밑줄·취소선·장평·정렬·
좌우 여백·위 간격·내어쓰기까지 맞춘다. 한 번에 적용·서식 적용의 서식통일은 그대로(전체 서식). ② 표본 조사를 한/글 문단 순회 대신 HWPX 스냅숏에서
한다(`알파_서식통일_XML조사_사용`, 기본 켬, 알파 플래그라 `--beta-mode`로 꺼진다). 알파에서 먼저 시험하고 개선 효과를 평가한 뒤 베타에 반영한다.

- 코드: `_서식통일_글꼴크기만`·`_서식통일_글꼴크기_대표`(대표값에서 font·size·marker_bold·label_bold만 남김, 위 간격 비교 끔), `_서식통일_XML_조사`
  (HWPX 직속 문단 목록에서 표본·문맥·위치 글을 만든다), `_서식통일_COM_조사`(예전 순회, 폴백).
- XML 조사의 안전장치: 한/글 본문 끝 문단 번호 = HWPX 직속 문단 수 + 글이 있는 문단 3곳(첫·가운데·끝)의 글 일치를 확인하고, 어긋나면 예전 순회로
  되돌린다. 1쪽 문단(표지 판정용)은 이분 탐색으로 1쪽 끝을 찾는다(한/글 호출 약 log₂ 문단 수 번). 고칠 문장만 한/글에서 글을 다시 읽어 자간·내어쓰기
  단계의 열쇠(`item["text"]`)로 쓴다(HWPX 글과 다르면 그 문장은 건드리지 않음).
- 비교 범위를 줄이므로 `내어쓰기 상태`처럼 기준이 없을 때 한/글에 묻던 호출도 생략한다.
- 시험(Linux 대체 환경): `tests/test_unify_font_size_xml.py` 9개(모드 판정·대표값 축소·XML 조사 5가지·전체 흐름에서 XML 조사 결과 = 예전 순회 결과),
  `tests/test_pipeline_review.py`에 글자색 불일치가 기본에서는 고쳐지지 않고 전체 서식에서만 고쳐지는 시험 추가. 전체 896개 중 실패는 기존 Tk·Windows 시험뿐.
- **PC에서 측정할 것**: 같은 문서로 `알파_서식통일_XML조사_사용` 켬/끔을 번갈아(`scripts/regression_pc.py --flag 알파_서식통일_XML조사_사용=0`) 2회씩, 처리 기록의
  `서식통일 조사` 단계 시간과 전체 시간, 최종 검수 점수, 결과 글·글자 서식 비교. 그리고 서식 통일 카드의 `전체 서식 맞추기` 켬/끔으로 전체 시간·고친 문장 수.
