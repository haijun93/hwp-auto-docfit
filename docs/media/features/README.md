# README 기능 비교 이미지

안내 기준: **1.72 Beta 13**. PNG 30개 중 `spacing.png`와 `all-in-one.png`는
사용자가 지정한 `111\test4`의 「보고서 예시 파일(한번에 적용).txt」 사본을
실제 앱으로 처리하고 한/글 자체 PDF 출력으로 렌더링한 사례입니다.
나머지 28개는 기능 설명용 도해입니다. 사용자가 좋다고 한 내어쓰기 이미지는 유지했습니다.
제품의 동작은 `hwp-auto-docfit.py`, `docfit_core/stage_selection.py`,
`docfit_core/writing_aids.py`와 Beta 13 릴리스 노트를 기준으로 확인했습니다.
실제 사례는 삼체 문명을 소재로 한 가상 보고서입니다. 원본 TXT·HWPX·로그는
수정하지 않았으며 공개 이미지에는 HWPX 메타데이터를 포함하지 않습니다.

- 왼쪽은 전, 오른쪽은 후입니다.
- 빨간 글자는 바뀌는 내용·서식·위치입니다. 검토·내보내기·저장 기능에서는
  새로 표시되거나 생성되는 정보를 뜻합니다.
- 검은 글자는 유지되는 부분입니다. 설명용 빨간색을 결과 문서에 넣는 기능이 아닙니다.
- 공백 정리 그림의 빨간 `·`는 삭제되는 빈칸을 눈에 보이게 하는 표기입니다.
- 쪽 수 맞춤은 성공하는 경우의 도해입니다. 원본 쪽 구성 유지와 목표가 다릅니다.
- 짧은 마지막 줄 그림은 기준을 4글자 이하로 설정한 예시입니다.
- 문서 구조·가독성 검토는 원문 수정이 없는 읽기 전용 기능으로 표현했습니다.
- 기존 `../samchein/` 영상·실제 결과는 **1.69 Beta 18**의 별도 자료입니다.

실제 사례의 빨간색은 PDF 글자의 줄 위치·글꼴·크기·좌표와 추가·삭제된 글을
비교해 표시합니다. 자간 이미지는 개요에서 줄을 옮긴 어절을 확대합니다.
원래 글꼴과 조판을 유지하고 비교용 색만 덧입히며 결과 HWPX는 색칠하지 않습니다.
[실행·원본 보존·이미지 해시 기록](test4-evidence.json)을 참고하세요.

## 재생성

저장소 루트에서 Windows의 맑은 고딕 글꼴과 Pillow를 사용합니다.

```powershell
.venv\Scripts\python.exe scripts\build_readme_comparisons.py
```

사용자 문서를 열지 않고 고정된 예시 문구만 렌더링합니다.
실제 사례 두 개는 위 명령으로 덮어쓰지 않습니다.
도해는 1440×760 PNG이며 실제 사례는 확대 가능한 별도 크기입니다.
README에서 누르면 원본 크기로 열립니다.
예시 문구와 빨간 표시 범위는 생성 스크립트의 `CARDS`에서 수정합니다.
텍스트와 표 칸의 경계 초과를 검사하고, 생성 후 그림과 README의 링크를 확인합니다.

실제 사례 두 개를 다시 만들려면 기존 결과가 없는 새 로컬 작업 폴더를 지정합니다.
한/글과 등록된 자동화 보안 모듈, Pillow·pypdfium2가 필요합니다.

```powershell
.venv\Scripts\python.exe scripts\build_test4_comparisons.py "C:\Users\haiju\OneDrive\바탕 화면\111\test4" --work "$env:TEMP\docfit-readme-new-run" --output docs\media\features
```

이미지에 쓰이는 원문 TXT를 별도 폴더에 복사하여 실행합니다. 한 번에 적용과
자간 정리는 같은 TXT의 독립 사본에서 시작합니다. 보안 모듈 등록·사용자 설정은
변경하지 않습니다. 실행 결과 HWPX·PDF·원시 로그는 로컬 작업 폴더에만 남깁니다.
