# 에이전트 지휘 체계 (Claude 지휘 · Codex · Gemini)

2026-10-20 사용자 지시: "토큰 소모까지 고려하여 코덱스와 제미나이를 지휘하며 작업하고, 둘을 잘 지휘하는 체계를 설계하여 운영하라."
작업판(상태·결과 보고)은 `docs/CODEX_CLAUDE_SPACING_COORDINATION.md`, 이 문서는 운영 규칙이다.

## 1. 역할

| 에이전트 | 맡는 일 | 쓰지 않는 일 |
|---|---|---|
| **Claude (지휘)** | 원인 조사, 작업 카드 작성, 합격 판정(스크립트), 통합·커밋, 사용자 보고 | 다른 에이전트 소유 파일 동시 수정 |
| **Codex (코드)** | 위치가 정해진 코드 수정 + 그 단위 시험 | 탐색·조사, 한/글 COM 시험, 긴 문서 읽기 |
| **Gemini (검증·보조 코드)** | 한/글 COM 실측 시험, 교차 검토, 중간 규모 코드(시험 스크립트·보조 모듈) | 엔진 핵심 파일 동시 수정 |

판정은 사람이 읽는 말이 아니라 **판정 스크립트의 종료 코드·JSON**으로 한다. 에이전트의 "통과했다"는 말은 판정 근거가 아니다.

## 2. 토큰 예산 원칙

1. **가장 비싼 자원은 Codex 한도**(소진 시 다음 재설정까지 정지, 2026-10-21 00:50 재설정). Codex에는 Claude가 원인·파일:행·고칠 내용·합격 명령을
   다 적은 **작업 카드 1장**만 보낸다. Codex가 저장소를 탐색하거나 HANDOVER 전체를 읽게 하지 않는다. 추론 노력 `low`.
2. **조사는 Claude가 한다.** 작업자가 같은 조사를 반복하지 않도록 카드에 결론과 근거 위치를 넣는다.
3. **한 번 호출에 카드 1장.** 실패하면 같은 작업자에게 최대 1회 재지시, 그래도 실패면 Claude가 직접 처리하거나 다른 작업자로 넘긴다.
4. **보고는 10줄 이내**, 로그·결과물은 파일로 남기고 경로만 적는다(문서에 로그를 붙이지 않는다).
5. **판정은 토큰 없이**: `lead_compare.py`·`split_check.py`·`regression_pc.py --verify`·`unittest` 종료 코드.
6. 한도가 걸린 작업자의 카드는 대기열에 두고, 기다리는 동안 Claude나 다른 작업자가 처리할 수 있는 카드는 바로 넘긴다.

## 3. 호출 방법 (사용자 붙여넣기 불필요)

- Codex:
  `codex exec -C <저장소> -s workspace-write --add-dir C:\HWP_AUTODOCFIT -c model_reasoning_effort="low" -o <결과.md> - < <카드.md>`
- Gemini:
  `agy -p --effort low --mode accept-edits --add-dir C:\HWP_AUTODOCFIT --print-timeout 40m "<카드 내용>"`
- 대화형 창(VS Code Codex, Antigravity 창)이 이미 같은 일을 하고 있으면 중복 호출하지 않는다. 그 창은 작업판을 읽고 보고 칸에 적는 방식으로 참여한다.

## 4. 작업 카드 형식

```
ID / 담당 / 예상 토큰 등급(S·M·L)
소유 파일: (이 카드만 고칠 수 있는 파일·범위)
원인(결론): 파일:행, 한두 줄
고칠 내용: 무엇을 어떻게
합격 명령: 실행할 명령과 기대 종료 코드·값
금지: 커밋·푸시, 소유 밖 파일 수정, COM 시험(Codex)
보고: 작업판 해당 칸에 10줄 이내(변경 파일·시험 결과·의문)
```

## 5. 공통 안전 규칙

- **한/글 COM 잠금**: `C:\HWP_AUTODOCFIT\.com-test.lock`(내용 `<이름> <시각> <카드ID>`). 있으면 기다리고, 끝나면 반드시 지운다.
  잠금 없이 동시 실행하면 결과가 빈 문서로 저장된 사례가 있다.
- **파일 소유권**: 카드에 적힌 파일만 고친다. 같은 파일을 두 작업자에게 동시에 주지 않는다.
- **커밋은 Claude만**: 판정 PASS 뒤 Claude가 커밋·푸시(github → origin)한다.
- 사용자 원본 문서는 사본으로만 처리한다. 결과물은 `C:\HWP_AUTODOCFIT\테스트예시\지시시험_<날짜>\<작업자>\<카드ID>\`.

## 6. 판정 루프

1. Claude가 조사해 카드 작성 → 작업판 '작업 현황'에 등록
2. 작업자 호출(또는 대화형 창이 작업판에서 수령)
3. 보고 도착 → Claude가 판정 스크립트로 확인(COM 시험은 잠금 아래 Gemini 또는 Claude)
4. PASS: Claude 커밋 / FAIL: 원인과 함께 재지시 카드(1회) → 이후 Claude 직접 처리
5. 사용자에게는 판정 결과(숫자)와 남은 과제만 보고한다.
