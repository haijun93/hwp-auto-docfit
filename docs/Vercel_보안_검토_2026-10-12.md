# Vercel 보안 기능 적용 검토 (2026-10-12)

## 전제와 범위
- 저장소에 Vercel 설정(`vercel.json`)·연동 흔적은 없다. Vercel에 올린다면 대상은 **정적 소개 페이지 `website/`**(index.html, cardnews.html, script.js, styles.css)뿐이다. 앱(.exe)은 GitLab 릴리스에서 내려받고 Vercel을 거치지 않으며, 앱의 업데이트 확인도 Vercel과 무관하다.
- 사이트 특성: 서버 코드·DB·로그인·입력 폼·쿠키·API 없음. 외부 자원은 Google Fonts(CSS `fonts.googleapis.com`, 글꼴 `fonts.gstatic.com`)와 GitLab/GitHub 링크뿐. `script.js`에는 `innerHTML`·`eval`·`fetch`·`localStorage` 사용이 없다. `cardnews.html`은 `<style>` 인라인, `index.html`은 `style=` 속성을 쓴다.
- 따라서 위험은 작다: 주된 위협은 (1) 사이트 변조·가로채기 (2) 클릭재킹 (3) 대량 접속으로 인한 사용량 소진 (4) 계정·배포 권한 탈취.

## 권고 (우선순위순)
| 순위 | 기능 | 위치 | 판단 |
|---|---|---|---|
| 1 | **계정 보안**: Vercel·GitHub 2단계 인증, 팀 최소 권한, Git 연동 저장소 접근 최소화 | 대시보드 | 필수. 가장 큰 실질 위험 |
| 2 | **보안 헤더**(`vercel.json` headers) | 코드 | 적용 권장(아래 초안). 비용 0, 정적 사이트와 충돌 없음 |
| 3 | **Deployment Protection**: 미리보기(Preview) 배포는 Vercel 인증 필요, 운영(Production)만 공개 | 대시보드 | 적용 권장. 작업 중 페이지(알파 내용) 노출 방지 |
| 4 | **Vercel Firewall**(WAF 기본 보호, 이상 트래픽 차단, 사용자 규칙으로 속도 제한) | 대시보드 | 선택. 평상시 불필요, 접속 폭주 시 켠다. *Attack Challenge Mode*는 폭주 때만 일시 사용(정상 방문자 방해) |
| 5 | **Spend Management**(사용량 상한 알림·일시정지) | 대시보드 | 권장. 대량 요청으로 요금·한도 소진 방지 |
| 6 | **환경 변수·비밀값** | — | 해당 없음(사이트에 비밀값 없음). 비밀을 넣지 않는 것이 원칙 |
| 7 | **Bot Protection / BotID, Rate Limiting SDK** | — | 불필요(로그인·폼·API 없음) |
| 8 | **Vercel Authentication으로 전체 비공개** | — | 부적합: 소개 페이지는 공개 목적 |

HTTPS(자동 인증서)와 HSTS는 Vercel이 기본 제공한다. 사이트가 GitLab 주소(내부망 성격 `gitlab.aigov.go.kr`)를 링크하므로, 외부 방문자는 접속이 안 될 수 있다는 점은 보안이 아닌 안내 문제다.

## `vercel.json` 초안 (적용 시 저장소 루트 또는 `website/` 기준 배포 폴더에 둔다)
```json
{
  "cleanUrls": true,
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "Content-Security-Policy", "value": "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data:; connect-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'; object-src 'none'" },
        { "key": "Strict-Transport-Security", "value": "max-age=31536000; includeSubDomains" },
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
        { "key": "X-Frame-Options", "value": "DENY" },
        { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=(), payment=(), usb=()" }
      ]
    }
  ]
}
```
- `style-src`의 `'unsafe-inline'`은 `cardnews.html`의 `<style>`·`index.html`의 `style=` 때문이다. 인라인 스타일을 CSS 파일로 옮기면 뺄 수 있다(우선순위 낮음).
- `HSTS preload`는 도메인 영구 영향이 커서 넣지 않았다. 사용자 도메인을 연결한 뒤 검토한다.
- `X-Frame-Options`는 `frame-ancestors`와 중복이나 옛 브라우저용으로 둔다.
- 카드뉴스를 SNS에 임베드해야 한다면 `frame-ancestors`·`X-Frame-Options`를 해당 경로만 풀어야 한다.

## 적용 전 확인 (실제 배포 환경에서 해야 함 — 이 환경에서는 시험 못 함)
1. 미리보기 배포에서 글꼴이 정상 로드되는지, 브라우저 콘솔에 CSP 위반이 없는지 확인한 뒤 운영에 반영.
2. 처음에는 `Content-Security-Policy-Report-Only`로 두고 위반이 없으면 강제로 전환.
3. 적용 후 securityheaders.com 등으로 점검.

## 결론
정적 소개 페이지라 Vercel의 고급 보안(Firewall 규칙·BotID 등)은 평상시 불필요하다. **계정 2단계 인증 → 보안 헤더 → 미리보기 보호 → 사용량 상한** 네 가지면 충분하다. 요청하시면 `vercel.json`을 `main`의 `website/` 배포 구성에 넣겠다(Vercel 프로젝트 루트 디렉터리 설정이 `website`인지 먼저 알려 주면 위치를 맞춘다).
