## 1. 서식 복사와 표의 적용 범위

### 문서 자체의 대표값과 예시 문서의 대표값

**서식 통일**은 정리할 문서 안에서 같은 역할의 문장끼리 비교합니다.
**서식 관리**는 예시 문서의 역할별 대표값을 저장하고, **한 번에 적용**이 그 값을 사용합니다.
표지·제목·본문·날짜·표 머리글을 하나의 대표값으로 섞지 않는 것이 기본 원칙입니다.

서식 통일은 일반적으로 같은 계층 문단 3개 이상에서 60% 이상을 차지한 값을 채택합니다.
표본 두 개가 모두 같거나 다른 계층·이웃 문장에 보완 근거가 있는 경우의 예외 규칙도 있습니다.
근거가 없거나 값이 갈리면 확정하지 않을 수 있으며, 같은 계층 문장 하나만으로 이상 여부를 단정하지 않습니다.

정상 문단은 본문 서식 교정을 건너뜁니다. 다만 **기본 표 서식**, **표 서식통일**, 고친 문장의 자간·내어쓰기 등은 별도 작업입니다.
표를 건드리지 않으려면 **표 제외**, 고친 문장의 자간을 정리하지 않으려면 **자간 정리 제외**를 선택하세요.

### 예시 서식에서 배워 오는 값

- 문두기호 계층별 한글·영문 글꼴, 크기, 굵게·기울임·밑줄, 글자색·음영, 장평·자간
- 문단 정렬, 좌우 여백, 문단 전후 간격, 줄 간격과 줄 나눔 기준
- 기호 앞뒤 빈칸, 기호·괄호 라벨 강조, 내어쓰기와 괄호 글자 줄임 규칙
- 제목·개요·중제목·붙임 표의 표 전체·칸별·칸 안 문단별 서식
- 일반 표의 위치별 글자·문단·테두리·배경·안쪽 여백·세로 정렬
- 쪽 여백과 쪽 번호 모양 등 지원하는 쪽 설정

문서에 기록된 정의 전체와 실제로 많이 사용한 대표값은 다릅니다.
대표값에는 표본 수·비율·다른 값도 함께 표시하므로 예시 문서 자체가 일관되지 않다면 등록 전에 검토하세요.

**서식 세부사항 → 적용 방식**은 다음과 같이 읽습니다.

| 표시 | 뜻 |
|---|---|
| 값 복사 | 글꼴·크기처럼 분석한 값을 적용 |
| 규칙 복사 | 글 길이에 따라 달라지는 내어쓰기 등을 규칙으로 적용 |
| 표시만 | 분석·확인은 가능하지만 해당 값의 자동 적용을 뜻하지 않음 |

용지 크기·방향은 자동 변경하지 않으며 예시와 다르면 기록으로 알립니다.
쪽 번호 모양 복사는 쪽 번호가 있는 문서가 대상입니다.
글 길이·글꼴·개체·병합 구조가 다르면 화면 전체가 같아지는 것은 아닙니다.

### 제목·개요 표와 일반 표를 구별하세요

- **제목 표**: 2×2 제목·날짜·담당자 표, 또는 2행 1열 제목·담당자 표 등 지원하는 구조를 판별합니다.
- **개요 표**: 제목 아래 요지를 담는 표입니다.
- **중제목·붙임 표**: 번호나 붙임 표시가 있는 구조에 별도 서식을 적용합니다.
- **일반 표**: 데이터나 내용을 행·열로 정리한 표입니다. 제목 표와 같은 방식으로 처리하지 않습니다.

예시 서식에 해당 종류가 있으면 그 표의 서식을 사용하고, 없으면 내장 기준을 사용할 수 있습니다.
제목·개요 표의 전체 폭은 편집 여백 사이의 본문 폭에 맞추므로, 예시의 절대 너비를 항상 유지하는 것은 아닙니다.
일반 표 정밀 복제는 행·열·칸 수, 위치와 글 등을 조합해 대응 표를 찾습니다.

한 번에 적용의 **표 제외**는 일반 표 작업을 제외합니다.
제목·개요·중제목·붙임까지 제외하려면 **세부 작업**의 **제목·개요·붙임 선행 서식** 등 관련 항목을 확인하세요.
제목·개요 폭 조정과 준말 변환처럼 별도 단계도 있으므로 “표 제외 = 모든 표 원형 보존”으로 해석하지 마세요.

### 준말과 라벨로 서식 표 만들기

한 번에 적용의 **준말 → 본말 변환**은 줄 맨 앞의 등록된 준말 뒤에 콜론이 있을 때 동작합니다.

```text
제목1: 추진 방향, 업무 개선계획
개요: 민원 처리 절차를 정비하고 담당자 교육을 실시함
로1: 추진 배경
붙임: 세부 일정
```

`제목1 가`처럼 콜론이 없으면 바꾸지 않습니다.
`붙임 : 1. 세부 시행계획 1부. 끝.` 같은 공문 붙임 목록은 일반 서식 표로 바꾸지 않습니다.
쪽 범위 작업처럼 구조 변경을 제한하는 경로에서는 준말 변환을 건너뜁니다.

**텍스트 붙여넣기의 라벨 입력**은 `제목:`·`제목1:`·`제목2:`·`개요:`·`상자:`·`네모:`·`원:`·`바:`·`당구:`·`주석:`·`참고:`·`표:` 등을 판별합니다.
제목·개요는 해당 서식 표로 만들고, 나머지 라벨은 지원하는 상자·문두기호·표로 변환합니다.
제목의 첫 쉼표 앞은 부제, 뒤는 제목으로 나누며, 쉼표가 없으면 제목만 만듭니다.
기관별 제목·담당자·날짜는 결과를 확인한 뒤 제출하세요.

### 서식 목록 관리와 백업

서식 관리에서 **사용·세부 수정·이름 바꾸기·삭제**를 할 수 있습니다.
기본 서식은 삭제되지 않으며, 수정하면 사용자 서식으로 저장합니다.
기관을 입력하면 `[기관] 이름` 형태로 구분할 수 있습니다.

프로필 저장 위치는 `%APPDATA%\HwpAutoDocFit\formats`입니다.
서식 JSON에는 예시 표·문장 등 원문의 일부가 포함될 수 있습니다.
공개 저장소에 올리거나 다른 기관에 전달할 때는 민감한 내용이 없는지 먼저 확인하세요.

## 2. 자동 정리의 세부 규칙

기존 README의 상세 규칙을 이곳으로 옮겼습니다. 필요한 항목만 찾아 읽으세요.
실험적 기능과 기본으로 꺼진 기능은 해당 설명에 따릅니다.

- 파일·폴더 드래그 앤 드롭과 여러 문서 일괄 처리, '텍스트 붙여넣기'로 파일 없이도 텍스트를 목록에 바로 추가(자동 저장 폴더를 지정하면 즉시 HWPX로 변환, 비워두면 저장 위치를 직접 골라 .txt로 추가)
- '아웃라이너로 작성': 워크플로위처럼 Tab/Shift+Tab으로 계층을 넣고 빼며 글을 쓰고, ㅁ/ㅇ/-/• 개조식 문두기호로 바로 문서 목록에 추가. 접기/펼치기(Ctrl+↑/↓), 확대(Alt+→/←), 항목 이동(Alt+Shift+↑/↓), 완료 표시(Ctrl+Enter), 메모(Shift+Enter, 개조식에서 ※ 부연설명), 검색(Ctrl+F), 저장·열기(Ctrl+S/O)를 지원하고, 창을 닫으면 쓰던 글을 자동 저장해 다음에 이어 씁니다
- HWP/HWPX 외 TXT·MD·DOC(X)·PDF 파일도 추가해 처리 가능. 자간·서식 작업 전에 작업용 HWPX로
  자동 변환하며 결과물은 항상 HWPX로 저장(MD/DOC(X)/PDF는 선택형 kordoc 엔진 필요, MD는
  엔진이 없으면 서식 없이 텍스트로만 변환). PDF는 텍스트층 없는 스캔 페이지를 내장 OCR로
  인식하고, 문서 안 이미지는 결과 HWPX에 실제로 임베드해 내용 손실을 줄임
- 표준서식 적용 시 문두기호 문장(`□`·`ㅇ`·`-`·`*`·`※` 등) 사이에 빈 줄로 띄운 간격을 모두 지우고 문단 위 여백으로 대신합니다(기본 켜짐, 설정 > 서식 정리 > 보고서 표준서식에서 켜고 끔). 앞뒤가 모두 문두기호 문장인 빈 줄과 문서 끝 빈 줄(빈 쪽 방지)만 지우며, 표·그림이 든 문단, 제목·날짜 주변 빈 줄, 제출서식에서 `○`·`*`처럼 기호만 있는 작성란 앞뒤의 빈 줄(작성 여백)은 그대로 둡니다
- 열거 뒤의 `등`은 바로 앞 어절과 한 어절로 묶어 자간을 조정합니다. 예: `사과, 바나나 등으로`에서 `바나나 등으로`가 `바나나 | 등으로`로 갈라지면 단어 분리로 보고 조정. `등`에 조사만 붙은 경우(`등`, `등의`, `등으로`, `등을` 등)만 해당하며 `등록`·`등급` 같은 낱말은 제외
- 열거의 `단어 + 빈칸 + 숫자 + 쉼표`도 한 어절로 묶어 자간을 조정합니다. 예: `수원 2, 서울 4, 용인 1등으로 구성`에서 `수원 2,`·`서울 4,`가 각각 한 어절이라 `수원 | 2,`로 갈라지면 단어 분리로 보고 조정. 쉼표 없이 끝나는 마지막 항목(`용인 1등으로`)도 바로 앞 항목이 `서울 4,`처럼 숫자+쉼표로 끝나면 한 어절로 묶음. `1, 2, 3`처럼 숫자끼리의 열거나 열거가 아닌 `대회에서 1등으로`는 묶지 않음
- 좁은 표 칸에서 줄 첫머리부터 시작한 단어가 칸 폭보다 길어 넘치면(넘친 부분이 그 줄 글자 수의 20% 초과, 예: 5자 칸의 `질그랭이거|점센터`) 어떤 조정으로도 풀 수 없으므로 시도하지 않고, 검수 보고서에는 문제가 아닌 `칸 폭보다 긴 단어`(적용 제외)로 적습니다
- 표 칸의 자간 조정 한도는 `표 재시도` 설정(기본 5단계)을 쓰되, 한 줄이 20자 이상인 넓은 칸은 본문처럼 `본문 재시도` 한도를 씁니다(좁은 칸은 자간을 많이 바꾸면 글자가 뭉개지므로 표 한도 유지)
- 숫자·기호만으로 된 표 칸(통계표의 수치 칸 등)과 그런 칸으로만 된 표는 어절이 없으므로 자간 초기화·자간 조정·문장부호 병합·단어 분리 검수에서 건너뜁니다(표 글꼴 등 서식 적용은 그대로 함)
- 제목 표 유형: 2×2 제목+날짜·담당자(부제 없음·있음 2종)와 **2행1열 제목+담당자(날짜 칸 없음, 부제+제목 / 담당자)**를 판별해 기준 서식을 적용합니다. 1×1 제목 표는 제목 서식 대상이 아닙니다. 부제(제목 칸의 첫 문단)는 15pt로 맞추며, 설정창 서식 정리의 '제목 부제 크기'(5~40pt, 기본 15)로 바꿀 수 있습니다(서식 프로필 예시 표를 쓰면 그 표의 크기). 제목 바로 뒤의 1칸 요지 표는 문단 좌우 여백 5·줄간격 140%·한컴돋움 15pt 굵게·테두리 0.4mm 기준으로 정리하고, 붙임 표(1행3열·1행2열)도 기준 서식을 적용합니다.

- 저장 후 결과를 다시 열어 제목 고립·문단 쪽 분리·본문/컨트롤 단어 분리를 읽기 전용으로 검사합니다. 선택적 다음 단어 당김의 미적용은 오류 통계에서 제외하고 별도로 기록합니다.
- 문두기호별 굵게 일관성(기본 켜짐, 설정 > 서식 정리 > 항목 이름 강조): 같은 문두기호의 라벨(`- 추진부서 :`, `- (운영방식)`)이 굵게 되면, 그 기호의 다른 문단 머리말도 굵게 맞춤. 예: `- 조례제정 (무료 셔틀버스 …)`의 `조례제정`. 부연설명 괄호와 머리말 없는 일반 문장은 제외
- **내어쓰기 기준(2026-10-10 개정)**: 괄호 라벨 `( )`은 라벨 뒤 본문이 아니라 **문두기호 뒤 첫 글자(`(`)**에 맞춥니다(`ㅇ (개요) 본문…`은 `(`). 콜론 `:` 라벨은 현행대로 **콜론 뒤 본문**에 맞춥니다(`- 추진부서 : …`은 `문`, `- (방식) : …`도 콜론 뒤). 문두기호 바로 뒤 글이 낫표(`「`, `『`)로 시작할 때만 낫표 다음 글자에 맞춥니다. 예: `ㅇ 「공유재산법」…`은 `공`에 맞춤
- 자간을 줄이거나 넓힌 뒤에는 내어쓰기를 다시 적용하고 자간을 재검사합니다(최대 3회). 2차부터는 내어쓰기 값이 실제로 바뀐 문단만 단어 분리를 검사하고, 선택적 '다음 단어 당김'은 하지 않습니다(1차에서 방향 규칙대로 밀어 둔 어절을 다시 당기지 않도록)
- 자간 초기화·단어 보정·짧은 줄 병합에서는 내어쓰기 기준점 앞의 문두기호·라벨·공백을 제외합니다. 자동 보조 장평 조정에서도 같은 선행부를 보호합니다.
- 세부 설정의 '자간 정리' 탭은 실행창 '세부 작업'과 같은 7단계로 구성되며 서로 반영됨(짧은 마지막 줄 병합 글자 수 포함)
- 세부 설정의 '서식 정리'·'내어쓰기' 탭은 실행창 '세부 작업'과 같은 10단계로 구성되며 서로 반영됨(문서 스타일(계층구조) 상세 수정, 문두기호별 글꼴·크기·굵게, 문단위 여백 포함)
- 로컬 문서 구조·가독성 검토: 계층 훑어보기, 기호·서식 편차와 표현 명료성 후보, 읽기 목적별 검토
- 붙여넣은 텍스트 정리: 생성형 AI 채팅창(제미나이·클로드·챗GPT 등)에서 복사한 답변의 마크다운 기호를 지우고 흐트러진 띄어쓰기·줄바꿈을 복원. '개조식으로 변환'은 제목·글머리 기호의 계층 구조를 ㅁ/ㅇ/-/• 문두기호로 바꾸며, 워크플로위 등을 브라우저로 통째로 복사해 줄바꿈이 공백으로 뭉개진 경우도 항목별로 펼쳐 인식
- AI 프롬프트: 붙여넣은 텍스트 정리 > 'AI 프롬프트…'에서 추진계획·행사·회의·심사·공모·결과·검토 보고, 보도자료 요지 등을 라벨 형식으로 답하게 하는 프롬프트를 복사하고, 챗GPT·클로드·제미나이를 브라우저로 엽니다(앱은 AI에 아무것도 전송하지 않음)
- 작성 도우미(파일 목록 옆 버튼): 금액 한글 병기(`금1,500,000원(금일백오십만원)`)·쉼표·천원 단위, 날짜 요일 붙이기·고치기와 이번/다음 달 금요일·기간·날짜 차이, 붙여넣은 표의 열 합계·평균·행 합계·구성비, 만 나이·주민번호→생년월일·주민번호 가리기, 번호 다시 매기기(1. 가. ① Ⅰ. 등), 회신공문 본문 생성
- 기관 서식: 작성 도우미 > '기관 서식'에서 기관 문서의 스타일을 전수 분석해 보고서(`_스타일분석.md`)와 예시 서식(`_서식예시.hwpx`)을 만들고 기관 이름을 붙여 문서 서식으로 등록합니다. 서식 목록에는 기본 서식 다음에 `[기관] 이름` 순으로 묶여 보이며, 서식 이름 바꾸기에서 기관도 바꿀 수 있습니다. 명령줄: `python scripts/style_inventory.py 문서.hwp`
- 서식 정리의 문두기호별 글꼴 선택 목록에 한컴오피스 전용 번들(HFT) 글꼴도 설치 경로에서 자동으로 찾아 포함

## 3. 문서 검토와 글쓰기 도구

### 문서 구조·가독성 검토

실행창의 **문서 구조·가독성 검토…**는 선택한 문서의 HWPX 구조를 읽기 전용으로 분석합니다.
HWP 입력은 임시 HWPX로 변환하며 원본을 변경하지 않습니다. 문서 유형(보고서·계획서·기안문)과
읽기 목적(빠른 의사결정용·상세 설명용)을 선택하면 계층 훑어보기와 검토 후보를 표시합니다.
선택된 서식 프로필이 있으면 그 프로필의 스타일을 비교 기준으로 사용하고, 검토 결과는 JSON으로
저장할 수 있습니다. 위치는 인쇄 쪽 번호가 아닌 HWPX 구역·본문 문단 번호 또는 표 행·열입니다.
문장 의미나 두괄식 적합성은 자동 확정하지 않으며, 원문 수정도 하지 않습니다.

### 공공언어 바로쓰기·한국어 문서 교정

실행창에서 HWP/HWPX 파일을 추가한 뒤 **공공언어·맞춤법 검토…**를 누르면
앱에 내장된 로컬 규칙이 본문과 표 셀의 교정 후보를 일괄 검출합니다. 외부 검사
서비스에 문서 내용을 전송하지 않습니다. 목록에서 승인할 표현만 선택하여
**선택 교정 승인·새 파일 저장**을 누르면 원본은 유지하고 같은 폴더에
`*_공공언어교정.hwpx`를 만듭니다. HWP 입력은 임시 HWPX로 변환한 뒤 검사합니다.

**선택 표현 이후 검색에서 제외**를 누르면 그 표현은 이후 검사에서 빠집니다.
제외 목록은 `%APPDATA%\HwpAutoDocFit\proofreading_exclusions.json`에 저장되고,
**제외 목록 관리**에서 다시 검색하도록 복원할 수 있습니다. 공공언어 교정안은
문맥에 따라 달라질 수 있는 *제안*이며, 내장 규칙만으로 모든 맞춤법 오류를
찾는 것은 아닙니다. 특히 인명·기관명·인용문은 승인 전에 문맥을 확인하세요.

### 붙여넣은 텍스트 정리

실행창의 **붙여넣은 텍스트 정리…**는 제미나이·클로드·챗GPT 같은 생성형 AI 채팅창에서
마우스로 복사한 답변을 대상으로 합니다. 창을 열면 클립보드 내용을 왼쪽 입력란에 자동으로
채우며, 직접 붙여넣거나 편집할 수도 있습니다. **한 번에 정리**를 누르면 `**굵게**`, `# 제목`,
`` `코드` `` 같은 마크다운 기호를 지우고, 목록·제목은 각각 문단으로 분리하며, 줄바꿈이 무시되어
한 줄로 뭉쳐진 문장은 다시 자연스러운 문단으로 이어 붙입니다. 백슬래시로 이스케이프된 강조
기호(예: `\*\*굵게\*\*`)도 먼저 풀어낸 뒤 정리하고, 문장 끝에 붙는 `[1]`·`[2][4]` 같은 숫자
전용 각주 표시는 제거하되 `[별표 21의2]`처럼 글자가 섞인 대괄호는 그대로 남깁니다.

**개조식으로 변환** 버튼은 제목(`#`)과 글머리 기호의 계층 구조를 공문서 개조식 문두기호로
바꿉니다. 1단계는 원문에 이미 있는 번호("1.", "2." 등)를 그대로 쓰고 없으면 `ㅁ`을 붙이며,
그 아래는 글머리 기호의 들여쓰기 깊이에 따라 `ㅇ`→`-`→`•`(3단계 이후는 모두 `•`) 순으로
문두기호를 매깁니다. 워크플로위 같은 아웃라이너를 브라우저에서 통째로 복사하면 줄바꿈이 전부
공백으로 뭉개져 한 줄에 " - "만 남는 경우가 있는데, 이때는 계층 깊이까지 복원할 수는 없지만
항목만은 한 줄씩 펼쳐서 `ㅇ`로 표시하고 워크플로위 해시태그(`#표시`)도 정리합니다. 정확한 계층
까지 살리려면 아래 아웃라이너로 직접 쓰거나, 워크플로위의 '내보내기 > 일반 텍스트'처럼 줄바꿈이
보존된 형식으로 붙여넣으세요.

HWP/HWPX 파일이나 한글 프로그램은 전혀 사용하지 않는 순수 텍스트 변환이며, **결과 복사**로
정리된 텍스트를 클립보드에 담아 원하는 곳에 붙여넣을 수 있습니다.

### 아웃라이너로 작성

실행창 '01 정리할 문서'의 **아웃라이너로 작성** 버튼은 워크플로위처럼 계층 구조로 글을 쓰는
창을 엽니다. `Enter`로 같은 계층의 새 항목을 이어가고, `Tab`/`Shift+Tab`으로 바로 위 항목
아래로 한 단계 들여쓰거나 내어씁니다. 저장 형식 자체가 계층 구조를 담은 마크다운(0단계는
`# 본문`, 그 아래는 `- 본문`을 들여쓰기 깊이만큼 겹쳐 표시)이라, **개조식 텍스트로 추가**를
누르면 0단계는 `ㅁ`, 1단계는 `ㅇ`, 2단계는 `-`, 3단계 이후는 모두 `•`로 바꿔 바로 '01 정리할
문서' 목록에 추가합니다. **마크다운으로 추가**를 누르면 원본 마크다운 그대로 추가되어, 고급
문서 엔진(kordoc)이 있을 때 서식을 살려 변환할 수 있습니다.

### 텍스트 붙여넣기로 문서 추가

실행창 '01 정리할 문서'의 **텍스트 붙여넣기** 버튼은 파일 없이 텍스트만으로 문서를
추가합니다. 창을 열면 클립보드 내용을 자동으로 채우며, **자동 저장 폴더**를 지정해 두면
**문서로 추가**를 누르는 즉시 그 폴더에 HWPX로 변환해(배치 자간·서식 작업과는 독립된 한/글
세션을 새로 띄워 사용하므로 다른 작업이 실행 중이 아니어야 합니다) 목록에 추가합니다. 폴더를
비워두면 기존처럼 저장 위치를 직접 골라 .txt로 추가합니다.

## 4. 고급 문서 도구와 추가 설치

기본 HWP·HWPX 편집과 기본 Markdown 내보내기에는 이 설치가 필요하지 않습니다.
**고급 문서 도구**나 MD·DOC(X)·PDF 변환에는 선택형 **kordoc v4** 엔진을 사용합니다.

지원 기능에는 페이지별 Markdown, 표 추출·분류, 블록·칸 비교, 누름틀·양식 필드 분석,
내용 패치, 페이지 미리보기, Markdown에서 HWPX 생성 등이 있습니다.
공통 문서 IR은 구조화된 JSON, RAG 청크는 검색용으로 나눈 문서 조각을 뜻합니다.

1. 기관의 외부 패키지 설치 정책을 확인합니다.
2. [Node.js 공식 다운로드](https://nodejs.org/ko/download)에서 지원 중인 LTS 버전을 설치합니다.
3. 앱을 완전히 종료한 뒤 다시 실행하고 **고급 문서 도구**를 엽니다.
4. 처음에는 내용 공개에 문제가 없는 작은 파일로 시험합니다.

앱은 `npx -y kordoc@^4`로 엔진을 호출하므로 첫 실행에 패키지 다운로드가 필요할 수 있습니다.
검토한 [kordoc 4.18.8의 요구 환경](https://github.com/chrisryugj/kordoc/blob/d15ee77d717e0670947d80b082aa5d7fa54eb249/package.json)은 **Node.js 20 이상**입니다.
앱의 일부 안내에 남아 있는 “18 이상”보다 엔진 패키지의 실제 요구 조건을 우선하세요.
`^4`는 버전 범위이므로 설치되는 엔진의 요구 조건도 확인해야 합니다.

- **MD**: 엔진이 없으면 서식 없는 텍스트 경로로 변환할 수 있습니다.
- **DOC·DOCX·PDF**: 형식과 엔진 지원 범위에 따라 변환이 실패하거나 배치가 달라질 수 있습니다.
- **스캔 PDF**: OCR에 필요한 구성요소와 모델이 준비되어야 합니다. 인식 결과의 숫자·표·이름을 반드시 확인하세요.
- **폐쇄망**: 엔진과 의존 패키지·필요 모델의 사전 준비가 필요합니다. Node.js만 설치했다고 오프라인 변환이 모두 되는 것은 아닙니다.

외부 엔진의 분석·미리보기·패치 성공은 원본 서식 전체나 모든 쪽의 완전한 일치를 보장하지 않습니다.
문서 내용을 외부 AI에 보내는 버튼과 혼동하지 마세요. 앱의 AI 프롬프트 기능은 복사할 문구와 브라우저 링크를 제공하며, 사용자가 외부 서비스에 직접 붙여넣는 내용은 해당 기관 정책을 따라야 합니다.

## 5. 검사·설정·로그 보관

### 자동 검사

- **저장 후 검수**: 결과를 다시 열어 단어 분리·쪽 배치 등 남은 문제를 확인합니다.
- **무결성 검사**: 처리 전후의 본문·표·이미지·구역 등 내용과 구조 변화를 비교합니다.
- **숫자 대조**: 표 주변 본문의 금액·비율·인원 등이 표와 맞는지 검토 후보를 제시합니다. 숫자를 자동으로 고치지 않습니다.
- **최종검수**: 작업 목표, 실행 결과, 검사 상태를 보고서로 남깁니다. 작업 수행 점수와 문서의 완성도·모든 규칙의 준수율은 같은 값이 아닙니다.

경고가 있더라도 결과 파일이 남을 수 있습니다. 파일이 있다는 사실만으로 검사가 통과했다고 판단하지 마세요.
표·이미지·컨트롤이 줄어드는 등 내용 손실 신호가 있으면 결과와 원본을 확인하세요.
자동 검수는 최종 확인을 대신하지 않습니다.

### 저장 위치

| 자료 | 위치 |
|---|---|
| 사용자 설정 | `%APPDATA%\HwpAutoDocFit\settings.json` |
| 사용자 서식 | `%APPDATA%\HwpAutoDocFit\formats` |
| 교정 제외 목록 | `%APPDATA%\HwpAutoDocFit\proofreading_exclusions.json` |
| 결과 HWPX | 원본과 같은 폴더, 작업별 접미사 사용 |
| 최종검수 보고서 | 첫 번째 입력 문서와 같은 폴더의 `문서이름(최종검수).json` |
| 작업 로그 파일 | 로그 저장을 켠 경우에만, 첫 번째 입력 문서와 같은 폴더의 `문서이름(작업로그-날짜시간).log` |

Windows 탐색기의 주소창에 `%APPDATA%\HwpAutoDocFit`를 입력하면 설정 폴더를 열 수 있습니다.
앱을 종료한 뒤 백업하고, 설정 파일을 직접 수정하기보다 앱 화면에서 변경하세요.
여러 문서를 한꺼번에 처리한 작업의 보고서는 첫 문서 이름으로 저장되므로 해당 폴더부터 확인하세요.
