# AI 웹 답변 → 개조식 공문서 (1.74 Alpha 4 설계)

입력은 Gemini/ChatGPT/Claude 웹서비스에서 복사한 **텍스트**다. 서비스 API·MCP 호출 없이 로컬에서 처리한다. Flutter/WebView2를 유지한다.

## 처리 단계

1. HTML 문자 참조(`&gt;`, `&#62;`, `&nbsp;` 등)와 이스케이프 Markdown·보이지 않는 문자를 정규화한다. 줄 앞 `>`는 인용 구조로 해석하며 본문 비교 연산자 `3 > 2`는 보존한다.
2. 서비스 출처 표식 `[1]`, `[1, 2]`, `[cite:...]`, `[cite_start/end]`, `【…】`, ChatGPT contentReference/oaicite 표식을 제거한다. 강조 기호 사이 각주를 없앨 때 임시 경계를 둬 `**본문**[2]**.**`가 잘못된 삼중 강조로 합쳐지지 않게 한다. 경계는 출력 전에 제거한다.
3. 제목·번호·글머리·서로 다른 들여쓰기·인용·표를 구조 블록으로 읽는다. Markdown 제목 깊이와 `1. → 1.1 → 1.1.1`, `Ⅰ. → 1. → 가. → 1) → 가) → (1) → (가) → ① → ㉮` 등 원문에서 확인되는 구조를 정규화한다. 명시적 구조 없이 잃어버린 글꼴/들여쓰기를 임의로 복원하지 않는다.
4. 기존 공문서 항목기호 정책을 적용한다: 3단계 이하 `□ → ㅇ → -`, 4단계 `Ⅰ. → □ → ㅇ → -`, 5단계 이상 `1. → 가. → 1) → 가) → (1) → (가) → ① → ㉮`. 참고/인용은 `※`. 제목·개요·표는 기존 라벨 블록으로 전달한다. 원문 문장의 사실·수치·법령 대괄호·의미 있는 따옴표/괄호/슬래시는 보존한다. 날짜의 마침표를 목차 번호로 쪼개지 않는다.
5. Flutter 원문 붙여넣기 화면에서 변환 미리보기를 제공한다. 사용자가 AI 답변 입력을 명시한 이 경로는 강제 구조 변환을 적용하고, 일반 파일의 기존 자동 판별·이미 개조식/라벨인 입력의 보호는 유지한다.
6. 문서 추가 시 설정된 붙여넣기 폴더(없으면 앱 설정 폴더의 붙여넣기 작업 폴더)에 새 TXT를 배타 생성하고, 기존 TXT→라벨→HWPX→한 번에 적용 파이프라인으로 넘긴다. 사용자 파일을 덮어쓰지 않는다. 실제 COM 처리는 기존 worker가 맡는다. 작업 중 추가/변경은 막고 저장 실패 시 입력을 유지한다.

## 회귀 기준

- 실제 벤치 민원 답변 6문단: 정리/개조식/AI 라벨 경로에서 의미 있는 문자 전체 일치, `&gt;`, 강조·각주·임시 경계 잔여 없음.
- 세 서비스의 제목/번호/목록/인용/표·서비스별 출처 표식, 원문 위계가 얕아지거나 다른 형식으로 돌아올 때 부모 단계 복귀.
- 내용 번호·날짜·법령·계산·문장부호 보존, 이미 개조식/라벨 입력 중복 변환 방지, 취소/저장 실패/작업 중 잠금.
- Flutter 화면과 실제 TXT 변환 진입점의 계약/회귀 시험. Windows HWP COM·실문서·EXE 결과는 별도 실기기 검증으로 남긴다.

이 기능은 복사된 텍스트의 구조와 기호를 변환한다. 외부 AI를 호출해 문장을 요약하거나 문체를 재작성하지 않는다. 무조건 모든 특수 문자를 지우지 않고 형식/출처 문법만 제거한다.

## 입력 분석과 예외 처리 상세 설계

서비스 이름으로 변환기를 분기하지 않는다. 같은 서비스에서도 복사 버튼, 화면 선택 복사, 브라우저, 답변 유형에 따라 텍스트가 달라지므로 실제 입력 문법을 판별한다. 아래 사례는 처리 규칙과 검증 대상이며, 세 서비스의 모든 화면에서 채취해 검증했다는 의미는 아니다. 서비스 변경과 복사 과정에서 소실된 구조까지 완전히 추정할 수는 없으므로 미리보기와 보수적 보존을 기본으로 한다.

| 입력 유형 | 예시 | 처리 기준 |
| --- | --- | --- |
| 렌더링된 평문 | 제목과 본문, 빈 줄만 남은 답변 | 문단 보존. 단순히 짧다는 이유로 제목으로 승격하지 않음 |
| 원시 Markdown | `## 추진 계획`, `**검토**`, `__강조__` | 블록 구조를 먼저 읽고 인라인 서식 제거 |
| 이스케이프된 Markdown | `\*\* 안녕하십니까.\*\*` | 제한된 Markdown 이스케이프 복원 후 공백을 포함한 강조 제거 |
| HTML 문자 참조 | `&gt;`, `&#x20;`, `&#xC77C;`, `&nbsp;` | 정상 문자 복원. 날짜·한글·의미 있는 비교 기호 보존 |
| 중첩된 문자 참조 | `&amp;gt;` | 무제한 반복 디코딩 금지. 변환 모드에서 제한된 재해석을 검토하고 원문 미리보기 제공 |
| 인용 | `>`, `>>`, `&gt; **본문**` | 인용 블록 구조 해석 후 원래 인용 기호 제거. 참조 내용은 `※`로 표현 |
| 출처 | `[1]`, `[1, 2]`, `[cite:...]`, `【...】`, `oaicite` | 알려진 출처 문법만 제거. 숫자 배열·법령·업무상 대괄호는 문맥으로 구분 |
| 출처와 강조 접합 | `**감사합니다**[2]**.**` | 출처 제거로 강조 기호가 합쳐지지 않도록 경계 보호 후 서식 제거 |
| 번호형 위계 | `1.`, `1.1`, `가.`, `1)`, `(가)`, `①` | 번호 종류·명시적 깊이·들여쓰기를 함께 해석하고 형제/상위 항목 복귀 |
| 날짜·수치 | `2026. 10. 13.`, `1.74`, `3 > 2`, `2 * 3` | 목차나 강조로 오인하지 않음. 수치와 연산자 보존 |
| 목록·체크박스 | `-`, `•`, `☑`, `- [x]` | 목록 구조로 해석. 완료/미완료 의미는 삭제하지 않음 |
| HTML 태그 | `<strong>`, `<br>`, `<li>` | 허용 태그만 구조/서식으로 해석. 실제 HTML 소스가 목적이면 코드로 보존 |
| 링크·이미지 | `[자료](https://...)`, `![설명](...)` | 표시 문구 보존. URL 보존 여부는 출처 정책에 명시. 이미지 자체를 평문에서 복원하지 않음 |
| 표 | Markdown 표, 탭 구분 표 | 열·행과 머리글 유지. 구분선만 제거. 불균등 열은 데이터 손실 없이 경고/평문 보존 |
| 코드·수식 | fenced code, `items[1]`, `x**2`, LaTeX | 일반 강조·출처 제거에서 보호. 실행하거나 임의로 공문 목록으로 변환하지 않음 |
| 서비스 화면 문구 | 복사, 좋아요, 답변 재생성 등 | 원문 본문과 구분되는 확실한 UI 조각만 제거. “문의해 주세요” 같은 본문은 자동 삭제하지 않음 |
| 문단 줄바꿈 손실 | 여러 줄로 접힌 문장/한 줄에 붙은 목록 | 명시적 목록 경계만 복원. 잃어버린 계층을 임의 생성하지 않음 |
| 깨진 강조 | 닫히지 않은 `**`, 여러 강조 중첩 | 전체 특수문자 일괄 삭제 금지. 확인 가능한 서식 범위만 제거, 불명확한 부분 미리보기 |
| 기존 공문서 | `제목:`, `네모:`, `□`, `ㅇ` | 이미 적용된 구조 보호. 두 번 실행해 번호·목차가 중복되지 않음 |
| 연락처·담당자 | `과(동)장: 홍길동, 팀장: 이순신` | 콜론과 이름까지 각각 하나의 의미단위. 쉼표는 별도 묶음 경계 |
| 전화·주소·URL | `☎ 02-3153-0000`, 경로, 이메일 | 하이픈·콜론·슬래시를 목록 기호로 오인하지 않음 |

## 내부 구조와 변환 순서

변환 결과는 문자열만 반환하지 않고 `blocks`, `warnings`, `removed_markers`, `source_spans`를 갖는 구조로 확장한다. 블록 종류는 제목, 본문, 목록, 참고, 표, 코드로 구분하며 원문 줄 범위와 원래 위계를 저장한다. 제거 사유를 추적할 수 있어야 하며 화면에는 사용자 판단에 필요한 불확실한 구조만 표시한다.

1. 입력 크기와 빈 입력 검사, 줄바꿈/유니코드 공백 정규화.
2. 코드·수식·URL 등 보호 범위 분리.
3. 보호 범위 밖에서 문자 참조와 이스케이프 복원.
4. 줄별 구조 토큰 생성: 제목 깊이, 번호 형태, 들여쓰기, 인용 깊이, 표.
5. 출처 제거와 인라인 서식 제거. 문장·숫자·연락처는 변경하지 않음.
6. 부모 스택으로 계층 복원. 같은 깊이는 형제, 얕아지면 부모 복귀. 단계가 건너뛰면 빈 목차를 만들지 않고 확인된 단계만 압축.
7. 기존 항목기호 정책으로 블록 직렬화. 본문의 “합니다”를 임의로 명사형으로 재작성하지 않음.
8. 원문/결과 미리보기와 불확실성 확인 후 기존 문서 처리 경로로 전달.
9. 자간 조정에서 직함·콜론·이름 의미단위를 보호. 일반 텍스트를 NBSP로 치환하지 않음.

정리, 위계 변환, 문체 재작성은 별도 책임으로 둔다. 이번 로컬 변환은 형식 정리와 위계 변환을 담당한다. 문체까지 바꾸려면 사실·주체·시제·조건이 달라질 수 있어 별도의 명시적 규칙과 검증이 필요하다.

## 직함·이름 의미단위

인식 대상은 확인된 직함/직위(예: 과(동)장, 과장, 동장, 팀장, 주무관, 담당자)와 `:` 또는 `：`, 이름으로 구성된 범위다. 이름과 콜론 사이의 공백도 포함하며 `○○○` 같은 담당자 미정 표시는 이름 자리로 인정한다. `과(동)장: 홍길동`, `팀장: 이순신`, `주무관: 홍당무`는 세 개의 독립 단위다. 쉼표, 줄바꿈, 다음 직함, 전화번호 시작에서 범위를 끝낸다. `장소: 서울`, `처리부서: 공원녹지과`를 사람 이름 단위로 묶지 않는다. 실제 줄 나눔 후보가 단위 내부일 때 전체 범위를 자간 조정에 전달하고 다른 단위와 합치지 않는다.

## 검증 매트릭스와 완료 조건

각 사례를 정리 함수, AI 구조 변환, 라벨 직렬화/역변환, 텍스트 입력 → TXT → HWPX 진입점에 동일하게 적용한다. 서비스별로 평문·Markdown·이스케이프 복사 사례를 구성하고 브라우저 차이는 입력 문자열 차이로 검증한다.

- 사용자 제공 민원 답변: 인사, 본문 4문단, 감사, 담당자, 날짜까지 누락 없이 보존하고 `**`, `\*`, `&gt;`, 출처 잔여를 검사.
- 계층: 1~8단계, 혼합 번호/글머리, 들여쓰기 탭/공백, 상위 복귀, 번호 재시작, 제목 뒤 본문, 같은 이름의 다른 부모.
- 보존: 날짜, 버전, 금액, 법령, 배열 인덱스, 수식, 전화, 이름, URL, 코드, 실제 인용문.
- 모호함: 깨진 강조, 독립 `[1]`, 구조 소실, 사용자 입력 자체의 별표, 표 열 불일치. 데이터 보존과 경고가 우선.
- 안정성: 빈 입력, 큰 입력, 반복 적용, 취소, 저장 실패, 작업 중 입력, 중복 파일명, 변환 예외. 원문 유실·덮어쓰기·UI 멈춤을 막음.
- 의미단위: 각 직함·이름 내부의 모든 줄 경계 위치를 검사. 쉼표/다음 담당자/전화에서는 병합 금지.
- Windows 최종 검증: 실제 한글에서 한 번에 적용, 자간 조정, HWPX 저장/재열기, Flutter 유지와 Tk fallback. Linux 단위시험으로 이 결과를 대체하지 않음.

## 현재 구현과 남은 구현의 구분

현재 수정은 HTML 문자 참조/이스케이프 복원, 공백을 포함한 굵게 표시 제거, 출처와 강조의 접합 처리, 날짜 보호, 번호 형태별 구조 해석을 포함한다. 사용자 민원 원문과 베타 1의 공백·이스케이프 사례는 회귀시험에 추가했다. 보호 범위 기반 코드/수식 처리, 모호한 출처 판별, 구조 경고 모델, Flutter 미리보기/추가 화면, 직함·이름의 실제 자간 조정 연동 및 Windows 실문서 검증은 이 설계에 따라 계속 구현할 항목이다.
