## 2. 진행 중이던 작업: 서식 통일 개편 (알파)

### 사용자 결정 (2026-10-11)
1. 서식 통일은 기본으로 **글꼴·크기만** 맞춘다(항목기호·라벨 굵게, 괄호 크기 -2pt 규칙 포함). 카드 옵션 `전체 서식 맞추기`(`unify_full_format`, 기본 끔)를 켜면 예전처럼 전체 서식(글자색·음영·기울임·밑줄·취소선·장평·정렬·좌우 여백·위 간격·내어쓰기)을 맞춘다. 한 번에 적용·서식 적용 모드의 서식통일은 그대로 전체 서식.
2. 표본 조사(대표값·불일치 탐지)를 한/글 문단 순회가 아니라 HWPX에서 한다(승인).
3. 알파에서 먼저 시험하고 **개선 효과를 평가한 뒤 베타에 반영**한다. 아직 베타(`main`)에는 반영하지 않았다.

### 구현된 것 (`709454c`)
- `hwp-auto-docfit.py`
  - `알파_서식통일_XML조사_사용`(기본 켬), `_서식통일_XML_조사()`: HWPX 직속 문단 목록(`_서식통일_HWPX_분석()["paragraphs"]`)에서 표본·문맥·위치 글을 만든다. 쓸 수 없으면 None → 예전 순회 `_서식통일_COM_조사()`(기존 루프를 그대로 옮긴 함수)로 복귀.
  - 안전장치: ① `MoveDocEnd` 뒤 한/글 끝 문단 번호 = HWPX 직속 문단 수 ② 글이 있는 문단 3곳(첫·가운데·끝)의 글이 한/글과 같음. 어긋나면 폴백. 1쪽 끝(표지 판정용)은 쪽 번호 이분 탐색.
  - 고칠 문장(`계획`의 mismatch·미확정)만 한/글에서 글을 다시 읽어 `item["text"]`로 바꾼다(자간·내어쓰기 단계가 이 글을 열쇠로 쓴다). HWPX 글과 다르면 그 문장은 건드리지 않는다.
  - `_서식통일_글꼴크기만()`: `작업_모드 == "unify"`이고 세부 작업 `unify_full_format`이 꺼져 있으면 참. `_서식통일_글꼴크기_대표()`가 대표값에서 `font·size·marker_bold·label_bold`만 남기고, 위 간격 비교를 끈다. 비교 기준이 없는 내어쓰기 상태는 한/글에 묻지 않는다.
  - 설정 `unify_full_format`(기본 False), Tk 카드 체크 `전체 서식 맞추기`, 요약 문구, 설정 저장·불러오기 연결.
- `docfit_core/stage_selection.py`: 세부 작업 `unify_full_format`(서식 통일 목록의 `style_unify` 바로 뒤, 기본 끔), `CARD_OPTION_STAGES["unify_full_format"]`.
- `desktop_web_ui.py`·`desktop_web/app.js`·`desktop_web/index.html`·`flutter_ui/lib/main.dart`: 카드 옵션 추가(기존 `unify_keep_layout`과 같은 방식).
- `scripts/regression_pc.py`: 서식 통일 카드 옵션 `unify_full_format`을 세부 작업에 반영.
- 시험: `tests/test_unify_font_size_xml.py`(9개: 모드 판정, 대표값 축소, XML 조사 5가지, 전체 흐름에서 XML 조사 결과 = 예전 순회 결과), `tests/test_pipeline_review.py`(글자색 불일치가 기본에서는 안 고쳐지고 전체 서식에서만 고쳐짐), 기존 시험 기대값 갱신.
- 문서: `docs/작업결과_2026-10-11.md`(이 개편 절 + PC 측정 항목), `HANDOVER.md`.

### 아직 안 한 것 / 다음 할 일
1. **PC 측정**(개선 효과 평가의 핵심): 같은 문서로 번갈아 2회씩.
   - `scripts/regression_pc.py --flag 알파_서식통일_XML조사_사용=0`(끔) 대 기본(켬): 처리 기록의 `서식통일 조사` 단계 시간, 전체 시간, 최종 검수 점수, 결과 글·글자 서식 비교.

   - 예시 파일: test4, 회의자료(서식 문서), 가능하면 폴더 `111`의 HWPX 여러 개. 사용자 원본은 사본으로 시험.
2. **알파 ≥ 베타 합격 판정**: 최종 검수 점수·쪽 구성·글자 보존이 베타와 같거나 나을 때만 베타 반영.
3. 한/글에서 XML 조사의 **문단 번호 대응**이 실제 문서에서 자주 어긋나는지 확인(로그 `문단 번호가 HWPX와 맞지 않아…` 또는 `…글이 HWPX와 달라…` 문구). 자주 나오면 원인(다중 구역, 숨은 문단, 표 안 문단 번호 등)을 찾아야 한다. 이 경우에도 결과는 예전 방식으로 안전하게 폴백한다.

5. 합격하면 베타 반영: `alpha` 변경만 `main`에 가져오되(`git cherry-pick`), 알파 전용 플래그 구조(`알파_…_사용`)와 항목기호/문두기호 용어 차이(`alpha`는 "항목기호", `main`은 "문두기호"로 이름이 달라 충돌할 수 있다)를 확인한다. 반영 후 `APP_VERSION`·릴리스 노트·exe 빌드·SHA-256·태그는 HANDOVER §6 절차.
6. 사용자가 이어서 요청했던 것은 아니지만 남은 정리: README의 "현재 안내 기준: 1.72 Beta 10" 문구와 `(최종검수).json 기본 켜짐` 표기가 낡았다(기본 꺼짐으로 바뀜).

## 4. 작업 규칙·환경 메모

- Windows + 한/글 2020 COM, 테스트 `python -m unittest discover -s tests`. 푸시는 `github` 먼저, 그다음 `origin`(GitLab). XML은 `defusedxml`만(lxml 쓰지 않음). `hwp-auto-docfit.py` 줄바꿈(저장소에서는 LF, 사용자 PC에서 CRLF일 수 있으니 편집기 설정 확인).
- 사용자 문서 원본은 수정하지 않고 사본으로 시험. 사용자와는 한국어. 작업이 끝나면 요청이 없어도 커밋하고 지정 브랜치에 푸시.
- 클라우드 세션 제약: Windows·한/글 없음(한/글 동작은 시험 못 함), GitLab 접속 불가, 태그 푸시 불가, Dart/Flutter SDK 없음.
- Linux에서 시험하려면 저장소 루트에서 `python3 scripts/linux_stub_test_runner.py discover -s tests`(기준선: 실패 7·오류 15, 모두 Tk·Windows 경로 시험).
- 한 번에 적용 등 알파 플래그는 `scripts/regression_pc.py --beta-mode`로 한꺼번에 끌 수 있다(`알파_…_사용`으로 시작하는 전역).
