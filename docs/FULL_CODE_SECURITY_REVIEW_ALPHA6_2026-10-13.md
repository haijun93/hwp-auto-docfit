# Alpha 6 전체 소스·보안·개선 효과 검증

검토일: 2026-10-13. 기반 커밋 7758f9e, 이번 보안 수정은 후속 alpha 커밋에 포함한다.

전체 Flutter 전환 완료를 의미하지 않는다. 이번 검증 대상은 Alpha 6까지 구현한 소스와 기존 처리 경로다. Windows 네이티브 COM 연결·모든 화면 전환은 아직 남아 있다.

## 결론

재현 가능한 문제 두 가지를 발견하고 수정했다. MCP 출력 파일 생성 경쟁 조건과 HWPX 중복 ZIP 항목 수용 문제다. 두 문제 모두 수정 전 실패하는 회귀 시험으로 확인했다. IPC 인증 우회나 입력을 통한 Python 임의 명령 실행은 이번 검사에서 재현하지 못했다. 이를 침투 불가능 보증으로 해석하면 안 된다.

## 재현·수정한 위험

| 항목 | 공격·오류 조건 | 영향 | 대응·증거 |
|---|---|---|---|
| MCP 출력 경쟁 조건 | 파일 없음 검사 뒤 생성 도중 다른 writer가 같은 최종 파일 생성 | 다른 문서 덮어쓰기 또는 실패 정리 때 삭제 가능 | 임시 파일 생성·검증 후 xb로 새 파일만 생성, 본인이 생성한 실패 출력만 정리. 수정 전 race 시험 실패, 수정 후 기존 파일 보존 |
| 중복 HWPX ZIP 항목 | 동일 section 이름 또는 정규화 뒤 같은 이름의 항목을 여러 번 삽입 | 도구별 다른 본문 해석·무결성 판단 혼동 | set 기반 중복 검사 후 즉시 거절. 수정 전 duplicate 시험 실패, 수정 후 통과 |
| 개발 설치 도구 pip | 취약 버전으로 악성 배포 파일·인덱스를 사용한 설치 | 패키지 설치 단계 파일 경로 조작 등 | 클라우드 venv 설치 도구 갱신. 앱 런타임이 외부 pip 설치를 실행하는 취약점과 구분 |

Windows 예약 장치 이름(NUL, CON.report, COM1 등)도 출력 이름으로 거절하도록 추가 보완했다. Windows 장치 동작 자체는 미실행이며 이름 검증은 Linux에서도 회귀 검사했다.

MCP는 이번에 활성화하거나 기능을 확대하지 않았다. 기존 출력 보존 경계만 수정했다. 배포용 Windows 의존성 및 사용자의 설치 환경은 별도 검사해야 한다.

## 해킹 시나리오 점검

- 네이티브 IPC는 127.0.0.1 임시 포트에만 바인딩한다. 32바이트 난수 토큰을 자식 stdin으로 전달하고 argv·환경·로그에 넣지 않는다. 잘못된 토큰은 명령 실행 없이 연결을 닫는다. auth 시험, 버전·중복 요청 거절 시험 통과.
- 서버 allowlist 밖 exec 명령은 거절한다. payload를 eval/exec/pickle로 실행하지 않는다. 외부 엔진 호출은 shell=True 없이 인자 배열을 사용한다. kordoc은 버전 고정, 자동 npx 다운로드는 명시적 환경 설정 없이는 차단한다.
- 메시지 최대 1MiB, 연결 8개, 요청 대기 8개다. 대형 프레임은 닫으며 부모 EOF·정상 shutdown 및 강제 종료 후 복구를 검증했다.
- ZIP 경로 탈출·심볼릭 링크·과도한 항목/크기/압축률·CRC 이상을 검사하고 외부 XML 엔티티는 defusedxml에서 거절한다. 로컬 파일을 읽게 하는 엔티티 공격 시험이 통과했다.
- MCP 출력 폴더는 프로세스 설정으로 고정하며 filename은 경로 문자를 허용하지 않는다. 임시 입력은 작업 종료 때 삭제한다. 문서 전체를 로그로 출력하는 경로는 추가하지 않았다.
- 구형 HTML UI는 문서명·상태 등을 textContent로 표시한다. Flutter는 Text 위젯으로 표시한다. BrowserApi는 46개 명령만 노출하고 GUI 객체는 숨긴다. pywebview 내부 HTTP 서버도 loopback 주소를 사용한다. 실제 Windows WebView2 origin·외부 탐색·파일 드롭 동작은 추가 검증이 필요하다.
- 업데이트는 HTTPS 허용 호스트·각 리디렉션·기본 TLS 검증·크기·MZ·필수 SHA256을 확인한다. SHA256 없는 자동 설치는 거절한다. 서명된 바이너리·서명된 릴리스 목록은 아직 검증하지 않는다. 배포 계정 탈취 시 EXE와 해시를 함께 바꾸는 위험은 이 검사로 해결되지 않는다.

## 남은 위험과 개선 우선순위

1. **네이티브 정식 전환 전 필수:** COM 전용 STA 작업 큐, job_id·진행 이벤트·취소·비동기 분석을 연결한다. 현재 분석은 서비스 잠금 아래 동기 실행되므로 큰 정상 문서도 UI 요청을 지연시킬 수 있다. 처리 시작은 비활성화했다.
2. **로컬 서비스 가용성:** 토큰을 모르는 다른 로컬 프로세스도 연결 슬롯을 점유해 서비스 거부를 시도할 수 있다. 토큰 인증은 OS 사용자 격리를 대신하지 않는다. 다중 사용자 Windows 환경은 ACL을 적용한 Named Pipe 또는 인증 전 짧은 timeout·접속 정책을 검토해야 한다.
3. **파서 자원 제한:** 기존 HWPX 최대 해제 512MiB·단일 항목 128MiB는 유한한 제한이지만 XML DOM·결과 JSON 메모리 증폭까지 막지는 않는다. 악성/극대형 입력의 분석은 별도 프로세스와 더 낮은 시제품 제한을 시험한 뒤 적용한다. 임의로 정상 문서 호환 범위를 축소하지 않았다.
4. **Windows 보안 검증:** 한글 2020·PDF/이미지 파서·보안 DLL·WebView2를 포함한 실기기 및 의존성 검사가 필요하다. 저장소에 DLL 구현 소스가 없으므로 바이너리 내부 안전성은 판단하지 않았다.
5. **재현 가능한 빌드:** Python requirements는 버전·hash 고정이 없다. 검증된 Windows dependency lock과 바이너리 서명, 공급망 검증이 필요하다. 현재 Linux 9패키지 감사 결과를 Windows 전체 결과로 확대하지 않는다.
6. **진단 정보 보호:** 문서 경로·내용 일부가 기존 진단 로그나 외부 엔진 오류에 포함될 수 있다. 로그 파일 생성은 기본 꺼짐이지만 사용자가 활성화한 로그·보고서의 보관·공유와 민감 내용 마스킹을 별도로 점검해야 한다.
7. **예외 처리:** COM 실패·취소·저장 오류가 조용히 삼켜지는 경로를 단계별로 측정·구조화한다. 실제 실패 재현 없이 모든 except를 일괄 제거하면 복구 경로를 손상시킬 수 있다.
8. **최적화:** 소스 2만 줄 이상 본체를 한 번에 분할하지 않고 상태·서비스·저장·COM 경계를 단계별로 분리한다. 캐시는 문서·설정 revision을 기준으로 무효화하고 실제 코퍼스·COM 호출 횟수로 효과를 확인한다.

## 개선 효과와 성능 근거

Beta 1의 동일 clean_pasted_text/outline_pasted_text 함수를 임시 소스 사본에서 실행해 비교했다. 이스케이프된 Gemini 굵은 표시와 HTML 공백 엔티티 표본에서 Beta 1은 **와 &#x20;를 남겼지만 Alpha 6은 제거했다. 버전 1.74와 소수 3.14, 직함·이름 문구는 보존됐다. 해당 비교는 세 표본이며 모든 AI 답변 형태를 보증하지 않는다.

현재 AI 변환 벤치마크 6표본에서는 분기 기대값 일치, 검사한 Markdown 잔여 토큰 없음. 코드 내부의 의미 있는 기호 보존과 모든 표 구조는 회귀 시험 결과를 함께 봐야 한다.

| 동일 정리 함수, 100배 반복 입력 | Beta 1 중앙값 | Alpha 6 중앙값 |
|---|---:|---:|
| Gemini escape, 5,099자 | 3.324ms | 4.903ms |
| 버전·소수, 3,599자 | 2.521ms | 3.569ms |
| 담당자 문구, 4,999자 | 2.440ms | 4.146ms |

11회 중앙값이며 클라우드 회귀 검사와 함께 실행한 소표본이다. 증가한 정규화·보존 검사 비용이 있으므로 처리 속도가 향상됐다고 주장하지 않는다. 절대 시간은 수 ms지만 대량 입력·COM 처리·실제 사용자 체감은 별도 측정이 필요하다. 새 네이티브 백엔드가 Tk/WebView2를 import하지 않는 효과와 설정 화면의 Tk 의존성 감소는 구조 및 실제 프로세스 시험으로 확인했다.

기계 판독 근거는 validation/ALPHA6_* JSON 파일에 보관한다. 소스 보안 요약은 첫 전체 스캔 기준이며 후속 수정 파일도 별도로 정적·회귀 검사했다.
