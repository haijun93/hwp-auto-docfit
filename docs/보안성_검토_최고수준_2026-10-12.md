# 보안성 검토 — 최고 수준 기준 (2026-10-12)

범위: ① 소개 사이트(`website/`, Vercel 배포 가정) ② 앱 본체(Python/Flutter·WebView2/Tk) ③ 자동 업데이트 ④ 외부 엔진(kordoc/Node) ⑤ 빌드·배포 파이프라인.
방법: 코드 정독과 검색(실행 시험 없음). 한/글·Windows·Vercel 실환경에서 확인하지 못한 것은 "미확인"으로 표시.

## 1. 이미 갖춘 것 (확인함)
- `shell=True`·`os.system`·`eval`/`exec`·`pickle` 없음. 외부 프로그램 호출은 인자 목록 방식(`subprocess` 5곳)뿐.
- XML은 `defusedxml`만 사용(표준 `xml.*` 가져오기 없음) → XXE·엔티티 폭탄 방어.
- 업데이트: 호스트 허용 목록 + HTTPS 전용 + 리디렉션마다 재검증, 인증서 검증 끄기 없음, 크기·MZ 머리·SHA-256 확인, **해시가 없으면 설치 중단(fail-closed)**, 교체 직전 해시 재확인(검증-사용 사이 바꿔치기 방지), 실패 시 구버전 복구.
- HWPX 압축 해제 방어(`docfit_core/hwpx.py`): 파일 크기·압축률(1000배)·합계 상한. `extractall` 사용 없음(경로 탈출 경로 없음).
- WebView2 브리지: `_BrowserApi`는 명령만 노출, 설정·도구는 허용 목록(`QUICK_OPTIONS`, `run_tool`), 결과 파일은 앱 내부 목록의 번호로만 접근, 프런트엔드(`app.js`)에 `innerHTML` 0건.
- 작업 로그·검수 JSON 기본 꺼짐(개인정보 잔존 최소화).

## 3. 소개 사이트(Vercel) — 최고 수준 설정
앞선 보고서(`docs/Vercel_보안_검토_2026-10-12.md`)의 초안에 더해 다음을 적용한다.
1. **인라인 스타일 제거**(`cardnews.html`의 `<style>`, `index.html`의 `style=` 14곳 → CSS 파일) 후 CSP에서 `'unsafe-inline'` 삭제. Google Fonts는 글꼴 파일을 **자체 호스팅**해 외부 도메인을 없애면 `default-src 'self'`로 닫을 수 있다(개인정보·가용성에도 유리).
2. 헤더 추가: `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`(자체 호스팅 후), `X-Permitted-Cross-Domain-Policies: none`, `Cache-Control`은 HTML `no-cache`·정적 자원 `immutable`.
3. 외부 링크 `target="_blank"` 중 `index.html`의 `rel="noreferrer"`는 `noopener`를 함께 의미하므로 충족. 카드뉴스는 `noopener noreferrer` 충족.
4. 대시보드: 2단계 인증(모든 팀원), **Deployment Protection**(Preview 인증), Production Branch 보호, 환경 변수 비밀값은 사용하지 않음, Firewall 사용자 규칙(속도 제한)과 Attack Challenge Mode는 폭주 시, Spend Management 상한, 감사 로그(Audit Log) 확인, Git 연동은 해당 저장소만 허용.
5. `security.txt`(`/.well-known/security.txt`)로 신고 창구 공개.
6. HSTS preload는 사용자 도메인을 확정한 뒤.
