# 표·문서 서식 학습과 범정부오피스 호환 입력

작성: 2026-10-15. 대상: alpha. 배포판(main) 변경 없음.

## 1. 학습 목표와 방식

목표는 예시의 문장을 암기하는 것이 아니라, **같은 역할의 요소에 같은 서식을 재현**하는 것이다.
현재 규모의 기관별 예시에서는 모델 미세조정보다 원본 HWPX의 실제 속성을 추출하고,
역할이 확인된 유사 예시를 검색해 기존 서식 복사 엔진으로 적용하는 방식부터 검증한다.
이 방식이 가장 효과적이라는 실험 결과를 얻은 상태는 아니다. 아래 비교 평가로 확인할 설계다.

학습 단위는 문서 전체, 역할별 블록, 표, 셀, 문단, 글자 구간이다.
문서 전체의 최빈 글꼴 하나로 결재란·제목·일반 표를 덮지 않는다.
원본 XML이 서식의 근거이며, 미리보기 PNG는 시각 검수용이다.

| 단계 | 자료 및 처리 | 통과 조건 |
|---|---|---|
| 수집 | 원본 사본과 SHA-256, 기관·문서 유형·출처 | 원본 수정 0건, HWPX ZIP/XML 검사 |
| 분해 | 구역·표 순번·중첩 관계, 글자·문단·테두리·글꼴 실제 정의 | 원본으로 역추적 가능 |
| 역할 검토 | 제목/결재/개요/참고/중제목/데이터/조직도/흐름도 | 미확인 표는 자동 적용 제외 |
| 유형화 | 텍스트·문서 내부 ID 제외, 병합·테두리·배경·글꼴·여백·열 폭 비율 비교 | 내용만 다른 동일 서식 묶기 |
| 대표 선정 | 문서별 1표 투표, 기관·문서 역할별 분리 | 한 문서의 반복 표가 과대 대표되지 않음 |
| 적용 후보 | 승인된 데이터 표만 기존 learn_from_table로 프로필 추출 | 원본 해시·후보 일치 재검사 |
| 평가 | 미사용 기관/문서, 기존 기본값·단일 예시 복사·역할별 검색 비교 | 내용/구조 보존 및 실제 한/글 조판 검수 |

데이터 표는 머리글/본문/마지막 행 × 첫 열/중간 열/마지막 열의 역할별로 배운다.
조직도·흐름도·제목·결재란은 칸 크기와 병합 자체가 뜻을 가지므로 별도 템플릿으로 보관한다.
이들에 일반 데이터 표 서식을 적용하지 않는다. 중첩표도 바깥 표와 독립된 일반 표로 자동 채택하지 않는다.

## 2. 이번에 구현한 범위

`docfit_core/style_learning.py`:

- HWPX를 읽기 전용으로 검사하고 모든 표의 원본 해시·구역·순번·중첩·후보 역할을 수집한다.
- 문서마다 다른 borderFill/charPr/paraPr/font ID를 실제 정의로 치환한다.
- 글자 내용과 행 높이는 유형 비교에서 제외하고 연속된 동일 행은 한 번만 비교한다.
  열 폭 비율은 소수 셋째 자리까지 보존한다. 실제 서식이 다르면 보수적으로 별도 유형이다.
- 원문은 목록에 복사하지 않고 내용 해시만 남긴다. 문서의 서식 정의는 보존한다.
- 같은 표 유형을 공유하는 문서는 연결된 한 그룹으로 묶어 train/validation/test 경계를 넘지 않게 한다.
  한 문서에 여러 유형이 있으면 그 유형들도 같은 평가군으로 연결된다.
- 분할은 그룹 해시로 결정한다(기대 비율 80/10/10). 표본이 적으면 비율을 강제하지 않는다.
  전체 자료가 하나의 큰 연결 그룹이면 독립 평가 불가를 경고한다. 이 경우 새로운 기관 원본을 확보한다.
- 모든 후보는 `unreviewed`, `eligible=false`로 시작한다.
  사람이 `data`로 승인한 격자 표 하나만 실제 `table_style` 프로필로 추출할 수 있다.
  출처가 달라지면 재검토한다. 사용자 설정을 자동 변경하지 않는다.

사용 예(저장소의 `.venv\Scripts\python.exe` 사용):

```powershell
python scripts/learn_style_corpus.py index "C:\자료\기관별 HWPX 문서" --organization "기관 미분류" --output "C:\자료\학습목록.json"
python scripts/learn_style_corpus.py learn-table "C:\자료\기관별 HWPX 문서\예시.hwpx" --catalog "C:\자료\학습목록.json" --candidate "목록의 표 id" --approve-role data --output "C:\자료\승인된표서식.json"
```

추출한 `table_style`은 기존 `table_style.learn_from_table`과 같은 구조다.
후속 서식 관리 화면에서는 승인된 프로필을 선택해 적용하도록 연결한다.
이번 구현에 자동 검색 UI, 신경망 학습, 문서 전체 서식 자동 승인 기능은 포함하지 않았다.

## 3. 평가 설계

비교 대상 A는 기존 기본 서식, B는 기존 단일 예시 복사, C는 기관·역할·표 유형을 제한한 검색이다.
같은 원본 사본에 A/B/C를 적용해 문서별로 비교한다. 같은 표를 여러 번 세지 않고 기관·유형별 평균을 먼저 낸다.
학습에 쓴 문서의 추출 표나 모음 문서를 평가에 재사용하지 않는다.

필수 보존 지표는 글자/숫자/날짜, 행·열·병합, 도형·이미지, 그림 표의 칸 크기다.
각 지표의 훼손 0건을 먼저 확인한 뒤, 역할별 서식 일치율과 처리 시간을 비교한다.
시각 평가는 한/글이 다시 조판한 페이지로 수행한다. 원본 미리보기 캐시는 평가 근거가 아니다.
기존 `fidelity`, `style_inventory`, 최종검수 기능의 구조·내용 검사와 함께 사용한다.

검색은 기관과 역할로 후보를 줄이고, 같은 유형의 승인 예시를 먼저 찾는다.
정확한 후보가 없거나 1·2위가 비슷하면 적용을 유보하고 후보·근거를 보여준다.
분류 정확도뿐 아니라 **잘못된 역할에 적용한 비율**과 **유보율**을 함께 기록한다.
미세조정은 독립 평가 자료가 충분하고 검색 방식의 한계를 수치로 확인한 뒤 검토한다.

## 4. 범정부오피스 마크다운 관찰과 독립 구현

벤치마크 자료는 사용자가 제공한 `범피스 1125.exe`의 내장 `마크다운설명서.hwp`와
앱을 통해 생성한 문서다. 실행 파일 SHA-256:
`d23c67fea656c5731ae56ff9a091bef66d6d0ded4891f41f8ec07c820c378949`.
외부 앱의 함수·실행 코드·문서 파일을 저장소에 옮기지 않고, 관찰한 입력과 출력 규칙만 독립 구현했다.
테스트 문장은 자체 작성했다.

| 관찰된 입력 | hwp-auto-docfit 처리 |
|---|---|
| 네모/사각형, 원/동그라미, 바 | 기존 □ / ㅇ / - 계층 |
| 당구/당구장, 주석/주석1, 주석2 | 기존 ※ / * / ** |
| 상단박스, 참고 | 실제 개요·참고 표 |
| 소제목, 숫자소제목/소제목숫자 | 호환 모드에서 1·2·3 번호 칸 + 제목 칸의 실제 표 |
| 로마소제목/소제목로마 | 호환 모드에서 Ⅰ·Ⅱ·Ⅲ 번호 칸 + 제목 칸의 실제 표 |
| 연속된 `표 : 셀 : 셀 : 셀` | 연속 행을 한 표로 생성. 빈 셀과 모든 열 보존 |

기존 입력에서 `소제목:`은 □였으므로 기본 동작은 유지했다.
첫 줄에 `#!범정부오피스`를 붙이면 붙여넣기·TXT·MD 변환에서 호환 문법을 선택한다.
파이썬 API는 `parse_labeled_text(text, dialect="beomgov")`다.
서로 다른 숫자/로마자 카운터는 문서마다 초기화한다. 소제목 표와 다음 데이터 표를 합치지 않는다.
코드 울타리 안의 라벨은 실행할 문법으로 해석하지 않는다.

콜론 표의 열 구분은 콜론 앞이나 뒤에 공백을 둔다. `14:00`, `https://...`는 그대로 보존한다.
셀 안의 공백 붙은 콜론은 `\:`로 적는다. 파이프/탭 구분도 기존대로 사용할 수 있다.
내장 설명서의 열 초과 예시는 내용을 버리는 동작이지만, 이 앱에서는 버리지 않고 넓은 행에 맞춰 빈 셀을 채운다.
기관별 픽셀 단위 외형 복제는 호환 파서의 역할이 아니며, 선택한 서식 프로필과 기존 서식 적용 단계에서 처리한다.
호환 라벨 입력은 Markdown 이미지 임베딩 문법을 추가로 구현하지 않는다.

명시적 라벨 MD는 일반 Markdown 엔진보다 먼저 처리한다.
새 HWPX를 직접 생성하는 명령도 제공한다(한/글 COM 필요, 기존 출력 덮어쓰기 금지):

```powershell
python scripts/beomgov_markdown.py tests/fixtures/beomgov_markdown.txt "C:\자료\범정부호환예시.hwpx"
```

## 5. 검증 기록

자동 시험은 ID 재번호, 글꼴/테두리/병합/열 폭 구별, 반복 행 통합, 원문 비노출,
문서 간 평가 누수 방지, 승인 전 적용 차단, 원본 변경 감지, 코드 울타리, 빈 셀·URL·시각 보존,
소제목 표·데이터 표 분리, 기존 라벨 회귀, MD 변환 경로를 포함한다.
실제 기관 예시를 이용한 수치는 로컬 자료로만 기록하고, 저장소에는 사용자 원문을 올리지 않는다.

2026-10-15 PC 검증:

- 내장 문서 22개: 표 126개, 서식 유형 94개, 문서 연결 평가군 19개.
  문서 수 기준 train 17 / validation 1 / test 4. 이는 자료 분할 결과이며 모델 정확도 수치가 아니다.
- 독립 작성 호환 예시: 실제 한/글 COM으로 HWPX 생성·재열기·재저장.
  제목/개요/참고/번호 소제목/데이터 표 합계 7개를 확인했다.
  데이터 표는 3행 4열이며 빈 셀·금액·시각·URL을 보존했다.
  번호 칸이 제목 칸보다 좁고 XML 후처리용 표식이 남지 않음을 검사했다.
- 전체 회귀시험 1,188개 통과(조건부 제외 1개). 외부 앱의 모든 생성 서식을 시험한 결과는 아니다.
