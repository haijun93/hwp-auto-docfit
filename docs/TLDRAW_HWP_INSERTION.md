# tldraw PNG의 HWP/HWPX 삽입 후속 설계

## 현재 상태

PNG 파일로 내보내는 단계까지만 구현했다. 한/글 COM 그림 삽입, 문서 내 개체 식별/교체, 재편집 연결은 아직 미구현이며 한/글 2020이 있는 Windows PC에서 검증하지 않았다. `HWP` 바이너리와 `HWPX` 압축/XML 경로를 임의로 직접 수정하지 않는다.

## 검증 순서

1. 사용자 문서가 아닌 사본 테스트 파일을 준비하고 삽입 전 SHA-256을 기록한다.
2. 한/글 COM에서 PNG를 새 그림 개체로 삽입할 수 있는 최소 명령과 투명도·크기·문단 배치·페이지 분할 동작을 확인한다.
3. 커서 위치·책갈피·지정 문단 뒤 가운데 하나의 위치 선택 방식을 별도 시험한다. 안정적으로 확인되지 않은 방법은 UI에 노출하지 않는다.
4. 결과 파일을 원본 옆 새 이름으로 저장하고 닫았다 다시 연다. 그림 존재·크기·위치·문서 열기·원본 해시를 검사한다.
5. 실패한 작업은 성공으로 표시하지 않고 임시 결과만 정리한다. 원본은 덮어쓰지 않는다.

## 후속 서비스 계약

`hwp_insert_service.py`는 독립적으로 다음을 입력받도록 설계한다: canonical PNG path, 원본 문서 사본 경로, 검증된 삽입 지점, 너비·비율·정렬. 입력 이미지는 PNG 시그니처와 디코더 크기 제한을 확인하고 SHA-256을 기록한다. 저장 후 재열기 검수, 결과 파일 경로, 적용된 개체 위치 및 오류코드를 반환한다. COM은 기존 STA 실행 규칙에 따라 단일 소유 worker에서 직렬 처리해야 한다.

재편집·교체는 그림을 경로 문자열로 찾지 않는다. 문서 저장 형식에 따른 개체 식별자가 COM으로 안정적으로 보장되는지 먼저 시험한다. 보장이 없으면 자동 교체를 구현하지 않고 사용자 확인 후 새 삽입만 제공한다. 원본 tldraw JSON과 PNG 해시는 AppData metadata에 매핑하되 HWP 파일 안에 민감 경로를 넣지 않는다.

## 완료 게이트

실제 Windows + 한/글 2020 테스트(최소 HWP 2종, HWPX 2종, 세로/가로, 기존 그림 포함), 원본 SHA 보존, 결과 재열기, COM timeout·취소·저장실패 복구, 문서 내용/쪽수 변화 안내가 통과하기 전에는 기능 완성 또는 배포 가능으로 표시하지 않는다.
