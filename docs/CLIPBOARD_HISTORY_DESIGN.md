# K클립보드 설계서 — 클립보드·화면캡처 보관함 (2026-10-31)

**기능 이름: "K클립보드"**(사용자 결정 2026-10-31). 설계 원칙: **복사된 내용은 로컬 컴퓨터 자원(CPU·메모리·디스크·입출력)을 최소한으로 쓰도록 설계한다** — §3·§12 참고.

사용자 요청: **K클립보드는 Windows에서 Ctrl+C로 복사하는 모든 것(텍스트·파일·폴더 등)**을 기록해 **사용자가 정한 개수까지 보관**하고, 언제든 골라 **다시 복사·붙여넣기** 할 수 있게 한다. **화면 캡처로 만든 모든 것도 같은 방식**으로 보관·재사용한다.
이 문서는 설계이며 구현·시험 결과가 아니다. 이 환경(리눅스 클라우드)에서는 Windows 클립보드를 실행해 보지 못했고, 아래 Windows API 설명은 일반 지식이므로 구현 전에 PC에서 확인한다. 저장소에는 아직 클립보드 감시·전역 단축키·트레이 코드가 없다(`docfit_app/clipboard_service.py`는 앱이 결과를 **쓰는** 쪽만 있음).

## 0. 먼저 알아 둘 것 — 이 기능의 성격과 위험

1. **기록 대상이 비밀번호·개인정보·업무 문서 내용일 수 있다.** 클립보드 기록기는 키 입력 기록기와 비슷한 감수성을 갖는다. 공공기관 PC는 보안 정책으로 이런 프로그램을 금지할 수 있다. → **기본값 꺼짐(켜기 전에는 아무것도 기록하지 않음), 처음 켤 때 위험·보관 위치 고지와 동의, 외부 전송 없음(오프라인), 보관 데이터 암호화, 앱 종료·화면 잠금 때 자동 삭제 옵션, 언제든 "모두 지우기".** 기관 보안 담당 검토 대상이다(보안 TODO S 항목과 같은 수준으로 취급).
2. **Windows에 이미 "클립보드 기록"(Win+V)이 있다**: 최근 25개, 텍스트·HTML·이미지(약 4MB 이하), 파일·폴더 항목은 없음, 재부팅하면 고정한 것만 남음. 우리 기능은 **파일·폴더 목록 보관, 개수 직접 지정, 재시작 뒤에도 유지, 화면 캡처 파일 통합, 검색·고정, HWP 작업과 연동**이 차별점이다. 설정 첫 화면에서 이 차이를 안내하고 기관이 Win+V만 허용하면 이 기능을 쓰지 않도록 한다.
3. **우리 앱이 닫혀 있으면 기록이 안 된다**(앱 안 구현 시). "언제든" 기록하려면 **백그라운드 상주**가 필요하다(§3).

## 1. 기능 정의

### 1.1 클립보드 기록
- 감시 대상: 사용자가 복사/잘라내기 한 **모든 클립보드 변경**(Ctrl+C·Ctrl+X·마우스 우클릭 복사·프로그램의 복사 버튼).
- 종류별 보관: **텍스트**(유니코드), **서식 있는 텍스트**(HTML·RTF — 한/글·워드·웹 복사), **이미지**(비트맵·PNG), **파일·폴더**(목록), **앱 고유 형식**(한/글 표·개체 등 — 가능하면 원형 그대로).
- 항목마다: 시각, 종류, 미리보기(텍스트 앞 200자·이미지 썸네일·파일 이름 목록), 크기, 복사한 프로그램(프로세스 이름 — 창 제목은 민감해 기본 저장 안 함), 고정 여부, 즐겨찾기.
- **보관 개수는 사용자 지정**(기본 50, 범위 10~1,000) + 총 용량 상한(기본 500MB) + 항목당 상한(기본 20MB) + 보관 기간(기본 무제한/7일/30일). 넘으면 **가장 오래된 비고정 항목부터 자동 삭제**(고정 항목은 보호, 고정이 개수 상한을 넘기지 않게 별도 상한).
- 같은 내용 연속 복사는 **중복 제거**(내용 해시가 직전 항목과 같으면 시각만 갱신), 비연속 중복은 옵션.

### 1.2 다시 쓰기(재복사·붙여넣기)
- 목록에서 항목을 고르면 **클립보드에 원래 형식 그대로 다시 올린다** → 사용자가 대상 프로그램에서 **Ctrl+V**.
- 단축키 팝업(§4)에서는 선택 즉시 **자동 붙여넣기**(이전 창으로 포커스를 돌려 Ctrl+V 입력 합성) 선택 가능.
- **일반 텍스트로 붙이기**(서식 제거), **여러 항목 이어 붙이기**(선택한 텍스트 항목을 구분자로 합쳐 한 번에), 이미지 항목 **파일로 저장**, 파일 항목 **경로 복사**.
- 파일·폴더 항목은 **경로 목록만 보관**하고 복사본을 만들지 않는다(기본). 붙여넣기 때 원본이 없으면 "원본 파일이 없어요" 표시(항목은 유지). 선택 옵션: "작은 파일은 복사본도 보관"(상한 이하)은 2차.
- **잘라내기(Cut) 표시**: 파일 항목은 `Preferred DropEffect`(복사/이동)를 함께 보관해 재현하되, 이동(잘라내기)으로 복원하면 위험하므로 **복사로만 복원**(사용자 선택).

### 1.3 화면 캡처 보관
요청은 "화면 캡처하는 **모든 것**도 같은 방식". 캡처 방식별로 흔적이 다르므로 경로를 나눠 모두 한 보관함에 모은다.

| 캡처 방식 | 결과가 남는 곳 | 포착 방법 |
|---|---|---|
| PrtScn, Alt+PrtScn | **클립보드 이미지** | 클립보드 감시로 자동 포착(§2). 이미지 항목에 `capture` 표시(직전 PrtScn 키 입력 아님 — 키 후킹 불필요; 이미지 단독 + 파일 아님이면 캡처 후보로 표시) |
| Win+Shift+S(캡처 도구), 캡처 도구 앱 | 클립보드 이미지(+알림 → 파일 저장은 사용자가 누를 때만) | 클립보드 감시. 포그라운드/소스 프로세스가 캡처 도구(`ScreenClippingHost`·`SnippingTool`)면 `capture` 태그 |
| **Win+PrtScn** | **파일**(`사진\스크린샷` 폴더, 클립보드에는 안 올림) | **폴더 감시**(`ReadDirectoryChangesW`/`watchdog`) — 기본 감시 폴더 `%USERPROFILE%\Pictures\Screenshots` |
| 서드파티 캡처(알캡처·Greenshot 등) | 클립보드 또는 사용자가 정한 저장 폴더 | 클립보드 감시 + **사용자가 감시 폴더 추가** |
| 우리 앱 **자체 캡처**(2차) | 보관함에 직접 저장 + 클립보드 | 전역 단축키로 영역/창/전체 화면 캡처(§6) |

- 캡처 항목은 같은 목록에서 **종류 필터 "캡처"**로 모아 보고, 썸네일 큰 미리보기, 재복사(이미지 형식 PNG+DIB 둘 다 올림), 파일 저장, 한/글 그림판·표그림판 배경으로 보내기(앱 연동 — 기존 `sketch_image_input` 경로) 가능.
- 폴더 감시로 들어온 파일은 **원본 파일을 옮기거나 지우지 않고** 경로+썸네일만 보관한다(파일 항목과 같은 방식) — 단 "캡처 복사본 보관" 옵션(기본 켬 — 이미지는 복사본 PNG로 저장해 원본이 지워져도 남김).

## 2. Windows 클립보드 감시 방식

**감시**: 숨은 메시지 전용 창(`HWND_MESSAGE`)을 만들고 `AddClipboardFormatListener`로 등록 → `WM_CLIPBOARDUPDATE` 수신. (폴링보다 정확하고 가볍다. `GetClipboardSequenceNumber`는 보조 검증으로 사용.) 구현은 `pywin32`(`win32gui`·`win32clipboard`, 이미 의존성) 또는 `ctypes`.
**읽기**: 메시지를 받으면 즉시 클립보드를 열고(`OpenClipboard`, 실패 시 짧게 재시도 — 다른 프로그램이 점유 중일 수 있음) **존재하는 형식 목록을 열거**(`EnumClipboardFormats`)해 아래를 읽는다.
- 텍스트 `CF_UNICODETEXT`(13), HTML(`HTML Format`), RTF(`Rich Text Format`), 비트맵 `CF_DIB`/`CF_DIBV5`(8/17)와 `PNG`, 파일 `CF_HDROP`(15), `Preferred DropEffect`, 셸 목록 `Shell IDList Array`(폴더·가상 항목), 앱 고유 등록 형식(한/글 등).
- **지연 렌더링(delayed rendering) 형식**은 읽는 순간 원 프로그램이 데이터를 만들어야 하고 프로그램이 이미 닫혔으면 실패할 수 있다. 큰 데이터를 느리게 만드는 프로그램이 있으므로 **형식별 읽기 시간 제한**을 두고(초과 시 건너뜀), `FileGroupDescriptorW`/`FileContents`(Outlook 첨부·ZIP 안 파일 같은 **가상 파일**)는 1차에서 **보관하지 않고** "가상 파일은 보관할 수 없어요"로 표시(2차에 `IDataObject`로 임시 폴더에 복사).
- **프라이버시 신호 존중(필수)**: 다음 형식·조건이 보이면 **기록하지 않는다** — `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory`=0, `CanUploadToCloudClipboard`=0(암호 관리자·Windows 자체가 쓰는 표시), `Clipboard Viewer Ignore`. 사용자 지정 **제외 프로그램 목록**(프로세스 이름), **제외 패턴**(정규식 — 주민등록번호 `\d{6}-?[1-4]\d{6}`·카드번호·`password` 포함 등, 일치하면 항목을 만들지 않거나 마스킹 저장 선택), **원격 데스크톱·가상 머신 창**에서 온 복사 제외 옵션.
- **자기 쓰기 무시**: 우리가 보관함에서 되돌려 올릴 때 자체 등록 형식(`HwpAutoDocFit.ClipboardRestore`)을 함께 넣어, 감시가 그것을 **새 항목으로 다시 기록하지 않게** 한다(시퀀스 번호도 기억).
- **저장 전 가벼운 처리**: 큰 데이터는 별도 스레드에서 압축·해시, 메시지 처리 스레드는 읽기만 하고 즉시 반환(클립보드 점유 시간 최소화 — 다른 프로그램을 방해하지 않기).

## 3. 상주 방식(결정 필요)

| 안 | 내용 | 장단점 |
|---|---|---|
| **A. 앱 안(1차 제안)** | 메인 앱 프로세스의 백엔드가 감시. 앱을 트레이로 최소화해 두면 계속 기록 | 구현 단순, 앱이 켜져 있어야 함 |
| B. 별도 **에이전트 프로세스**(`clipboard_agent.exe`, 로그인 시 자동 시작 옵션) | 앱이 닫혀도 기록, 보관함 DB를 앱과 공유 | "언제든 기록" 충족. 새 실행 파일·자동 시작·권한·백신 오탐·**기관 보안 정책 위험이 큼**, 설치형 배포 변경 필요 |
- **(자원 최소화 반영 — 갱신)**: 앱의 화면(WebView2·Flutter)은 켜 두면 수백 MB를 쓰므로 **감시를 화면과 분리**한다. 1차 제안: **같은 exe를 `--kclip` 인수로 실행하는 "감시 전용 모드"**(WebView·Flutter·한/글 COM·Node·OCR 런타임을 **전혀 불러오지 않는** 가벼운 파이썬 프로세스 — 새 exe·새 설치 없이 A와 B의 장점) + 관리 화면·팝업이 필요할 때만 메인 앱 화면을 연다. 감시 코어는 어느 쪽이든 같은 모듈이다(Core ↔ 인프라 분리). 앱 안 감시(A)는 메인 앱이 이미 떠 있을 때의 같은 코드 경로로 지원.
- 트레이 아이콘·전역 단축키는 저장소에 아직 없다(`Shell_NotifyIcon`·`RegisterHotKey` 새 구현; pywin32 또는 `pystray` — 의존성 추가는 라이선스·보안 확인 후).

## 4. 화면(UI)

1. **탭 "클립보드"**(9번째) 대신 우선 검토: **전역 단축키 팝업 + 설정 화면**. 이미 탭이 8개(파일이름 신설 시)라 탭줄이 넘치는 문제(P6)가 있어, 관리 화면은 **설정 서랍의 "클립보드 보관함" 항목 또는 기존 도구함 안**에 두고, 자주 쓰는 동작은 팝업으로 한다. (사용자 결정 필요: 탭 신설 vs 팝업+설정)
2. **관리 화면(앱 안)**: 목록(최신순, 종류 아이콘·미리보기·시각·크기·출처 프로그램), 검색(텍스트·파일 이름), 필터(전체·텍스트·이미지·파일·캡처·고정), 고정/즐겨찾기, 삭제·전체 삭제, 선택 → [다시 복사] [일반 텍스트로 복사] [파일로 저장] [여러 개 합치기], 보관 개수·용량 표시와 설정(§5).
3. **빠른 팝업(전역 단축키)**: 기본 **Ctrl+Shift+V**(설정 변경 가능; **Win+V는 Windows 예약이라 사용 불가**), 화면 가운데 작은 목록, 방향키/숫자 키로 선택, Enter = 클립보드에 올리고(+자동 붙여넣기 옵션) 닫기, Esc = 닫기. **포커스를 빼앗지 않게**(`WS_EX_NOACTIVATE`) 만드는 것이 기술 위험 — 웹뷰(WebView2) 창은 이 속성을 주기 어렵다. 1차는 앱 창이 앞으로 나오는 방식으로 하고 자동 붙여넣기는 "이전 활성 창 복귀 후 Ctrl+V"로 구현, 2차에 네이티브 소형 창을 검토.
4. 상태 표시: 기록 중/일시정지 표시(트레이 아이콘·앱 상단), **일시정지(10분·1시간·끌 때까지)**, 마지막 기록 시각. 기록 중에는 항상 보이는 표시를 둔다(몰래 기록 방지).

## 5. 설정 항목

보관 개수(10~1,000, 기본 50) · 총 용량·항목 상한 · 보관 기간 · 기록할 종류(텍스트·서식·이미지·파일·캡처) · 제외 프로그램 · 제외 패턴/마스킹 · 앱 종료 시/화면 잠금 시 삭제 · 재시작 후 유지 여부(기본 유지) · 단축키 · 자동 붙여넣기 · 캡처 감시 폴더(기본 `사진\스크린샷`) · 캡처 복사본 보관 · 저장 위치(기본 `%APPDATA%\HwpAutoDocFit\clipboard\`) · **보관 데이터 암호화**(기본 켬) · 일시정지 · 모두 지우기. 설정 저장은 기존 `settings_schema`/`config_store`·백업·복원과 같은 방식.

## 6. 자체 화면 캡처 (3~4단계)

외부 캡처 도구에 의존하지 않고 앱에서 직접 캡처: 전역 단축키로 **영역 선택·활성 창·전체 화면·지연 캡처**, 다중 모니터·DPI(고배율) 처리, 결과를 보관함에 저장하고 클립보드에 올림. 구현 후보: `PIL.ImageGrab.grab(all_screens=True)`(간단, DPI 인식 설정 필요), Windows Graphics Capture(고급). 영역 선택 화면은 전체 화면 반투명 오버레이 창이 필요해 네이티브 창 구현 부담이 크다 → **1차(캡처 보관)와 분리해 후순위**. 캡처 파일 자동 저장 옵션은 기본 꺼짐(파일이 남는 것을 사용자가 선택).

## 7. 저장소와 보안

- 저장: **SQLite(표준 라이브러리 `sqlite3`)** `history.db`(메타·미리보기·해시·형식 목록) + **blob 폴더**(큰 텍스트·이미지·형식별 원본). 트랜잭션·인덱스·검색(텍스트 `LIKE`/FTS5 가능하면)·원자적 삭제. 손상 시 안전하게 새 DB 시작(백업본 1개 유지).
- **암호화**: 항목 payload를 **Windows DPAPI**(`win32crypt.CryptProtectData`, 현재 사용자 계정에만 풀림)로 암호화해 저장 — 다른 사용자·다른 PC에서 DB를 열어도 내용이 보이지 않는다(미리보기 텍스트도 암호화 필드). 키 관리가 필요 없고 의존성 추가 없음(pywin32). 한계: 같은 로그온 계정의 악성코드는 읽을 수 있다 → 보안 문서에 명시.
- **오프라인·외부 전송 없음**, 로그에 복사 내용 기록 금지(항목 개수·종류만), 크래시 보고에 내용 포함 금지.
- 삭제는 **안전 삭제**(DB 행 + blob 파일 삭제 후 VACUUM/덮어쓰기 옵션).
- 파일·폴더 항목은 경로만(복사본 없음) → 경로 자체가 개인정보일 수 있음. 경로 검증(복원 시 `..`·UNC·존재 확인)은 기존 파일 선택 규칙과 같게.
- 앞선 보안 검토(S 항목)·OSS 스캐너·기관 보안성 검토 대상에 새 모듈(`clipboard` 감시·DPAPI·전역 단축키)을 추가.

## 11-1. 감시 프로세스 공유 — 타임머신(2026-11-01 사용자 결정)

K클립보드의 **감시 전용 프로세스(`--kclip`)는 "타임머신"(작업 문서 타임라인)의 조사 폴더 파일 변경 알림도 함께 받는다.** 한 프로세스가 (1) 클립보드 변경 알림 (2) 스크린샷 폴더 감시 (3) 타임머신 조사 폴더의 파일 변경 알림(`ReadDirectoryChangesW`)을 모두 이벤트로 처리하고, 설정·일시정지·동의·자원 예산(§12)·자동 시작을 한 곳에서 관리한다. 두 기능의 저장소(SQLite)는 **별도 파일**로 두어 서로 독립이다. 에이전트가 허용되지 않은 환경에서는 K클립보드는 앱이 켜져 있을 때만 기록하고 타임머신은 앱을 열 때 증분 스캔한다. 설계 상세는 TODO.md의 "타임머신" 섹션.

## 12. 자원 최소화 설계 (K클립보드 핵심 요구)

원칙: **"아무 일도 없을 때는 거의 0, 복사가 일어날 때만 짧게 일하고, 보관량은 사용자가 정한 작은 상한 안에서만 쓴다."** 아래는 설계 수단과 **수치 목표**이며 실측으로 검증하기 전에는 목표일 뿐이다(측정 도구와 합격 기준은 §12.4).

### 12.1 CPU — 이벤트 구동, 폴링 금지
- 클립보드는 `WM_CLIPBOARDUPDATE` 메시지만 기다린다(메시지 루프가 블로킹 `GetMessage`에서 잠듦 — **유휴 CPU 0%**). `GetClipboardSequenceNumber` 주기 폴링 금지(검증용 1회성 호출만).
- 스크린샷 폴더는 `ReadDirectoryChangesW`(완료 포트/비동기) 이벤트로만 반응하고 **디렉터리 주기 스캔 금지**, 변경 알림은 **디바운스**(파일 쓰기가 끝날 때까지 300~500ms 합치기).
- 연달아 복사(예: 프로그램이 한 번에 여러 번 클립보드를 갱신)는 **150ms 디바운스**로 마지막 상태만 처리.
- 무거운 작업(해시·압축·썸네일)은 **메시지 스레드가 아닌 단일 작업자 스레드**에서, **낮은 우선순위**(`SetThreadPriority(BELOW_NORMAL)`, 프로세스 `EcoQoS`/`PROCESS_MODE_BACKGROUND_BEGIN` 가능하면)로 하고 **한 번에 한 항목씩 큐로 순차 처리**(동시 처리로 CPU 급등 방지).
- **지연 렌더링 형식은 읽지 않거나 시간 제한**(예: 형식당 500ms) — 원 프로그램이 큰 변환을 하게 만들어 PC를 느리게 하지 않는다. 자주 쓰는 형식만 저장하고 나머지는 열거만(§2 1차 형식 화이트리스트).
- 검색은 입력할 때만 실행, 색인(FTS)은 **기본 끔**(끄면 `LIKE` 검색 — 보관 수가 수백 개면 충분히 빠름). 필요할 때만 켜게 한다.

### 12.2 메모리 — 작은 상주 크기와 스트리밍
- **감시 전용 프로세스는 가볍게**: 시작 때 `pywin32`(`win32gui`·`win32clipboard`·`win32crypt`)와 `sqlite3`만 불러오고 `PIL`·`defusedxml`·Flutter·WebView·한/글 COM·Node는 **지연 import**(이미지 썸네일이 필요한 순간에만 `PIL` 로드, 끝나면 참조 해제). 목표: **상주 작업 집합(RSS) 40MB 이하**(파이썬 기본 크기 포함 — 실측 후 조정).
- **큰 데이터는 메모리에 오래 두지 않는다**: 클립보드에서 읽은 바이트를 곧바로 파일(blob)로 쓰고 변수 해제. 항목당 상한(기본 **10MB**, 설정으로 변경) 초과 시 **저장하지 않고 "너무 커서 건너뜀" 기록만**(메타 한 줄).
- 목록 화면은 **가상 스크롤 + 현재 보이는 항목만 불러오기**(미리보기·썸네일은 보이는 것만 로드, 화면을 벗어나면 해제). 이미지 원본은 선택·복원 때만 디스크에서 읽는다.
- 이미지는 **저장 시 무손실 압축(PNG optimize)·큰 이미지는 긴 변 상한 옵션**, 썸네일은 **작은 크기(긴 변 160px) JPEG 품질 70** 한 장만 만들어 DB/blob에 저장(원본 디코딩을 목록에서 반복하지 않음).
- 텍스트는 1KB 이상이면 `zlib`(표준 라이브러리) 압축 저장, 미리보기 200자는 평문 필드(암호화 시 별도 필드).

### 12.3 디스크·입출력
- 저장소 기본 상한: **총 200MB**(제안 — 앞 설계의 500MB에서 축소), 항목당 10MB, 개수 50. 상한은 설정으로 변경.
- **중복 제거를 쓰기 전에**: 해시(내용 SHA-256 앞부분 + 길이)가 이미 있으면 **쓰지 않고 시각만 갱신**. 같은 파일 목록·같은 텍스트·같은 이미지를 반복 복사해도 저장량이 늘지 않는다.
- SQLite는 **WAL 모드 + `synchronous=NORMAL`**, 작은 페이지 캐시(예: 2MB), **트랜잭션당 한 항목**(작은 쓰기), 삭제는 행+blob 파일 삭제 후 **`VACUUM`은 드물게·유휴 때·사용자가 요청할 때만**(주기 실행 금지). blob은 **항목당 파일 1개**(큰 DB 파일 확장·복사 방지) — 작은 텍스트(예: 2KB 미만)는 DB 필드에 직접.
- 한도 초과 정리(eviction)는 **쓰기 직후 한 번에 필요한 만큼만**(배치), 전체 스캔 없이 인덱스(생성 시각) 순서로.
- 파일·폴더 항목은 **경로 목록만**(복사본 없음 — 기본). 스크린샷 폴더 감시 항목도 **"캡처 복사본 보관"을 기본 끔**으로 바꾸는 안을 검토(원본이 남는 폴더이므로 경로+썸네일만 저장, 원본이 지워질 수 있다는 사실을 안내) — 디스크 사용 최소화 vs 보관 안정성은 사용자 선택.
- 파일 쓰기는 **임시 파일 → 원자적 이름 바꾸기**(손상 방지), 로그는 **내용 없는 카운터만**, 로그 크기 상한·회전.

### 12.4 시작·상주 비용
- 감시 전용 모드는 **로그인 후 자동 시작 옵션을 기본 끔**, 켜면 **지연 시작**(로그인 후 30~60초)으로 부팅 속도를 건드리지 않는다. 시작 시 DB는 **열기만** 하고 항목을 메모리에 올리지 않는다(개수·합계만 질의).
- 일시정지 중에는 **클립보드 리스너 등록을 해제**(`RemoveClipboardFormatListener`)해 메시지 처리도 0이 되게 한다.
- 전역 단축키(`RegisterHotKey`)는 OS가 대기하므로 상주 비용이 거의 없다. 팝업은 **눌렀을 때만** 메인 앱 화면을 열어 보여 준다(상시 로드 금지).
- 배터리·절전: 노트북 **배터리 절약 모드**에서는 썸네일 생성 지연·폴더 감시 디바운스 증가(옵션).

### 12.5 측정과 합격 기준 (자원 목표를 지키는지 확인)
- 시험 도구 `scripts/kclip_benchmark_pc.py`(Windows PC): 감시 전용 프로세스를 띄워 **유휴 10분 CPU 시간·작업 집합·핸들 수**, **복사 1,000회(텍스트 1KB·이미지 1MB·파일 100개 목록 혼합) 동안 CPU 시간·최대 메모리·디스크 쓰기 바이트**, **중복 복사 100회 쓰기량**, **eviction 반복 시 DB 크기 증가**를 기록. 같은 PC에서 K클립보드 켠/끈 상태의 **전체 시스템 CPU 사용률 차이**도 비교(앞서 앱 성능 측정과 같은 번갈아 측정 방식).
- 합격 기준(제안, 실측 후 조정): 유휴 CPU **0.1% 미만**, 상주 메모리 **40MB 이하**(감시 전용), 복사 1건 처리 **CPU 50ms 이하(텍스트)·200ms 이하(1MB 이미지)**, 메시지 스레드 점유 **10ms 이하**(클립보드를 연 시간 — 다른 프로그램 방해 방지), 디스크 상한 초과 **0건**, 장시간(24시간) 실행 뒤 메모리·핸들 **증가 없음**(누수 시험).
- 시험(리눅스 가능한 부분): 한도 eviction·중복 제거·압축 저장·지연 로딩을 **가짜 클립보드**로 돌려 메모리 사용(`tracemalloc`)·쓰기 횟수를 단언하는 단위 시험 — "큰 항목은 저장 안 함", "중복은 쓰기 0회", "목록 조회가 blob을 읽지 않음".
