# 파일이름 탭 설계서 — 파일 이름 일괄 변경 (2026-10-31)

사용자 결정: **탭을 새로 추가하는 방식**(기존 파일변환 탭에 합치지 않음). 벤치마킹 대상은 DarkNamer(`nanpuhaha/DarkNamer`, MIT) — 기능·화면 흐름만 참고하고 코드는 복사하지 않는다.
이 문서는 설계이며 구현·시험 결과가 아니다. 코드 위치는 `main` aad2b37(앱 버전 2.0.7) 기준으로 읽은 결과이고, Windows 실행·끌어놓기는 확인하지 못했다.

## 1. 목표와 사용 장면

사용자가 준 화면(첨부 이미지)처럼 **의미 없는 이름의 파일이 한꺼번에 있을 때**(`6C1D56A5-12B9-4F7D-9846-BA1255C43404.JPG` 같은 UUID 이름 사진 7장) 이름을 규칙으로 바꾼다.
- 예: 촬영일 + 번호 → `20261031_001.jpg`, `20261031_002.jpg` …
- 예: `현장사진_01.jpg`, `현장사진_02.jpg` … (자리수·시작값·스텝)
- 보고서 작업 파일: `보고서(자간조정).hwpx` → 접미사 제거, `YYYYMMDD_부서_제목_v1.hwpx` 템플릿, 문서 안 제목으로 이름 짓기.
대상 파일은 문서(HWP/HWPX/PDF…)에 한정하지 않고 **모든 확장자**(JPG·PNG·XLSX·ZIP 등)다. 그래서 기존 파일 선택 서비스의 문서 확장자 허용 목록(`DOCUMENTS`)을 그대로 쓸 수 없다(§6).

## 2. 탭 위치와 셸 변경

현재 7탭: 문서편집(0)·표템플릿(1)·표그림판(2)·다이어그램(3)·마인드맵(4)·그림판(5)·파일변환(6). "파일변환은 항상 맨 끝"(2026-10-30 사용자 지시)이므로 **새 탭 "파일이름"은 그림판(5) 다음, 파일변환 앞인 6번**에 넣고 **파일변환은 7번으로 밀린다.**

| 파일 | 변경 |
|---|---|
| `flutter_ui/lib/features/workspace/tab_navigation_shell.dart` | `fileRename` 위젯 필드 추가, `_labels`·`_icons`에 `'파일이름'`(아이콘 `Icons.drive_file_rename_outline`) 삽입, `initialIndex < 8`, `pages` 순서, 주석의 탭 번호 설명(`WorkspaceTabScope.selectTab`) 갱신 |
| `flutter_ui/lib/features/workspace/workspace_adapters.dart` | `FileRenameAdapter`(`KeyedSubtree(key: ValueKey('tab-file-rename-adapter'))`) 추가, `IntegratedWorkspace`가 `fileRename:` 전달 |
| **`flutter_ui/lib/main.dart:172-177`** | `onTabChanged`의 **`index == 6`/`from == 6`(파일변환 탭 특수 처리) → 7로 변경.** 놓치면 파일변환 탭의 모드 전환이 새 탭에서 동작한다. 탭 번호를 상수(`kTabFileRename = 6`, `kTabFileConversion = 7`)로 뽑아 하드코딩 제거 |
| 시험 | `flutter_ui/test/tab_navigation_shell_test.dart`, `docfit_app_integrated_shell_test.dart`, `tab_back_button_test.dart`의 탭 수·번호 갱신 + 새 탭 추가 시험 |

탭 영구 마운트 규칙(`isModal: false`, `CloseGuards` 충돌 방지)을 지킨다 — 파일이름 화면은 모달이 아니며 변경 적용 중(진행 중)에는 창 닫기 가드를 등록한다(2.0.0 `CloseGuards`).

## 3. 계층 구조

```
Flutter  features/file_rename/            (화면·상태·규칙 편집기)
   │  api('file_rename', action, payload)   — 기존 IPC 규약(api_contract.ServiceError, 버전 있는 JSON)
Python   docfit_app/file_rename_service.py  (계획·실행·이력·경로 검증, 토큰 파일 선택)
Core     docfit_core/file_rename/            (순수 파이썬: 규칙·계획·검사·실행기 — 리눅스에서 임시 폴더로 시험)
```
- **Core는 UI·COM·Windows API 없이 동작**하고 `pathlib`/`os`만 쓴다(`defusedxml`은 문서 제목 읽기에만).
- 서비스는 기존 패턴(`table_sketch_service.command(action, payload)` → `dict(ok=..., ...)`)을 따른다. `application_service.py`의 메서드 개수 표(`counts[...]`, 92~95행)에 `file_rename: 2`를 추가하고 `desktop_web_ui._BrowserApi` 노출 목록(2284행)에 등록한다.

## 4. 규칙 모델 (파이프라인)

DarkNamer는 규칙을 하나씩 적용하지만 우리는 **규칙 목록을 위에서 아래로 연달아 적용**하고 결과를 한 표에 미리 보여 준다.

```jsonc
{ "version": 1, "rules": [
  {"kind": "replace",   "find": "IMG_", "to": "", "regex": false, "case": false, "scope": "stem"},
  {"kind": "date",      "source": "exif|mtime|ctime|today", "format": "YYYYMMDD", "position": "prefix", "sep": "_"},
  {"kind": "number",    "start": 1, "step": 1, "digits": 3, "position": "suffix", "per_folder": true, "sep": "_"},
  {"kind": "ext_case",  "mode": "lower"}
]}
```
규칙은 `Entry`의 현재 상태(앞 규칙의 결과)를 받아 새 상태를 돌려준다. 규칙마다 `scope`(이름/확장자/전체)를 가진다.

**규칙 종류(1차 범위 = DarkNamer 전부 + 보완)**
1. `replace` 문자열 바꾸기(일반·정규식·대소문자·첫 번째만/전부)
2. `add` 앞/뒤 추가(고정 문자열, 변수 `{date}`·`{n}`·`{folder}`·`{orig}`)
3. `clear` 이름 지우기(확장자만 남김)
4. `del_pos` 위치 지우기(n번째~m번째, 앞에서/제일 뒤에서, 음수·범위 오류는 규칙 단계에서 거부)
5. `del_between` 묶인 곳 지우기(시작·끝 문자, 중첩 처리: 가장 바깥 / 가장 안쪽 선택)
6. `digits_keep` / `digits_delete` 숫자 남기기·삭제
7. `digits_pad` 자리수 맞추기(제일 앞/뒤 숫자 기준 0 채우기)
8. `number` 번호 붙이기(자리수·시작값·**스텝**·앞/뒤·**폴더별**)
9. `number_shift` 이름 속 번호 ±n 일괄 증감(예 `1589(3-1)` → `1588(3-1)`)
10. `ext_del`·`ext_add`·`ext_replace`·`ext_case` 확장자
11. `date` 날짜·시각 삽입(수정·생성·오늘·EXIF 촬영일, **날짜·시간 분리**, 형식 선택)
12. `cleanup` 공백·밑줄·특수문자 정리, 한글 NFC 정규화, 연속 공백 줄이기
13. `move_folder` 경로 통일(다른 폴더로 이동 — 2차, 확인 대화상자 필수)
14. **앱 전용(3단계)**: `doc_title`(HWPX 제목으로 이름 짓기), `strip_result_suffix`(`(자간조정)`·`(일괄적용)`·`(서식통일)`·`(서식적용)` 제거/교체), `template`(공문서 파일명 템플릿)

**DarkNamer 버그를 처음부터 막는 규칙(번호 붙이기)**
- *폴더별 번호*는 **폴더 키로 묶어 각 폴더 안에서 목록 순서대로** 센다. 하위 폴더 파일이 목록 중간에 끼어도 상위 폴더 번호가 끊기거나 1부터 다시 시작하지 않는다(목록 정렬과 번호 부여 순서를 분리: 번호 순서 = 현재 목록 순서를 폴더별로 걸러낸 것).
- 번호 부여 순서의 기준 목록은 **규칙 적용 전의 목록 순서**이며 정렬은 번호 규칙 앞에서 확정한다(정렬 바꾸면 미리보기 즉시 재계산).

## 5. 계획(Plan)과 안전 검사

`preview(entries, rules)`는 **파일 시스템을 읽기만** 하고 `Plan`을 만든다. 각 항목 상태:
`ok` · `unchanged`(이름 변화 없음) · `conflict`(충돌) · `invalid`(금지 문자·예약어·길이) · `blocked`(읽기 전용·잠김·권한) · `skipped`(사용자가 제외).

검사(`check.py`) — 하나라도 오류면 **"변경 적용" 비활성**(오류 항목만 제외하고 적용하는 선택지 제공):
1. 같은 폴더에 **이미 있는 다른 파일**과 이름 충돌(대소문자 무시 — Windows) · 목록 안 새 이름끼리 중복
2. Windows 금지 문자 `\ / : * ? " < > |`, 제어 문자, **예약어**(`CON PRN AUX NUL COM1~9 LPT1~9`, 확장자 붙어도 동일), **끝의 마침표·공백**, 빈 이름
3. 전체 경로 길이(260자 초과 경고 — 긴 경로 사용 설정 여부와 무관하게 경고만, 32,767자 초과는 거부)
4. **교차 이름 바꾸기**(A→B, B→A / 순환): 실행기가 임시 이름(`.rename-tmp-<uuid>`)을 거쳐 처리
5. **열려 있는 파일**: rename 시도 시 `PermissionError`(공유 위반)가 나면 `blocked`로 기록하고 이유 표시 — 미리보기 단계에서는 `os.access` 정도만 확인(정확한 잠금 판정은 실행 시점)
6. 확장자 변경은 **파일 형식을 바꾸지 않음**을 경고하는 안내, `.exe .bat .cmd .ps1 .lnk .dll .sys` 등 실행 파일 이름 변경은 확인 한 번 더
7. 숨김·시스템 속성 파일과 앱 설치 폴더·Windows·Program Files 안은 기본 제외(허용 목록 설정)

## 6. 파일 선택·끌어놓기 (경로 안전)

- 끌어놓기: `desktop_web_ui.py`의 `set_drop_target`(1992행) 허용 대상에 `"rename_files"` 추가, 이 탭이 활성일 때만 설정(탭 이동 시 `documents`로 복귀). `_FILE_DROP_SCRIPT`의 안내 문구를 "여기에 파일을 놓으면 이름 목록에 추가됩니다"로.
- 파일 추가 버튼(`native_file_dialog_service.PURPOSES`)에 **`'rename_files': ('open', ANY)`**(모든 확장자, 다중 선택)와 **`'rename_folder': ('directory', ANY)`** 목적을 추가하고 **확장자 필터 `None`(모두)**을 지원하도록 `native_dialog`의 필터 문자열 생성(`extensions[0][1:]` 가정)을 고친다. 한 번에 최대 파일 수(`MAX_FILES = 1000`)는 이름 변경에서는 상향(예 10,000) 여부 결정.
- 호스트는 경로를 메모리에 보관하고 UI에는 **토큰만** 돌려주는 기존 구조(`NativeFileDialogService`, TTL 300초)를 유지한다. 끌어놓은 경로도 같은 방식으로 검증: 절대 경로, `..` 없음, 심볼릭 링크·정션 거부(또는 `resolve` 후 같은 폴더 안), UNC 경로 허용 여부(네트워크 드라이브 안내), 존재 확인.
- 폴더를 추가하면 하위 파일을 재귀로 펼치되 옵션(하위 폴더 포함, 숨김 포함)으로 제어하고 개수 상한과 진행 표시.

- **목록**: 가상 스크롤(수천 개), 열 = 선택·원래 이름·새 이름·상태·크기·수정 시각·폴더(보기 옵션), 헤더 클릭 정렬(이름/경로/크기/수정/생성 오름·내림, **자연 정렬 기본**), 행 위/아래 이동(`<` `>`), F2 새 이름 직접 편집(그 항목만 규칙 결과를 덮어씀 — 표시), 선택 제외, 다중 선택.
- **규칙 패널**: 규칙 카드 목록(순서 변경·사용 켜기/끄기·복제), 규칙마다 옵션 폼. 규칙 변경 즉시 미리보기(디바운스 150ms, 대량이면 백엔드에서 계산 — 응답에 변경된 항목만).
- **상태 표시**: 충돌·오류 행은 색과 아이콘(색만으로 구분하지 않음), 툴팁에 이유, 상단 요약 배지.
- **적용 흐름**: "변경 적용" → 확인 대화상자(변경 개수·충돌 제외 개수·실행 파일 포함 여부) → 진행(취소 가능: 지금까지 한 것은 이력에 남김) → 결과 요약(성공·건너뜀·실패와 이유) → **"되돌리기"가 켜짐**.
- **되돌리기**: 마지막 적용 1회 단위(Ctrl+Z). 앱을 껐다 켜도 이력 목록에서 이전 적용을 골라 되돌릴 수 있음(되돌리기도 충돌 검사: 원래 이름 자리가 이미 쓰였으면 해당 항목만 거부).
- **규칙 세트**: 규칙 목록을 이름 붙여 저장/불러오기/내보내기(JSON), 자주 쓰는 세트(예: "카메라 사진 날짜+번호", "공문 파일명 정리") 기본 제공. 설정 백업/복원 연동.
- **단축키**: Ctrl+O 파일 추가, Ctrl+L 목록 지우기, Ctrl+S 변경 적용, Ctrl+Z 되돌리기, `<`/`>` 이동, F2 직접 편집, Delete 목록에서 제외. 탭 안에서만 동작하도록 포커스 범위 제한(다른 탭 편집기와 충돌 방지).
- **접근성/좁은 창(P6)**: 규칙 패널은 좁은 창에서 목록 아래로 내려가는 세로 배치, 도구줄은 가로 스크롤.

## 8. IPC 계약 `file_rename_service.command(action, payload)`

| action | 입력 | 출력 |
|---|---|---|
| `add` | `{tokens\|paths, recursive, include_hidden}` | `{entries:[{id,path,name,size,mtime,ctime}], skipped:[{path,reason}]}` |
| `preview` | `{entry_ids, order, rules, overrides}` | `{plan_id, items:[{id,new_name,status,warnings}], summary}` |
| `apply` | `{plan_id, confirm:{executables:bool}}` | `{history_id, done, skipped, failed:[{id,reason}]}` (진행은 `jobs.py` 작업 흐름 재사용) |
| `undo` | `{history_id}` | `{restored, skipped, failed}` |
| `history` | `{limit}` | `{items:[{id,when,count,first_name}]}` |
| `ruleset_save/load/list/delete` | 이름·규칙 | 규칙 세트 저장소(설정 폴더) |
| `inspect` | `{entry_id}` | EXIF·문서 제목 등 미리보기 정보(느린 읽기는 별도 호출) |
- `plan_id`는 **미리보기 내용의 해시**이며 `apply`는 그 사이 파일이 바뀌지 않았는지(크기·수정 시각) 다시 확인하고 달라졌으면 거부한다(미리보기와 다른 결과 방지).
- 오류는 `ServiceError(code, message)`(`RENAME_CONFLICT`, `RENAME_INVALID_NAME`, `RENAME_PATH_REJECTED`, `RENAME_IN_USE`, `RENAME_PLAN_STALE` …).

## 9. 실행기와 이력

1. 계획에서 `ok` 항목만 취해 **의존 그래프**를 만든다(A의 새 이름 = B의 현재 이름이면 B 먼저).
2. 순환이 있으면 순환 중 하나를 **임시 이름**으로 먼저 옮기고 마지막에 최종 이름으로.
3. 각 rename 직전 이력 파일에 `intent`(원래→새) **먼저 기록**, 성공 뒤 `done`. 중간에 전원 차단·크래시가 나도 다음 실행에서 이력으로 복구/되돌리기 가능.
4. `os.rename`/`os.replace` 금지 — **덮어쓰기 불가**(이미 대상이 있으면 실패, `os.replace` 사용 금지). 대소문자만 바꾸는 이름 변경은 임시 이름 경유(Windows 대소문자 무시 파일시스템).
5. 실패하면 그 항목만 `failed`로 기록하고 **계속할지 멈출지**는 옵션(기본: 멈춤 — 부분 적용 상태를 단순하게).
6. 파일 내용·수정 시각·속성은 건드리지 않는다(`rename`만). 이름 변경 뒤 **재확인**(새 경로 존재, 원래 경로 없음).
7. 이력 파일: 설정 폴더(`%APPDATA%\HwpAutoDocFit\file_rename\history.jsonl`), 항목 수 상한·보관 기간(예 30일/1,000건), 사용자가 지울 수 있음. 경로가 개인정보일 수 있으므로 **외부로 보내지 않음**(오프라인), 설정의 "기록 파일 만들기" 옵션과 일관(기본: 되돌리기 기능에 필요하므로 이력은 켬 — 안내 표시).

## 10. 앱 전용 규칙 (3단계)

- `doc_title`: HWPX면 `docfit_core/hwpx.py`로 제목 문단(`제목1:` 표 A1 칸 또는 첫 굵은 문단)을 읽어 `{title}`로 쓴다. 파일 안전 열기(압축 폭탄 한도·`defusedxml`)와 읽기 전용. HWP(이진)·PDF는 파일 이름만 쓰고 제목 읽기는 미지원 안내.
- `strip_result_suffix`: 앱 결과 접미사 `(자간조정)` `(일괄적용)` `(서식통일)` `(서식적용)` `(최종검수)` 등을 제거·교체(앱이 만드는 접미사 목록을 한 곳에서 가져옴 — 새 접미사가 생기면 자동 반영).
- `template`: `{date}_{dept}_{title}_v{n}` 같은 변수 템플릿. `{dept}`는 설정의 기관·부서 값 사용(없으면 입력).
- 한/글 문서 이름 바꾸기 시 **같은 폴더의 부속 파일**(`.hwpx`와 같은 이름의 `.pdf` 등)을 함께 바꾸는 옵션(2차).

## 11. 시험 계획

- **Core 단위(리눅스, 임시 폴더)**: 규칙별 경계(빈 이름·확장자 없음·여러 점·한글·이모지·긴 이름), 번호 붙이기(폴더별·하위 폴더 섞임·스텝·시작값·자리수 넘침), 자리수 맞추기(앞/뒤 숫자), 묶인 곳 삭제(중첩 괄호), 위치 삭제(범위 오류), 숫자 증감(자릿수 올림/내림, 0 미만 거부), 자연 정렬, 날짜 형식(EXIF 없는 파일 대체 규칙), 충돌·금지 문자·예약어·대소문자 충돌, 교차·순환 이름 바꾸기, 실패 후 이력으로 복구, 되돌리기 충돌, `plan_id` 낡음, 이력 손상·잘림, 파일 내용 해시·수정 시각 불변.
- **서비스**: 경로 검증(심볼릭 링크·`..`·UNC·존재하지 않음), 토큰 TTL, 상한, 오류 코드.
- **Flutter 위젯**: 탭 7→8개(번호·라벨·`WorkspaceTabScope`), 파일이름 탭 마운트 유지, 미리보기 갱신, 충돌 행 표시, 적용 확인 대화상자, 단축키 범위, 좁은 창, **파일변환 탭 번호 변경(6→7)에 따른 `main.dart` 분기 시험**.
- **PC 확인(Windows)**: 실제 끌어놓기, 한/글·탐색기가 열고 있는 파일, OneDrive·네트워크 드라이브, 한글 이름·긴 경로, 대소문자만 바꾸기, 수천 개 파일 성능.

## 12. 구현 순서와 산출물

1. **Core + 시험**(UI 없이 CLI/서비스로 검증): 모델·규칙(1~12번)·검사·실행기·이력 — 리눅스에서 전부 시험.
2. **서비스 + 선택/끌어놓기**: IPC, 파일 선택 목적 추가, `set_drop_target`.
3. **탭 + 화면**: 셸 변경(§2) → 목록·규칙 패널·미리보기·적용·되돌리기.
4. **앱 전용 규칙·규칙 세트·단축키·EXIF**, README·사용 설명서·`THIRD_PARTY_NOTICES.md`(DarkNamer 참고 표기 검토).
5. 릴리스 노트에 "이전 버전 대비 개선 효과"(측정한 것만), 정식 배포 전 Windows PC 확인.

## 13. 열린 질문(사용자 확인)

1. **폴더 이름 변경**을 1차에 포함할지(포함하면 하위 항목 경로가 함께 바뀌므로 계획에서 하위 경로 재계산 필요 — 제안: 2차).
2. **실행 취소 이력 보관 기간·개수**(제안: 30일·1,000건).
3. **EXIF·공문서 템플릿**을 1차에 넣을지(제안: Core는 1차에 EXIF 읽기 포함 — Pillow가 이미 의존성, 공문서 템플릿은 3단계).
4. **적용 실패 시 기본 동작**: 멈춤(제안) vs 계속.
5. 탭 이름 **"파일이름"**(제안) vs "이름바꾸기" — 7·8번째 탭 이름 길이와 좁은 창에서의 탭줄 넘침(P6)을 함께 확인.

## 14. PowerRename·DarkNamer 벤치마킹 보강(2.0.9)

탭 이름을 **'파일명 일괄변경'**으로 바꾸고 다음을 더했다.

| 기능 | 내용 |
|---|---|
| 변수 | '문자열 바꾸기'의 바꿀 글자, '앞/뒤에 추가'의 넣을 글자에서 아래 문법 사용 |
| 정규식 묶음 | `\1`·`\g<이름>`에 더해 `$1`·`$2`. 없는 묶음을 가리키면 규칙 오류로 알림 |
| 이름 목록 붙여넣기(`names_list`) | 엑셀 열·메모장 줄을 화면 목록 순서대로 새 이름으로. 제외한 행도 자기 줄을 차지하고, 줄이 모자라거나 빈 줄이면 원래 이름 유지(`names_short` 경고). 확장자 유지 선택 |
| 대소문자 | `capitalize`(맨 앞 글자만 대문자), `sentence`(맨 앞만 대문자·나머지 소문자) 추가 |
| 전각↔반각 | '공백·밑줄·전각 정리'의 `width`(`keep`·`half`·`full`). 한글은 그대로 |
| 폴더 | 확장자 규칙만 건너뛰고 나머지 규칙 적용(폴더 이름 전체를 이름으로 봄) |
| 충돌 자동 번호 | `on_conflict="number"`이면 충돌 항목에 ` (2)`·` (3)` …을 붙임(`auto_numbered` 경고). 기본은 `block`(적용 안 함) |
| 화면 | 바뀌는 것만 보기, 충돌 처리 선택, 이름 목록 복사, 바뀐 부분 강조 |

| 변수 문법 | 뜻 |
|---|---|
| `${start=1,increment=1,padding=3}` | 목록 순서 번호. 옵션은 골라 쓰며 기본값은 시작 0·간격 1·자리수 없음(`${}`도 가능) |
| `${rstringalnum=8}`·`${rstringalpha=8}`·`${rstringdigit=8}` | 무작위 영숫자·영문·숫자(최대 64자) |
| `${ruuidv4}` | 무작위 UUID v4 |
| `$YYYY` `$YY` `$MM` `$DD` `$hh` `$mm` `$ss` `$fff` | 수정 시각의 연·월·일·시·분·초·밀리초 |
| `$$` | `$` 글자 그대로(`$$1`은 글자 `$1`) |
| `{orig}`·`{folder}`·`{date}` | 앱 변수: 원래 이름, 폴더 이름, 수정일(YYYYMMDD) |

무작위 변수는 미리보기마다 값이 달라지며, 적용은 마지막 미리보기 계획을 그대로 실행하므로 화면에 보인 이름이 그대로 쓰인다.
