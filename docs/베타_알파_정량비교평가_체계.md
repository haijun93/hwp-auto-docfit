# 베타–알파 정량 비교평가 체계

## 목적과 범위

알파 변경이 베타 대비 기능 품질을 떨어뜨리거나 처리시간 회귀를 일으키는지, 같은 입력·설정·한/글 PC 환경에서 짝지어 측정한다. 이 평가는 배포 안전성을 위한 증거를 제공하지만 모든 문서의 동등성을 증명하지는 않는다. HWP/HWPX 실측은 Windows와 한/글 2020이 필요하다.

## 평가 단계

1. 단위·통합 시험: 빠르고 재현 가능한 코드 수준 오류를 찾는다.
2. Quick tier: HWP/HWPX 원본의 해시 기반 5쪽 발췌 사본으로 대표 문서를 빠르게 선별한다. TXT/Markdown은 입력 그대로 양쪽에 전달한다.
3. Full tier: 원본 전체와 실제 사용 흐름(예: AI 답변 복사 텍스트 `format`, 문서 `unify`/`all`)을 평가한다. 승격 전에는 핵심 문서·모드별 3회 이상, 변동이 큰 문서 또는 쪽 배치 비교는 5회 이상 반복한다.

양 버전은 같은 입력 파일·모드·설정을 받는다. 실행 순서는 반복마다 Beta→Alpha, Alpha→Beta로 교차하고, 입력 및 quick 발췌의 SHA-256을 전후 확인한다. 회귀 도구는 문서별 작업 사본에 처리하며 원본을 변경하지 않는다. 비교 산출물은 작업 폴더에 두고 입력 본문 텍스트를 리포트에 저장하지 않는다.

## 측정 지표

- 기능·품질: 출력 생성, 프로세스 종료, 최종검수 점수, 기준 쪽 구성 유지, 레이아웃 플래그, HWPX 유효성 및 본문 해시.
- 출력 구조: 문단·표·그림·컨트롤·섹션 수와 Markdown 흔적(제목/굵게/목록/인용/코드/인용 마커), 개요기호 문단 수. 구조 변경은 그 자체로 오류라고 단정하지 않고 해당 기능의 기대 결과와 함께 판정한다.
- 성능: 동일 작업의 처리 초, 단계별 상위 시간, 버전별 중앙값·p95, 짝별 증감률 중앙값 및 재표집 95% 구간.
- 신뢰성/재현: 반복 성공률, 버전 커밋, 파일 해시, 설정, 문서·모드별 판정.

## 판정 규칙

- 베타는 성공했는데 알파가 실패하거나, 점수/요구 쪽 배치가 하락하면 회귀로 판정한다.
- 3쌍 미만, 실행 실패, 양 버전 입력·설정 불일치 또는 결과 누락은 자료 부족/판정 보류다.
- 알파의 짝별 처리시간 증감률 중앙값이 +5%를 넘고 95% 구간의 하한도 0보다 크면 성능 회귀다. 95% 구간이 0을 가로지르면 판정 보류이며, 통계적으로 검출되지 않았다는 결과는 시험 범위에서만 유효하다.
- `improved`는 품질 기준을 충족하고 시간 개선이 반복적으로 확인된 경우에만 쓴다. 그 외 무회귀는 `no_detected_regression`이다.
- 베타 승격은 전체 회귀시험 통과, 핵심 문서·모드의 반복 측정, 알려진 보안 고위험 이슈의 승인/해결, 배포물 출처·해시 확인을 모두 요구한다.

## Windows 실기기 명령

```powershell
$py = '.venv\Scripts\python.exe'
$beta = '..\mapo-beta1-finalcheck-20261013'
$alpha = (Get-Location).Path
$out = Join-Path $env:TEMP 'docfit-beta-alpha-quick'

& $py scripts/compare_versions_pc.py `
  --beta-root $beta --alpha-root $alpha `
  --corpus "$env:APPDATA\HwpAutoDocFit\test_corpus.json" `
  --tier quick --mode unify --repeat 3 `
  --unify-full-format 0 --require-same-layout --out-dir $out
```

AI 복사 답변 예시는 `tests/fixtures/ai_answer_chatgpt.txt`, `ai_answer_claude.txt`, `ai_answer_gemini.txt`를 같은 입력 인자로 전달하고, `--tier full --mode format --repeat 3`으로 반복한다. 상세 결과는 `comparison.md`와 비식별 구조·시간 데이터를 담은 `comparison.json`에 기록된다.

## 해석상 한계

한/글 COM의 조판, 페이지 재배치, 캐시·PC 부하가 실행시간에 영향을 준다. 특히 페이지 배치 단계가 달라지면 앱 단계별 로그로 원인을 분리하고 같은 입력 교차 반복으로 재시험한다. 소수 반복의 부트스트랩 구간은 정밀한 모집단 추론이 아니라 판정 불확실성을 드러내는 기술통계로 취급한다. 화면 사용성, 문서 시각적 완성도, 보안은 별도 수동·보안 게이트다.
