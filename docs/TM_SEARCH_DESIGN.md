# 타임머신 검색 재설계 — Docufinder 벤치마킹 (2026-11-03 사용자 지시)

현재 파일명·본문 검색은 실사용 수준이 아니다. [Docufinder](https://github.com/chrisryugj/Docufinder)의 검색 기능을 벤치마킹해 다시 만든다. 폐쇄망 원칙에 따라 AI(시맨틱·질의응답·요약)는 가져오지 않는다.

## 가져올 것
1. **파일명 검색**: 색인과 별개로 메모리 캐시에서 즉시 부분 일치(한글 포함, 공백으로 나눈 여러 낱말 모두 포함). 정렬 가능한 열 보기(이름·경로·크기·수정일·형식).
2. **본문 키워드 검색 연산자**: `"구문"`(정확한 구문), `-낱말`(제외), `ext:hwp,pdf`(확장자), `path:`(폴더), `after:2024-06`·`before:`(수정일), `~N`(N낱말 이내 근접). 여러 낱말은 모두 포함(AND).
3. **한국어 부분 일치**: SQLite FTS5 `trigram` 토크나이저로 조사·어미가 붙어도 찾게 한다(형태소 분석기 없이). 2글자 낱말은 보조 LIKE 검색.
4. **형식**: HWPX, HWP5(kordoc-runtime), DOCX, PPTX, XLSX·XLS(시트·행 위치), PDF(쪽 번호), TXT·MD(EUC-KR/CP949 자동), EML(제목·보낸이·받는이·본문). 암호 문서는 건너뛰고 표시.
5. **결과 표시**: 문서마다 일치 문장 스니펫과 검색어 강조, `3p`·`시트1 12행` 같은 위치 배지, 클릭=미리보기(일치 위치), 더블클릭=열기.
6. **색인**: 폴더 등록 후 자동 증분(경로·크기·수정 시각), 파일 추가·수정·삭제 자동 반영(기존 KAgent 감시 연계), 파일명 검색은 색인 전에도 동작.
7. **속도 목표**: 문서 수천 개에서 본문 검색 1초 이내, 파일명 검색 즉시(100ms 이내).

## 단계
- **TMS-CORE**: 검색어 해석기(연산자), FTS5 trigram 스키마·이전, 순위(bm25)·스니펫·위치, 파일명 메모리 캐시. 서비스 명령 `content_search`·`file_search`를 새 결과 형식으로.
- **TMS-EXTRACT**: 형식별 추출기와 위치 정보.
- **TMS-UI**: 검색창 연산자 안내, 열 보기, 스니펫 강조, 위치 배지, 미리보기·열기.
