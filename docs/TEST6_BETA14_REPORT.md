# Beta 14 · test6 실문서 테스트

시험일: 2026-10-10. 대상: 사용자 지정 `111/test6`의 HWP 1개·HWPX 3개.

## 시험 조건

- 공식 태그 `v1.72-beta.14`의 코드(태그 커밋 `10aba71`)를 별도 임시 폴더에 추출해 실행했다. 작업 중인 최신 코드와 분리했다.
- **한 번에 적용 / 표 제외 켜짐 / 자간 조정 포함 / 기본 보고서 서식 / 1회 / 검수 켜짐**.
- 화면의 표 제외와 같은 `without_tables()`를 적용하고 `표자간조정=False`로 실행했다. 일반 표 변환·서식·너비·정밀 복제·표 안 자간·줄 병합·단어 검사를 껐다.
- 제목·개요·중제목·붙임 서식 표, 공통 표준서식, 쪽 맞춤은 제품의 해당 옵션 동작대로 유지했다.
- 원본은 사본으로만 시험했다. 한/글 COM으로 처리·결과 재열기·전후 PDF 출력 후 전체 페이지 도해와 문제 페이지를 비교했다. EXE 화면 클릭 시험은 아니다.
- 아래 시간은 문서 처리·저장·제품 검수 시간이다. 후속 PDF 출력·보고서 분석은 포함하지 않는다. 1회 측정이므로 일반적인 성능 수치로 확대 해석하지 않는다.

## 확인한 문제와 우선순위

### P1 · 금액 단위가 쉼표로 바뀜

문화경제국 문서의 원본 `구비2,241,275천원,`이 결과에서 `구비2,241,275천, ,`으로 바뀌었다. 원본 PDF 32쪽과 결과 PDF 46쪽, 전후 HWPX XML에서 확인했다. 숫자는 같지만 금액 단위의 **‘원’이 삭제되고 쉼표가 삽입**됐다.

원본 문단에는 쉼표 다음에 `hp:fwSpace`(고정폭 공백)가 있다. 이를 제외한 스캔 문자열로 Beta 14의 `쉼표_공백_보정_대상()`을 실행하면 두 번째 수정 범위가 `[40, 41)`이다. 같은 범위를 실제 문자열에 대입하면 쉼표 대신 **‘원’**을 선택한다. 스캔 문자열과 한/글 문자 위치의 불일치가 강한 원인 후보이며, 실제 COM 단계별 스냅숏으로 최종 확정하는 작업은 남아 있다.

제품 무결성 검사는 이 결과를 통과시켰다(본문 일치도 약 99.18%). 전체 유사도 기준은 한 글자 단위의 내용 훼손을 놓친다.

권고: 고정폭·묶음 공백 및 줄바꿈을 포함한 실제 문자 위치로 범위를 변환하고, 삭제 직전에 선택된 문자열이 예상 문자열인지 확인한다. 숫자·단위 변경은 전체 유사도와 별도로 검사한다.

### P1 · 표 제외 상태에서 일부 표가 용지 밖으로 잘림

문화경제국 결과의 PDF 30·31·43·44쪽 등에서 표의 오른쪽 끝이 용지 경계를 넘는 모습을 확인했다. 원본의 대응 표는 용지 안에 있었다. 표 너비 조정은 꺼져 있지만 공통 용지 여백·문단 서식 변경은 남으므로, 기존 표의 위치·폭과 새 편집 영역이 맞지 않을 수 있다.

권고: 표 제외일 때 일반 표의 실질 배치도 보존하거나, 용지·편집 영역 변경 시 기존 표의 넘침을 확인해 결과 검수에 표시한다. 제목·개요 등 서식 표는 일반 표와 구분한다.

### P2 · 제목 줄바꿈과 테두리 겹침

`(서식)10월 확대간부회의_부서명.hwpx`의 제목이 원본 한 줄에서 결과 두 줄로 바뀌고, 첫 줄 글자가 제목 표 위쪽 테두리와 겹쳤다. 표 제외 조건의 결과 PDF 1쪽에서 확인했다. 제품 점수는 100점으로 이 문제를 잡지 못했다.

권고: 제목 서식을 바꾼 뒤 실제 줄 수·칸 높이·테두리와 글자의 겹침을 검사한다. 표 제외로 일반 표 자간을 끌 때에도 제목 서식 표의 마무리 조건을 별도로 확인한다.

### P2 · 저장 후 문장과 표의 쪽 분리가 다시 남음

문화경제국 문서는 처리 중 쪽 배치 13건을 해결했다고 집계했지만, 저장 결과 검사에서 17쪽의 사업비 문장과 표가 서로 다른 쪽인 항목 1건이 남았다. 최종 `page_group` 검사는 실패이며 점수는 99.6점·부분 달성이다. 처리 중 성공 집계와 저장 결과를 구분해야 한다.

권고: 최종 재열기 검사 결과를 최종 판정으로 사용하고, 쪽 배치 후 재조판·후속 변경이 이미 해결한 묶음을 분리하는지 추적한다.

### P2 · 쪽 수 증가 후 목차 쪽 번호가 그대로 남음

문화경제국 문서는 35쪽에서 50쪽으로 늘었다. 목차의 문화예술과는 계속 13쪽을 가리키지만 결과에서는 PDF 23쪽, 인쇄 쪽 번호 20쪽에서 시작한다. 쪽 수 증가 자체는 표준서식 적용의 결과일 수 있으나, 목차를 그대로 두면 탐색 정보가 틀어진다.

권고: 자동 목차·정적 목차를 구분해 갱신 가능 여부를 알리고, 갱신하지 못한 목차는 검수 항목으로 표시한다.

### P3 · 사진·표가 있는 마지막 쪽을 텍스트 두 줄로 판정

전기버스 검토자료 결과 11쪽은 사진과 표가 많이 있는 쪽이다. 제품은 텍스트 줄 두 개를 근거로 10쪽 맞춤을 시도했고 실패·원복에 20.3초를 썼다. 로그상 표 셀 74개를 조사하고 20개 셀의 여백을 변경했다가 복원했다. 이는 표 제외에서도 쪽 맞춤의 표 셀 여백 조정 경로가 유지됨을 보여준다. 최종 표 여백 변경이 남았다는 뜻은 아니다.

권고: 마지막 쪽의 사진·표·도형 점유 면적을 포함해 부족한 쪽인지 판정하고, 표 제외와 쪽 맞춤의 표 여백 조정 관계를 명확히 한다.

## 검사 범위와 재현 이력

- 공식 태그의 괄호 라벨 내어쓰기 관련 단위 테스트 7개 통과. 실제 모든 문단의 정밀 내어쓰기 위치를 자동으로 검증했다는 뜻은 아니다.
- 제품 최종검수는 선택된 작업 중 15개에 대해 결과 검사 기능이 없고 수행 여부만 확인한다고 명시한다. 100점은 모든 배치·서식·내용이 정확하다는 보증이 아니다.
- 최초 표 포함 실행은 사용자 조건 변경에 따라 중단했다. 그 결과는 위 표 제외 판정에 포함하지 않았다.
- 표 제외 연속 실행에서는 첫 파일 저장 후 COM 종료 시 RPC 오류가 표시됐고, 이어 대형 HWP 처리 중 테스트 프로세스의 access violation이 발생했다. 독립 프로세스 재시험 결과와 구분하여 기록하며, 배포 EXE에서도 같은 종료가 발생한다고 단정하지 않는다.
- 사용자 원본·설정은 수정하지 않았다. 원본 사본과 원본의 SHA-256을 비교하고, 결과의 표·이미지·컨트롤 개수 및 표 안 글자를 포함한 전후 텍스트를 별도로 확인했다.
- 원본 문서, 결과 HWPX, PDF와 상세 JSON은 저장소에 넣지 않고 로컬 시험 폴더에 보관한다: `%TEMP%/docfit-beta14-test6-20261010`.
