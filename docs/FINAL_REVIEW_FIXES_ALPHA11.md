# Alpha 11 — 전체 최종 검토 F1~F5 수정

작성일: 2026-10-14. 검토 기준: bf955f1, 검토 보고서 커밋 26a359b.
대상: `docs/FINAL_CODE_REVIEW_BF955F1.md`의 P1 2건·P2 3건.

## 반영 내용

- F1/P1: fidelity 출력은 같은 폴더에 예측 불가능한 이름으로 독점 생성한 임시 파일을
  fsync한 뒤 하드링크로 **기존 이름을 교체하지 않고** 원자적으로 확정한다.
  고정 `.tmp`를 열지 않으며 원본·기존 대상·별칭을 덮어쓰지 않는다.
  실패 시 자신이 만든 임시 파일만 정리한다. NTFS 등 하드링크 지원 파일시스템이 필요하며,
  미지원 파일시스템에서는 안전하지 않은 덮어쓰기 방식으로 우회하지 않고 오류를 반환한다.
- F2/P1: Flutter 준비 후 native closing 콜백은 즉시 거부하고, 기존 상태/확인 폴링으로
  `app_close` 요청을 전달한다. 편집 화면은 `CloseLease`로 저장 대기·미저장 상태를 확인한다.
  설정·프로필은 명시적 폐기/취소, 흐름도·tldraw는 기존 폐기 확인, 아웃라이너는 저장 성공을 요구한다.
  저장/RPC 대기, 다른 모달, 처리 실패는 종료를 허용하지 않는다.
  모든 편집 경로가 dispose된 뒤 메인 화면 입력을 잠근 상태에서만 종료를 승인한다.
  승인된 종료는 이미 거부한 OS 이벤트와 구분하여 Tk 종료 감시자가 WebView를 닫게 한다.
  기존 실행 중 작업 중단 확인과 숨김 Tk 소유 스레드 디스패치는 유지한다.
- F3/P2: 표 보호용 스냅샷/XML 판별 실패 및 COM 칸 위치·텍스트 불일치는 명시적인 오류로 중단한다.
  보호 대상 없음과 판별 불가를 구분한다. 장식 표와 기존 제목/붙임 서식 표 경로에 모두 적용한다.
  정상적인 빈 결과와 서식 표 모양이 없는 빠른 경로는 유지한다.
- F4/P2: 흐름도와 tldraw에 문서별 `ProcessLock` 및 원본 바이트 SHA-256 revision을 도입한다.
  잠금 내부에서 expected revision 대조·원자적 저장·응답 revision 확정을 수행한다.
  삭제도 같은 잠금으로 직렬화하여 저장 중 삭제한 문서가 다시 생기는 경합을 막는다.
  기존 문서에 revision 없는 저장도 거부하며 신규 ID 생성은 기존 3인자 API와 호환된다.
  Flutter·웹 브리지·네이티브 서비스가 revision을 전달한다.
  충돌 시 현재 편집은 유지하고 **사본으로 저장**으로 새 ID에 복구할 수 있다.
  기존 파일 포맷을 일괄 변환하지 않고 로드 시 revision을 계산한다.
- F5/P2: 버전별 프로세스 잠금 안에서 설치 유무를 다시 확인하여 먼저 완성된 유효 설치를 재사용한다.
  유효 런타임을 뒤 호출자가 삭제하지 않는다. 실패한 staging은 정리하고 다음 요청은 재시도할 수 있다.
  잠금 파일은 잠금 inode 교체 경합을 막기 위해 유지하며 설치 찌꺼기로 간주하지 않는다.

## 검증

- Python 전체 1,146개: 통과 1,143·조건부 제외 3·실패/오류 0.
  실제 Xvfb/Tk/TkDND/pywebview를 사용하고 Windows COM·레지스트리만 대체했다.
- Flutter 전체 55개 통과. 종료 시 편집 보존·명시적 폐기·dispose 대기·대기 RPC 거부와
  등록되지 않은 모달의 보수적 종료 차단을 신규 시험으로 검증했다.
- 흐름도 모델 Node 시험 6개 통과.
- 생산 Python 88개 AST/컴파일, runpy import_check 및 소스 --self-test 통과. 본체 CRLF 3,323줄 유지.
- Flutter 분석 지적 0개. 운영 웹 번들 재빌드 및 로컬 폰트·라이선스·CanvasKit 자산 검사 수행.
- 신규 Python 회귀 시험: 고정 임시 파일 별칭, 기존 결과 보존, 동시 비덮어쓰기 확정,
  출력 실패 정리, 실제 호스트 종료 승인 경로, 보호 판별 오류·위치 불일치,
  문서 파이프라인의 후속 수정 차단, 두 서비스/두 독립 프로세스의 stale-save 거부,
  동시 첫 설치의 단일 확정·유효 설치 보존·실패 후 재시도.
- 브라우저 검증은 컴파일된 Flutter/iframe과 실제 임시 Python 저장소를 사용한다.
  `scripts/verify_flutter_flow.py`, `scripts/verify_flow_save_race.py`,
  `scripts/verify_flow_conflict_and_close.py`로 일반 저장·PNG·재열기·삭제,
  지연 ACK 중 입력 보존, 충돌 거부/사본 복구 및 종료 취소/명시적 폐기를 확인한다.
  마지막 스크립트의 OS 이벤트는 HTTP 어댑터로 모사하며 실제 Windows 이벤트를 실행한 것은 아니다.

## 남은 실기기 검증

- Windows 한/글 COM 문서 조판·WebView2 X/Alt+F4·tldraw 네이티브 WebView와
  PyInstaller EXE는 이 Linux 환경에서 실행하지 못했다.
- 위 항목은 소스/회귀 시험으로 해결한 F1~F5와 구분하는 배포 전 실기기 검증 게이트다.
  해당 실행 결과 없이 Windows 배포 안정성을 모두 확인했다고 판단하지 않는다.
- 현재 운영 경로는 Flutter Web + WebView2 + 숨김 Tk/COM이며,
  별도 네이티브 시제품의 `engine_ready=False` 계약은 유지한다.
