## 1. 지금 화면의 문제

| # | 문제 | 원인(코드) | 사용자가 겪는 일 |
|---|---|---|---|
| P1 | 파일 형식 변환에 맞는 진행 안내가 없음 | `MODE_GUIDES`에 `file_format`이 없어 `all`로 대체되고, 변환 작업자(`파일포맷_변경_시작.worker`)는 `guide` 신호를 보내지 않음 | PDF로 바꾸는 중인데 '준말 정리·자간 조정…' 13단계가 0/13인 채로 멈춰 보임 |
| P2 | 제목 문구가 모든 기능에서 같음 | `progress()`의 제목이 '문서를 정리하고 있어요'로 고정 | 변환 중에도 '정리'라고 표시됨 |
| P3 | 끈 단계도 목록에 남음 | `guide_steps(mode)`가 세부 작업 선택(`stage_choices`)·카드 옵션(표 제외·페이지 맞춤 제외)을 보지 않음 | 진행 막대가 건너뛰기 때문에 갑자기 뛰고, '일부 단계는 건너뛸 수 있어요'라는 변명 문구가 필요함 |
| P4 | 여러 문서의 진행이 보이지 않음 | 문서마다 `step_reset`으로 단계를 다시 시작하지만, 화면에는 문서 순번이 없음 | 5개 중 몇 번째인지 알려면 상태 한 줄(`status`)을 읽어야 함 |
| P5 | 단계 결과가 없음 | 안내는 '하고 있어요' 문장뿐이고 끝난 단계의 숫자를 보내지 않음 | 무엇이 바뀌었는지 결과 화면이나 로그에서만 알 수 있음 |
| P6 | 단계 문장이 길어 한눈에 읽기 어려움 | 안내 문장 하나가 제목과 설명을 함께 맡음 | 13줄짜리 긴 문장 목록이 됨(키오스크 원칙인 '짧은 이름 + 지금 단계만 설명'과 맞지 않음) |

## 2. 공통 틀(네 기능이 함께 쓰는 부품)

```
┌──────────────────────────────────────────────────────────┐
│ [기능 배지] 자간 정리            문서 2 / 5 · 3분 12초 경과    │ ← ProgressHeader
│ 보고서_10월.hwpx                                            │
│ ████████████░░░░░░░░  48%                                │ ← 전체 진행 막대
├──────────────────────────────────────────────────────────┤
│ ✓ 열기                                                    │ ← StepList
│ ✓ 기존 자간 초기화        문단 214개 0%로                 │   (끝난 단계: 결과 한 줄)
│ ● 본문 자간 조정                                          │   (지금 단계: 설명 펼침)
│   줄 끝에서 단어가 갈라지지 않게 글자 간격을 맞추고 있어요.    │
│   [ 갈린 줄 37 → 12 ]                                      │ ← MetricChip(기능별 지표)
│ ○ 표·글상자 자간                                          │
│ ○ 저장·검사                                               │
├──────────────────────────────────────────────────────────┤
│ 상세 작업 로그                                 [ 중단 ]     │
└──────────────────────────────────────────────────────────┘
```

- **단계는 '짧은 이름(2~8자) + 지금 단계에서만 펼치는 한 줄 설명 + 끝난 단계의 결과 한 줄'** 세 가지로 나눈다.
- **목록은 시작할 때 확정한다.** 실제로 켜진 세부 작업과 카드 옵션으로 단계를 걸러 내고, 끈 단계는 목록에 넣지 않는다(P3).
  실행 중에 조건이 맞지 않아 건너뛴 단계(예: 표가 없음)는 `건너뜀` 회색 표시로 남긴다.
- **진행 막대 = (끝난 문서 수 + 지금 문서의 단계 진행 비율) ÷ 전체 문서 수**(P4). 단계 진행 비율에는 단계 무게를 쓴다.
  무게는 단계 시간 기록(`단계시간_구간` 로그)의 평균에서 정하고, 무게가 없으면 같은 무게로 둔다.
- **제목 문구는 기능별로 다르게 쓴다**(P2). 표 3 참고.
- 끝나면 기능별 **요약 카드**를 1~2초 보여 준 뒤 결과 확인으로 넘어간다(지금의 자동 이동은 유지).

| 기능(내부 모드) | 배지 색 | 진행 중 제목 | 끝 제목 |
|---|---|---|---|

## 3. 기능별 맞춤 설계

### 3-1. 자간 정리(`spacing`): 숫자가 줄어드는 과정을 보여 준다

이 기능의 목적은 **줄 끝에서 단어가 갈라지는 곳을 없애는 것**이다. 그래서 화면 중심에 '갈린 줄' 숫자를 두고,
그 숫자가 줄어드는 과정을 보여 준다.

| 순서 | 단계 이름 | 연결 세부 작업 키 | 지금 단계 설명 | 끝난 단계 결과(예) |
|---|---|---|---|---|
| 1 | 열기 | (항상) | 문서를 열고 작업할 준비를 하고 있어요. | 7쪽 · 문단 412개 |
| 2 | 기존 자간 초기화 | `reset_spacing` | 예전에 넣은 자간을 0%로 돌려 여유를 되찾고 있어요. | 문단 214개 0%로 |
| 3 | 본문 자간 조정 | `body_spacing`, `word_check` | 줄 끝에서 단어가 갈라지지 않게 글자 간격을 맞추고 있어요. | 갈린 줄 37 → 0 |
| 4 | 표·글상자 자간 | `control_spacing`, `control_word_check` (카드 '표 제외'를 켜면 뺌) | 표와 글상자 안도 같은 방식으로 다듬고 있어요. | 칸 58개 조정 |
| 5 | 짧은 줄 모으기 | `short_line`, `control_short_line` | 한두 글자만 남은 마지막 줄을 앞줄로 모으고 있어요. | 짧은 줄 9곳 → 1곳 |
| 6 | 내어쓰기 맞춤 | `hanging_indent`(이 작업에서 켜진 경우) | 둘째 줄 시작 위치를 가지런히 맞추고 있어요. | 문장 31개 |
| 7 | 저장·검사 | (항상) | 새 파일로 저장하고 원본과 글자가 같은지 확인하고 있어요. | 본문 일치 100% |

- **지표 칩:** 갈린 줄 `처음 → 지금`, 짧은 줄 `처음 → 지금`. 3·5단계에서만 보인다.
- **요약 카드:** "갈린 줄 37곳을 0곳으로, 짧은 줄 9곳을 1곳으로 줄였어요. 자간을 바꾼 문단 132개."
- **남은 문제가 있으면** 요약 카드에 `남은 1곳 보기`(결과 화면의 검수 목록으로 연결)를 둔다.

### 3-2. 서식 통일(`unify`): 무엇을 기준으로 맞췄는지 먼저 보여 준다

이 기능은 **문서에서 가장 많이 쓴 서식을 기준으로 다른 문장만 고친다**(서식통일 설계 원칙). 그래서 사용자가 가장
궁금한 것은 '무엇을 기준으로 잡았나'와 '몇 문장만 고쳤나'이다. 조사 단계가 끝나면 대표 서식을 칩으로 보여 준다.

| 순서 | 단계 이름 | 연결 세부 작업 키 | 지금 단계 설명 | 끝난 단계 결과(예) |
|---|---|---|---|---|
| 1 | 열기 | (항상) | 문서를 열고 원본 쪽 구성을 기록하고 있어요. | 7쪽 · 보고서 2건 |
| 2 | 대표 서식 찾기 | `style_unify`(조사) | 항목기호별로 가장 많이 쓴 서식을 찾고 있어요. | 대표 서식 칩(아래) |
| 3 | 다른 문장 고치기 | `style_unify`, `unify_full_format`, `unify_spacing` | 대표와 다른 문장만 고치고, 맞는 문장은 그대로 둬요. | 다른 문장 23개 중 23개 수정 · 그대로 389개 |
| 4 | 표 서식 맞추기 | `table_style`, `table_unify` | 같은 종류 표끼리 글꼴·크기가 다른 칸을 맞추고 있어요. | 표 6개 중 2개 · 꾸민 표 1개 보호 |
| 5 | 쪽 구성 맞추기 | `page_layout_keep`, `page_fit`(카드 '페이지 맞춤 제외'를 켜면 뺌) | 결과 쪽 수가 원본과 같도록 배치하고 있어요. | 원본 7쪽 → 결과 7쪽 |
| 6 | 저장 | (항상) | 새 파일로 저장하고 있어요. | 저장됨 |
| 7 | 다시 열어 검수 | (항상) | 저장한 결과를 다시 열어 서식이 맞았는지 확인하고 있어요. | 불일치 0건 |

- **대표 서식 칩(2단계가 끝나면):** `□ 휴먼명조 15pt 굵게` · `○ 휴먼명조 15pt` · `- 휴먼명조 13pt` …
  (항목기호마다 칩 1개, 표본 비율이 낮으면 `△ 표본 적음` 표시).
- **보호 표시:** 사용자가 꾸민 표(장식 막대 표·단위 캡션 표)를 건드리지 않았다면 4단계 결과에 '꾸민 표 n개 보호'를 쓴다
  (사용자 규칙 2026-10-15을 눈으로 확인하게 함).
- **요약 카드:** "412문장 중 23문장만 대표 서식으로 고쳤어요. 쪽 수는 원본과 같은 7쪽이에요."

### 3-3. 한 번에 적용(`all`·`format`): 큰 4마디 + 펼치는 세부 단계

세부 작업이 20개가 넘어 목록을 그대로 늘어놓으면 읽을 수 없다. 그래서 **큰 마디 5개**로 묶고, **지금 마디만 펼쳐**
세부 단계를 보여 준다. `format`(자간 조정 제외)이면 '글자 간격' 마디를 통째로 뺀다.

| 마디 | 이름 | 묶는 세부 작업 키 | 마디 결과(예) |
|---|---|---|---|
| A | 문서 구조 정리 | `abbreviation`, `text_table_convert`, `asterisk_superscript`, `attachment_font`, `pre_format` | 준말 12개 풀어 씀 · 박스 표 1개 변환 |
| B | 표준 서식 입히기 | `standard_format`, `normalize_space`, `punctuation_space`, `parenthesis`, `style_unify`, `star_align` | 문단 412개에 '마포구 보고서' 서식 |
| C | 표 정리 | `table_style`, `table_width`, `precise_table`, `table_format`, `single_cell_spacing`(카드 '표 제외'면 마디 전체를 뺌) | 표 6개 서식 · 꾸민 표 1개 보호 |
| D | 글자 간격(`all`만) | `reset_spacing`, `body_spacing`, `short_line`, `control_spacing`, `control_short_line`, `word_check`, `control_word_check`, `hanging_indent`, `supplement_indent` | 갈린 줄 37 → 0 |
| E | 쪽 배치·저장 | `page_fit`, `page_group`(카드 '페이지 맞춤 제외'면 뺌), 저장, 최종 검수 | 9쪽 → 8쪽 · 검수 96.5점 |

- **머리 줄에 서식 기준 이름**을 표시한다: `서식 기준: 마포구 보고서(기본)`.
- **2회 처리**를 고른 경우 머리 줄에 `1회차 / 2회차`를 붙인다(`문서_처리_1회`의 `회차`·`총회차`).
- **쪽 범위 작업**이면 머리 줄에 `3~5쪽만`을 표시하고, 구조 변환 마디(A)를 '범위 작업에서는 건너뜀'으로 둔다.
- **요약 카드:** 쪽 수 변화, 최종 검수 점수(`최종검수['score']`), 자간을 포함했으면 갈린 줄 숫자.

### 3-4. 파일 형식 변환(`file_format`): 단계 목록 대신 파일 대기열

변환은 **문서 하나하나가 짧고 단계가 결과 형식에 따라 다르다.** 그래서 단계 목록 대신 **파일 대기열**을 주 화면으로 하고,
지금 변환 중인 파일 줄에만 작은 단계 점(●○○)을 보여 준다(P1 해결).

```
┌──────────────────────────────────────────────────────────┐
│ [변환] 5개 파일을 PDF로 바꾸고 있어요       2 / 5 · 40%      │
│ ████████░░░░░░░░░░░░                                     │
├──────────────────────────────────────────────────────────┤
│ ✓ 업무계획.hwp        → 업무계획.pdf        [열기]          │
│ ● 회의자료.docx       ●●○ 한/글로 PDF 저장 중               │
│ ○ 현황표.xlsx         대기                                 │
│ ✕ 스캔본.png          글자를 읽지 못했어요 · 원본 그대로 둠   │
│ ○ 안내문.hwpx         대기                                 │
└──────────────────────────────────────────────────────────┘
```

결과 형식별 파일 1개의 단계:

| 결과 형식 | 단계 점(순서) | 쓰는 도구 |
|---|---|---|
| HWPX | 읽기(kordoc) → 한/글 문서로 만들기 → 저장 | kordoc |
| PDF | (HWPX가 아니면 HWPX로 바꾸기) → 한/글로 열기 → PDF로 저장 | kordoc + 한/글 COM |
| DOCX·EPUB | 읽기(kordoc Markdown) → Pandoc 변환 → 저장 | kordoc + Pandoc |
| 그림(PNG 등) | 한/글로 열기 → 쪽마다 그림 저장(`쪽 3/7`) | 한/글 COM |

- **실패는 그 줄에 바로 이유를 쓴다**(지금은 `document_error`가 로그로만 감). 원본은 항상 그대로라는 점을 함께 쓴다.
- 재생성 경로(kordoc → HWPX)는 레이아웃을 완전히 되살리지 못하므로, 그 경로를 쓰는 파일 줄에 `모양이 조금 다를 수 있어요` 표시를 한다.
- **요약 카드:** "5개 중 4개를 PDF로 바꿨어요. 1개는 바꾸지 못했어요(원본은 그대로)." + `폴더 열기`.

### 4-2. 새 큐 신호(엔진·작업자 → `legacy.py`)

| 신호 | 보내는 곳 | 내용 |
|---|---|---|
| `("doc_begin", index, total, name)` | `_문서_처리_본체` 시작, 변환 작업자 파일마다 | 문서 순번·이름(P4) |
| `("guide", 단계명)` | 기존 `단계표시` + **변환 작업자에도 추가** | 단계 이동(P1) |
| `("guide_result", 단계명, 결과문구)` | 단계가 끝나는 곳(통계를 이미 로그에 남기는 곳) | 끝난 단계 결과(P5) |
| `("guide_metric", 이름, 처음값, 지금값)` | 자간 조정 반복, 서식통일 수정 | 지표 칩 |
| `("guide_skip", 단계명, 이유)` | 조건이 맞지 않아 건너뛸 때 | `건너뜀` 표시 |
| `("file_state", 경로, 상태, 이유)` | 변환 작업자 | 대기열 줄 상태(대기·진행·완료·실패) |

- 결과 문구는 **이미 로그에 쓰고 있는 숫자**를 재사용한다(예: `표 칸 너비 맞춤: 표 {count}개`, 자간 초기화 통계,
  서식통일 수정 수). 새로 세는 작업은 넣지 않아 처리 시간이 늘지 않게 한다.
- `legacy.py`는 받은 값을 `self._안내결과`·`self._안내지표`·`self._문서순번`에 모으고, `desktop_web_ui.get_state()`가
  `guide_state(...)`에 넘긴다. Tk 화면(`stage_board`)은 바꾸지 않는다.

### 4-3. Flutter(`main.dart`)

- `progress()`를 `switch (mode)`로 나누되 부품은 공통으로 쓴다: `ProgressHeader`, `StepList`(마디 펼침 지원),
  `MetricChips`, `FileQueue`, `SummaryCard`.
- 새 필드가 없으면(예전 엔진) 지금 화면을 그대로 그린다(하위 호환).
- 접근성: 단계가 바뀔 때 `Semantics(liveRegion: true)`로 지금 단계 이름을 읽어 준다. 색만으로 상태를 나타내지 않고 ✓●○✕ 기호를 함께 쓴다.
