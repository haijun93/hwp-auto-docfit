# 업무 흐름도 템플릿 명세 (시제품)

아래 템플릿은 편집 가능한 작성 예시이며 법령·기관별 절차·결재 규정을 확정하지 않는다. 기본은 흰 바탕, 절제된 파랑·회색 계열, 한국어 문구, 세로 흐름이다.

| ID | 템플릿 | 기본 흐름 | 구현 상태 |
|---|---|---|---|
| `general` | 일반 행정업무 처리 | 접수 → 검토 → 결재 → 시행 → 완료 | 구현 |
| `complaint` | 민원 처리 | 접수 → 담당자 배정 → 내용 검토 → 예: 보완 요청·재검토 / 아니오: 결과 통보 | 구현, 분기 예시 |
| `contract` | 계약 및 발주 | 수요 발생 → 발주 검토 → 계약 방법 결정 → 계약 체결 → 검사·검수 | 구현 |
| `direct_contract` | 수의계약 검토 | 계약 대상 확인 → 금액·사유 검토 → 적정성 판단 → 계약 진행 | 구현 |
| `budget` | 예산 집행 | 집행 계획 → 예산 확인 → 품의 → 지출 원인행위 → 대금 지급 | 구현 |
| `subsidy` | 지방보조금 관리 | 공모·신청 → 심사 → 교부 결정 → 사업 수행 → 정산 → 사후관리 | 구현 |
| `construction` | 공사 관리 | 사업 계획 → 설계 → 발주 → 착공 → 준공 검사 → 대금 지급 | 구현 |
| `permit` | 인허가 처리 | 신청 접수 → 요건 검토 → 보완 여부 판단 → 승인·반려 결정 → 결과 통보 | 구현 |
| `approval` | 보고 및 결재 | 자료 작성 → 담당 검토 → 팀장 검토 → 부서장 결재 → 시행 | 구현 |
| `incident` | 사고·민원 대응 | 상황 접수 → 긴급성 판단 → 초기 조치 → 보고 → 사후관리 | 구현 |

## 편집 데이터

다이어그램은 tldraw SDK의 versioned store snapshot (`document`, `session`)으로 저장한다. ID는 32자리 hex이고 metadata는 `{version, id, name, updated_at}`를 기록한다. 템플릿을 적용하면 현재 선택 도형을 지운 뒤 새 도형·화살표를 생성한다. 전환 전에 Flutter에서 미저장 변경사항 확인을 받는다.

추가 단계: 카드 썸네일·검색·분류 필터·즐겨찾기·사용자 템플릿 등록, 연결선의 도형 자동 연결과 분기 라벨 위치 보정, 사용자 템플릿 schema migration. 현재 템플릿 생성은 최소 동작 예시이며 개별 기관의 세부 업무 흐름을 자동 검증하지 않는다.
