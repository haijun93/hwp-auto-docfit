# 한글문서 후처리 도구

한글 2020의 HWP/HWPX 문서를 편집하는 Windows용 Python 프로그램입니다.
바이너리 HWP 입력은 원본을 변경하지 않고 작업용 HWPX로 변환하며, 모든 처리 결과는 HWPX로 저장합니다.
실행 파일은 `hwp-auto-docfit.py`이며, 프로그램 버전은 `1.68 Beta 1`입니다(베타 브랜치 `main`; 새 기능 시험판은 `alpha` 브랜치).
기존 사용자 설정과 자동 업데이트 호환성을 위해 실행 파일명 `HWP_AutoDocFit.exe`,
설정 폴더명 `HwpAutoDocFit`, 보안 모듈 등록명은 유지합니다.

서식 예시 문서를 드래그하거나 **서식 복사하기**를 누르면 문단의 들여쓰기, 글꼴,
글자 크기, 문두기호를 중심으로 1~5단계와 부연설명을 분석합니다.
문단 위 여백은 동일 역할에서도 달라질 수 있으므로 보조 정보로 표시합니다.
분석된 5대 시각 요소와 논리적 구조는 스크롤 가능한 확인 창에서 검토한 뒤
승인해야 서식 프로필로 저장·적용됩니다. `ㅁ`·`ㅇ`·`-`·부연설명으로 시작하는
`ㅇ` 본문과 다음 `ㅇ`/`□` 전까지 이어지는 `-` 내용·부연설명을 한 묶음으로 검사합니다.
`□` 소제목은 첫 `ㅇ` 묶음까지 연결합니다. 묶음이 서로 다른 쪽으로 갈라지면 줄간격 재배치를 시도하고(줄 수가 많은 쪽으로
보내되, 줄간격이 이미 최소/최대라 움직일 수 없으면 반대 방향으로 보완), 양쪽 모두 해결되지 않은
경우 검수 문제로 기록합니다.
`□`부터 다음 `□` 전까지의 논리묶음은 `□`·`ㅇ`마다 논리단위를 나누고(`-`·`*`는 바로 앞 단위에 포함:
`ㅇ-*` = `ㅇ`, `□*` = `□`), 논리단위가 5개 이하이면 묶음 전체를 한 쪽에 모읍니다. 앞쪽에서 시작한 단위 수가
뒤쪽 이상이면 앞쪽으로 당기고(`□ㅇ/ㅇㅇ` → `□ㅇㅇㅇ/`, `□ㅇ-/--` → `□ㅇ---/`), 적으면 뒤쪽으로 밉니다
(`□ㅇ/ㅇㅇㅇ` → `/□ㅇㅇㅇㅇ`). 6개 이상이면 이 규칙을 적용하지 않고 기존 방식대로 `ㅇ` 단위(`ㅇ`와 `-`·`*`)를 한 쪽에 모으며,
`□` 단위는 첫 `ㅇ` 단위와 같은 쪽에 둡니다.
줄간격 조정으로 옮기지 못한 묶음은 앞쪽에 남은 줄이 반 쪽 이하일 때 `문단 앞에서 쪽 나눔`으로 다음 쪽에 보내고,
한 쪽보다 긴 묶음(쪽 첫 줄에서 시작해도 넘치거나 전체 줄 수가 한 쪽보다 많음)은 규칙 적용에서 제외해 검수 보고서에 참고로만 적습니다.
그 밖의 상·하위 항목 전체를 한 쪽에 강제하지 않으며,
최종 결과를 저장할 때 문단 페이지 보호 속성은 모두 해제합니다.

실행창 카드 위의 **빠른 선택**에는 두 가지 조합이 있습니다. **기본후처리**는 자간 정리에 서식통일을, **전문후처리**는 한 번에 정리(자간+서식)에 서식통일을 더해 실행합니다. **서식통일**은 여러 사람이 쓴 문서를 합친 문서에서 문두기호(□·ㅇ·-·*·※)별로 본문 글자의 글꼴·크기·장평을 모아 가장 많이 쓴 값(같은 기호 문단 3개 이상, 60% 이상일 때)을 대표 스타일로 정하고, 대표와 다른 문단만 대표 값으로 맞춥니다. 제목·날짜 같은 일반 문단과 표는 대상이 아니며 라벨·굵기는 건드리지 않습니다. 기준이 "이 문서 자신"이라 세부 작업에서 기본 꺼짐이고, 카드를 직접 고르면 꺼집니다.

실행창의 **자간 정리·서식 정리·한 번에 정리** 카드에는 각각 **세부 작업…** 버튼이
있습니다. 실제 실행 순서대로 나열된 작업을 켜거나 끌 수 있으며, 선택은 앱을 닫을
때까지 해당 작업 모드에 적용됩니다. 파일 열기·결과 저장·무결성 검사는 이 목록에서 제외됩니다.

## 주요 기능

- 파일·폴더 드래그 앤 드롭과 여러 문서 일괄 처리, '텍스트 붙여넣기'로 파일 없이도 텍스트를 목록에 바로 추가(자동 저장 폴더를 지정하면 즉시 HWPX로 변환, 비워두면 저장 위치를 직접 골라 .txt로 추가)
- '아웃라이너로 작성': 워크플로위처럼 Tab/Shift+Tab으로 계층을 넣고 빼며 글을 쓰고, ㅁ/ㅇ/-/• 개조식 문두기호로 바로 문서 목록에 추가. 접기/펼치기(Ctrl+↑/↓), 확대(Alt+→/←), 항목 이동(Alt+Shift+↑/↓), 완료 표시(Ctrl+Enter), 메모(Shift+Enter, 개조식에서 ※ 부연설명), 검색(Ctrl+F), 저장·열기(Ctrl+S/O)를 지원하고, 창을 닫으면 쓰던 글을 자동 저장해 다음에 이어 씁니다
- HWP/HWPX 외 TXT·MD·DOC(X)·PDF 파일도 추가해 처리 가능. 자간·서식 작업 전에 작업용 HWPX로
  자동 변환하며 결과물은 항상 HWPX로 저장(MD/DOC(X)/PDF는 선택형 kordoc 엔진 필요, MD는
  엔진이 없으면 서식 없이 텍스트로만 변환). PDF는 텍스트층 없는 스캔 페이지를 내장 OCR로
  인식하고, 문서 안 이미지는 결과 HWPX에 실제로 임베드해 내용 손실을 줄임
- 표준서식 적용 시 문두기호 문장(`□`·`ㅇ`·`-`·`*`·`※` 등) 사이에 빈 줄로 띄운 간격을 모두 지우고 문단 위 여백으로 대신합니다(기본 켜짐, 설정 > 서식 정리 > 보고서 표준서식에서 켜고 끔). 앞뒤가 모두 문두기호 문장인 빈 줄과 문서 끝 빈 줄(빈 쪽 방지)만 지우며, 표·그림이 든 문단, 제목·날짜 주변 빈 줄, 제출서식에서 `○`·`*`처럼 기호만 있는 작성란 앞뒤의 빈 줄(작성 여백)은 그대로 둡니다
- 열거 뒤의 `등`은 바로 앞 어절과 한 어절로 묶어 자간을 조정합니다. 예: `사과, 바나나 등으로`에서 `바나나 등으로`가 `바나나 | 등으로`로 갈라지면 단어 분리로 보고 조정. `등`에 조사만 붙은 경우(`등`, `등의`, `등으로`, `등을` 등)만 해당하며 `등록`·`등급` 같은 낱말은 제외
- 열거의 `단어 + 빈칸 + 숫자 + 쉼표`도 한 어절로 묶어 자간을 조정합니다. 예: `수원 2, 서울 4, 용인 1등으로 구성`에서 `수원 2,`·`서울 4,`가 각각 한 어절이라 `수원 | 2,`로 갈라지면 단어 분리로 보고 조정. 쉼표 없이 끝나는 마지막 항목(`용인 1등으로`)도 바로 앞 항목이 `서울 4,`처럼 숫자+쉼표로 끝나면 한 어절로 묶음. `1, 2, 3`처럼 숫자끼리의 열거나 열거가 아닌 `대회에서 1등으로`는 묶지 않음
- 좁은 표 칸에서 줄 첫머리부터 시작한 단어가 칸 폭보다 길어 넘치면(넘친 부분이 그 줄 글자 수의 20% 초과, 예: 5자 칸의 `질그랭이거|점센터`) 어떤 조정으로도 풀 수 없으므로 시도하지 않고, 검수 보고서에는 문제가 아닌 `칸 폭보다 긴 단어`(적용 제외)로 적습니다
- 표 칸의 자간 조정 한도는 `표 재시도` 설정(기본 5단계)을 쓰되, 한 줄이 20자 이상인 넓은 칸은 본문처럼 `본문 재시도` 한도를 씁니다(좁은 칸은 자간을 많이 바꾸면 글자가 뭉개지므로 표 한도 유지)
- 숫자·기호만으로 된 표 칸(통계표의 수치 칸 등)과 그런 칸으로만 된 표는 어절이 없으므로 자간 초기화·자간 조정·문장부호 병합·단어 분리 검수에서 건너뜁니다(표 글꼴 등 서식 적용은 그대로 함)
- 화면줄 경계에서 갈라진 어절의 이동 방향: 문단 마지막 줄에 남는 글자가 빈칸 포함 5자 미만이면 앞줄로 당기고, 그 외에는 글자 수가 많은 쪽으로 붙임(같으면 앞줄로 당김). 예: `전기|버스`는 앞줄로 당기고, `실|질적인`은 `실`이 있는 줄의 자간을 넓혀 `실`을 다음 줄로 밀어냄. 정한 방향이 한도 안에서 안 되면 반대 방향으로 보완
- 줄 끝 단어 분리를 줄이기 위한 자간 조정(괄호 안 공백을 포함한 부연 설명도 한 어절로 처리). 자간만으로 안 되면 장평(글자 가로비율)을 최대 10단계(90%까지) 추가로 줄이고, 긴 단어 전체가 통째로 다음 줄로 밀려 양쪽정렬 간격이 벌어지는 경우도 감지해 끌어올림(단, 끌어올릴 단어가 5자 이하일 때만 시도하고, 자간·장평 한도는 이번 시도분만이 아니라 그 구간에 이미 적용된 값까지 합쳐 최종 기준으로 지킴 — 여러 단계·회차에 걸쳐 조금씩 계속 눌리는 것을 방지)
- 곧은 큰·작은따옴표(", ')를 한글 표준 둥근따옴표(" ", ' ')로 자동 통일(숫자 뒤 발·분 표기는 제외), 문두기호 뒤 공백은 탭·전각공백도 표준 반각 공백 1칸으로 정리
- 날짜·기간·시간의 하이픈(-)·엔대시(–)·엠대시(—)를 물결표(~)로 통일, 날짜 뒤 빠진 온점과 요일 괄호 앞뒤 온점 위치 보정(전화번호·법령 조항 등 점 없는 하이픈은 제외)
- 공문서 항목 인식, 문장 줄 병합, 세트 문장의 같은 페이지 유지
- 마지막 쪽에 몇 줄만 남았으면 본문 줄간격은 그대로 두고 항목기호 문단의 '문단 아래 간격'만 1pt씩(최대 10pt) 줄여 앞쪽 쪽으로 당겨 페이지 수를 맞춤(세부 작업 '문단 아래 간격 페이지 맞춤'으로 켜고 끌 수 있음)
- 보고서 표준서식, 표·셀 서식, 괄호·공백 정리
- (실험적, 기본 꺼짐) 표 구조 정밀 조정 3종: 셀 텍스트가 2줄로 넘어가면 안쪽 여백을 1.8mm→0mm까지 축소 / 표 전체 너비를 본문 가용 너비에 비례 맞춤 / 표 테두리를 삼선표(외곽 0.5mm·헤더 이중선·내부 0.12mm·좌우 외곽선 없음)로 통일. 코드의 표_셀여백_축소_사용/표_열너비_맞춤_사용/표_테두리_통일_사용을 켜야 실행되며, 실제 한/글에서 검증 전이라 사본으로 먼저 확인 권장
- 기본 좌우 여백 20mm(예시 문서에서 복사한 서식은 원본 여백 유지), 연도 앞 작은따옴표 `’` 통일
- 문단 위 간격은 깊은 항목에서 얕은 항목으로 복귀할 때 설정 배율만큼 확대(기본 150%, 100%는 기존 방식)
- HWPX ZIP bomb·경로 조작·CRC·필수 구조 사전 검사
- 처리 전후 본문·표·이미지·섹션 무결성 비교와 JSON 보고서
- 작업 종료 시 목표 대비 완료율·결과물·세부 작업·무결성을 종합한 최종 달성도 평가와 `(최종검수).json` 보고서
- HWP/HWPX 문단과 표를 UTF-8 Markdown으로 내보내기
- 예시 문서 드래그 앤 드롭 서식 분석과 사용자 서식 프로필 저장·재사용
- 일반 표의 셀별 글꼴·문단·테두리·음영·여백·크기·병합 구조 정밀 복제
- 선택형 kordoc v4 엔진을 이용한 공통 문서 IR, 중첩 표 Markdown, 표 분류와 블록·셀 신구대조
- 누름틀·양식 필드 분석 및 서식 보존 채우기·텍스트 패치, 공문서 표기법 검수
- 페이지별 Markdown, RAG 구조 청크 및 보고서·계획서·기안문 HWPX 생성
- 글자색 표시, 결과 검수, 진행률과 작업 로그
- 설정 저장 및 작업 중단(중단 후 실행 버튼을 누르면 완료된 문서는 건너뛰고 이어서 진행)
- 전체 파이프라인은 기본 1회 실행하며, 세부 설정에서 필요한 경우에만 2회 반복 가능
- 저장 후 결과를 다시 열어 제목 고립·문단 쪽 분리·본문/컨트롤 단어 분리를 읽기 전용으로 검사합니다. 선택적 다음 단어 당김의 미적용은 오류 통계에서 제외하고 별도로 기록합니다.
- 문두기호별 굵게 일관성(기본 켜짐, 설정 > 서식 정리 > 항목 이름 강조): 같은 문두기호의 라벨(`- 추진부서 :`, `- (운영방식)`)이 굵게 되면, 그 기호의 다른 문단 머리말도 굵게 맞춤. 예: `- 조례제정 (무료 셔틀버스 …)`의 `조례제정`. 부연설명 괄호와 머리말 없는 일반 문장은 제외
- 문두기호·괄호라벨 뒤 본문이 낫표(`「`, `『`)로 시작하면 내어쓰기 기준은 낫표가 아니라 바로 다음 글자입니다. 예: `ㅇ (개요)「공유재산법 시행령」…`은 `공`에 맞춤
- 자간을 줄이거나 넓힌 뒤에는 내어쓰기를 다시 적용하고 자간을 재검사합니다(최대 3회). 2차부터는 내어쓰기 값이 실제로 바뀐 문단만 단어 분리를 검사하고, 선택적 '다음 단어 당김'은 하지 않습니다(1차에서 방향 규칙대로 밀어 둔 어절을 다시 당기지 않도록)
- 자간 초기화·단어 보정·짧은 줄 병합에서는 내어쓰기 기준점 앞의 문두기호·라벨·공백을 제외합니다. 자동 보조 장평 조정에서도 같은 선행부를 보호합니다.
- 세부 설정의 '자간 정리' 탭은 실행창 '세부 작업'과 같은 7단계로 구성되며 서로 반영됨(짧은 마지막 줄 병합 글자 수 포함)
- 세부 설정의 '서식 정리'·'내어쓰기' 탭은 실행창 '세부 작업'과 같은 10단계로 구성되며 서로 반영됨(문서 스타일(계층구조) 상세 수정, 문두기호별 글꼴·크기·굵게, 문단위 여백 포함)
- 로컬 문서 구조·가독성 검토: 계층 훑어보기, 기호·서식 편차와 표현 명료성 후보, 읽기 목적별 검토
- 붙여넣은 텍스트 정리: 생성형 AI 채팅창(제미나이·클로드·챗GPT 등)에서 복사한 답변의 마크다운 기호를 지우고 흐트러진 띄어쓰기·줄바꿈을 복원. '개조식으로 변환'은 제목·글머리 기호의 계층 구조를 ㅁ/ㅇ/-/• 문두기호로 바꾸며, 워크플로위 등을 브라우저로 통째로 복사해 줄바꿈이 공백으로 뭉개진 경우도 항목별로 펼쳐 인식
- 라벨 입력 모드: `제목: / 상자: / 네모: / 원: / 바: / 당구: / 주석: / 참고: / 표:` 줄머리 라벨이 있는 텍스트는 계층을 추론하지 않고 라벨대로 개조식으로 바꿉니다. 라벨 없는 `일시: …`는 `ㅇ (일시) …`가 됩니다. '텍스트 붙여넣기'로 문서를 추가하면 제목·상자·참고는 1×1 상자 표로, 표 줄은 표로 넣어 기존 제목 서식이 그대로 적용됩니다.
- AI 프롬프트: 붙여넣은 텍스트 정리 > 'AI 프롬프트…'에서 추진계획·행사·회의·심사·공모·결과·검토 보고, 보도자료 요지 등을 라벨 형식으로 답하게 하는 프롬프트를 복사하고, 챗GPT·클로드·제미나이를 브라우저로 엽니다(앱은 AI에 아무것도 전송하지 않음)
- 작성 도우미(파일 목록 옆 버튼): 금액 한글 병기(`금1,500,000원(금일백오십만원)`)·쉼표·천원 단위, 날짜 요일 붙이기·고치기와 이번/다음 달 금요일·기간·날짜 차이, 붙여넣은 표의 열 합계·평균·행 합계·구성비, 만 나이·주민번호→생년월일·주민번호 가리기, 번호 다시 매기기(1. 가. ① Ⅰ. 등), 회신공문 본문 생성
- 기관 서식: 작성 도우미 > '기관 서식'에서 기관 문서의 스타일을 전수 분석해 보고서(`_스타일분석.md`)와 예시 서식(`_서식예시.hwpx`)을 만들고 기관 이름을 붙여 문서 서식으로 등록합니다. 서식 목록에는 기본 서식 다음에 `[기관] 이름` 순으로 묶여 보이며, 서식 이름 바꾸기에서 기관도 바꿀 수 있습니다. 명령줄: `python scripts/style_inventory.py 문서.hwp`
- 서식 정리의 문두기호별 글꼴 선택 목록에 한컴오피스 전용 번들(HFT) 글꼴도 설치 경로에서 자동으로 찾아 포함

교체하는 것을 권장합니다.

## 설치 및 실행

프로젝트 폴더에서 PowerShell로 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe hwp-auto-docfit.py
```

창에서 HWP/HWPX 파일을 선택하거나 끌어다 놓고, 설정을 조정한 다음 **실행**을 누릅니다.

목록에서 문서를 선택하고 **Markdown 내보내기**를 누르면 원본 폴더에 같은 이름의
`.md` 파일이 생성됩니다. HWPX는 직접 안전하게 분석하며, 바이너리 HWP는 한글 COM으로
임시 HWPX 스냅샷을 만든 뒤 변환합니다. 표는 Markdown 표로, 번호형 제목은 가능한 범위에서
제목 문법으로 변환됩니다.

세부 설정의 **상세 진단 및 문서 무결성 검사**가 켜져 있으면 편집 결과 옆에
`(무결성검사).json` 보고서가 만들어집니다. 이때 **숫자 대조**도 합니다: 표 앞뒤 3문단 안의 본문에서 금액·비율·인원 등 단위가 붙은 수치가 그 표에 같은 단위로(칸의 `4대`, 머리글의 `(억원)`·`(단위: 억원)` 등) 있는지 보고, 없으면 최종검수 보고서에 "확인 필요"로만 적습니다(문서는 고치지 않으며 실패로 치지 않음). 본문 일치도와 문단·표·이미지·섹션 개수 변화를
기록하며, 경고가 있어도 결과를 삭제하지 않으므로 보고서를 확인해 최종 판단할 수 있습니다.
표·이미지·컨트롤(쪽 번호 새로 시작 등)이 줄어든 경우는 내용이 지워진 것으로 보고 경고가 아닌 오류(검사 실패)로 기록합니다.

### 문서 서식 분석과 복제

실행창의 **적용 서식**에서 기본 서식 또는 저장해 둔 사용자 서식을 선택할 수 있습니다. 기존 문서가 없으면 설정 > 서식 정리의 **편집하여 추가…**로 빈 한/글 문서에 예시를 직접 쓰고 **분석 시작**을 눌러 서식으로 등록할 수 있습니다(이름은 첫 문장 앞 8글자, **이름 바꾸기…**로 언제든 수정).
새 서식을 바로 사용하려면 오른쪽 드롭 영역에 예시 HWP/HWPX 문서를 놓습니다. 앱이 페이지
여백, 대표 본문·제목·기호 문단의 글꼴/크기/굵기, 장평·자간·줄간격·문단 모양을 분석합니다.
또한 문서의 모든 일반 표에서 셀별 문자·문단 서식, 테두리·색·음영, 셀 여백과 크기,
행·열 및 병합 좌표를 분석해 사용자 프로필로 저장한 뒤 `서식 정리` 작업에 바로 선택합니다.
적용할 때는 표의 행·열·셀 수, 순번, 첫 셀과 첫 행 텍스트를 조합해 대응 표를 찾으며,
대상 표 내용은 유지한 상태로 서식만 복제합니다.
일반 본문이 전혀 없는 표 전용 문서는 표 본문 셀의 대표 문자 서식(없으면 머리글 셀)을
본문 서식 대체값으로 사용하므로 표만 있는 양식도 프로필로 저장할 수 있습니다.
세부 설정의 **서식 복사하기**를 이용하면 저장 이름을 직접 지정할 수 있습니다.
복사 전 확인 창에는 1~5단계·부연설명의 계층과 함께
반복·비반복 스타일 변형이 모두 표시됩니다. 글꼴, 크기, 왼쪽 여백, 첫 줄 들여쓰기,
문단 위 여백을 수정한 뒤 확인해야 서식이 저장됩니다. **상세 수정**으로 저장된
사용자 서식을 다시 편집하거나 기본 서식의 사용자 수정본을 만들 수 있고,
**삭제**로 사용자 서식을 지울 수 있습니다. 각 스타일에서 글꼴·크기·들여쓰기·
문단 위 여백의 적용 여부를 따로 선택할 수 있습니다. 같은 문두기호의 변형이
여러 개면 가장 자주 나온 변형을 대상 문서의 적용 기준으로 사용합니다.

서식 프로필은 `%APPDATA%\HwpAutoDocFit\formats`에 JSON으로 저장됩니다. Markdown은 HWP의
정밀 서식 속성과 병합 셀을 표현할 표준 문법이 없어 프로필 저장 형식으로 사용하지 않습니다. JSON은
숫자 단위, HWP 전용 참조 속성 및 셀 구조를 손실 없이 저장하면서 이전 버전 프로필과도 호환됩니다.

### 문서 구조·가독성 검토

실행창의 **문서 구조·가독성 검토…**는 선택한 문서의 HWPX 구조를 읽기 전용으로 분석합니다.
HWP 입력은 임시 HWPX로 변환하며 원본을 변경하지 않습니다. 문서 유형(보고서·계획서·기안문)과
읽기 목적(빠른 의사결정용·상세 설명용)을 선택하면 계층 훑어보기와 검토 후보를 표시합니다.
선택된 서식 프로필이 있으면 그 프로필의 스타일을 비교 기준으로 사용하고, 검토 결과는 JSON으로
저장할 수 있습니다. 위치는 인쇄 쪽 번호가 아닌 HWPX 구역·본문 문단 번호 또는 표 행·열입니다.
문장 의미나 두괄식 적합성은 자동 확정하지 않으며, 원문 수정도 하지 않습니다.

### 공공언어 바로쓰기·한국어 문서 교정

실행창에서 HWP/HWPX 파일을 추가한 뒤 **공공언어·맞춤법 검토…**를 누르면
앱에 내장된 로컬 규칙이 본문과 표 셀의 교정 후보를 일괄 검출합니다. 외부 검사
서비스에 문서 내용을 전송하지 않습니다. 목록에서 승인할 표현만 선택하여
**선택 교정 승인·새 파일 저장**을 누르면 원본은 유지하고 같은 폴더에
`*_공공언어교정.hwpx`를 만듭니다. HWP 입력은 임시 HWPX로 변환한 뒤 검사합니다.

**선택 표현 이후 검색에서 제외**를 누르면 그 표현은 이후 검사에서 빠집니다.
제외 목록은 `%APPDATA%\HwpAutoDocFit\proofreading_exclusions.json`에 저장되고,
**제외 목록 관리**에서 다시 검색하도록 복원할 수 있습니다. 공공언어 교정안은
문맥에 따라 달라질 수 있는 *제안*이며, 내장 규칙만으로 모든 맞춤법 오류를
찾는 것은 아닙니다. 특히 인명·기관명·인용문은 승인 전에 문맥을 확인하세요.

### 붙여넣은 텍스트 정리

실행창의 **붙여넣은 텍스트 정리…**는 제미나이·클로드·챗GPT 같은 생성형 AI 채팅창에서
마우스로 복사한 답변을 대상으로 합니다. 창을 열면 클립보드 내용을 왼쪽 입력란에 자동으로
채우며, 직접 붙여넣거나 편집할 수도 있습니다. **한 번에 정리**를 누르면 `**굵게**`, `# 제목`,
`` `코드` `` 같은 마크다운 기호를 지우고, 목록·제목은 각각 문단으로 분리하며, 줄바꿈이 무시되어
한 줄로 뭉쳐진 문장은 다시 자연스러운 문단으로 이어 붙입니다. 백슬래시로 이스케이프된 강조
기호(예: `\*\*굵게\*\*`)도 먼저 풀어낸 뒤 정리하고, 문장 끝에 붙는 `[1]`·`[2][4]` 같은 숫자
전용 각주 표시는 제거하되 `[별표 21의2]`처럼 글자가 섞인 대괄호는 그대로 남깁니다.

**개조식으로 변환** 버튼은 제목(`#`)과 글머리 기호의 계층 구조를 공문서 개조식 문두기호로
바꿉니다. 1단계는 원문에 이미 있는 번호("1.", "2." 등)를 그대로 쓰고 없으면 `ㅁ`을 붙이며,
그 아래는 글머리 기호의 들여쓰기 깊이에 따라 `ㅇ`→`-`→`•`(3단계 이후는 모두 `•`) 순으로
문두기호를 매깁니다. 워크플로위 같은 아웃라이너를 브라우저에서 통째로 복사하면 줄바꿈이 전부
공백으로 뭉개져 한 줄에 " - "만 남는 경우가 있는데, 이때는 계층 깊이까지 복원할 수는 없지만
항목만은 한 줄씩 펼쳐서 `ㅇ`로 표시하고 워크플로위 해시태그(`#표시`)도 정리합니다. 정확한 계층
까지 살리려면 아래 아웃라이너로 직접 쓰거나, 워크플로위의 '내보내기 > 일반 텍스트'처럼 줄바꿈이
보존된 형식으로 붙여넣으세요.

HWP/HWPX 파일이나 한글 프로그램은 전혀 사용하지 않는 순수 텍스트 변환이며, **결과 복사**로
정리된 텍스트를 클립보드에 담아 원하는 곳에 붙여넣을 수 있습니다.

### 아웃라이너로 작성

실행창 '01 정리할 문서'의 **아웃라이너로 작성** 버튼은 워크플로위처럼 계층 구조로 글을 쓰는
창을 엽니다. `Enter`로 같은 계층의 새 항목을 이어가고, `Tab`/`Shift+Tab`으로 바로 위 항목
아래로 한 단계 들여쓰거나 내어씁니다. 저장 형식 자체가 계층 구조를 담은 마크다운(0단계는
`# 본문`, 그 아래는 `- 본문`을 들여쓰기 깊이만큼 겹쳐 표시)이라, **개조식 텍스트로 추가**를
누르면 0단계는 `ㅁ`, 1단계는 `ㅇ`, 2단계는 `-`, 3단계 이후는 모두 `•`로 바꿔 바로 '01 정리할
문서' 목록에 추가합니다. **마크다운으로 추가**를 누르면 원본 마크다운 그대로 추가되어, 고급
문서 엔진(kordoc)이 있을 때 서식을 살려 변환할 수 있습니다.

### 텍스트 붙여넣기로 문서 추가

실행창 '01 정리할 문서'의 **텍스트 붙여넣기** 버튼은 파일 없이 텍스트만으로 문서를
추가합니다. 창을 열면 클립보드 내용을 자동으로 채우며, **자동 저장 폴더**를 지정해 두면
**문서로 추가**를 누르는 즉시 그 폴더에 HWPX로 변환해(배치 자간·서식 작업과는 독립된 한/글
세션을 새로 띄워 사용하므로 다른 작업이 실행 중이 아니어야 합니다) 목록에 추가합니다. 폴더를
비워두면 기존처럼 저장 위치를 직접 골라 .txt로 추가합니다.

## EXE 빌드와 자동 업데이트

`build.bat`을 실행하면 `dist\HWP_AutoDocFit.exe`가 생성됩니다. Pillow와 tkinterdnd2도 EXE에 포함됩니다.

자동 업데이트를 배포하려면 현재 GitLab 프로젝트에 Release를 만들고 다음 규칙을 지킵니다.

- 태그: 현재 앱 버전보다 높은 버전(예: `v1.68`)
- Release 자산 링크 이름: `HWP_AutoDocFit.exe`
- 자산 링크 대상: 빌드한 `HWP_AutoDocFit.exe`를 내려받을 수 있는 URL
- 자동 업데이트를 사용하는 배포 환경에서는 Release API와 자산 링크를 인증 없이 읽고 내려받을 수 있어야 함

배포된 EXE는 시작 후 백그라운드에서 현재 GitLab 프로젝트의 최신 Release를 확인합니다. 새 버전이 있으면 사용자 확인 후 EXE를 다운로드하고 현재 실행 파일을 교체한 뒤 다시 실행합니다. 네트워크 오류나 Release가 없는 경우 앱 실행에는 영향을 주지 않습니다.
결과는 입력 형식과 관계없이 원본과 같은 폴더에 `원본파일명(자간조정).hwpx`로 저장됩니다.
HWP 입력은 임시 작업 공간에서 HWPX로 변환되므로 원본 HWP 파일은 그대로 유지됩니다.

### 고급 문서 도구

실행창의 **고급 문서 도구**에서는 kordoc v4 문서 엔진을 선택적으로 사용합니다.

- 고급·페이지별 Markdown, 공통 문서 IR(JSON), RAG 구조 청크
- 표 추출·데이터표/레이아웃표 분류, 페이지 이미지 미리보기
- 블록·셀 단위 신구대조, 누름틀·양식 필드 분석과 자동 채우기
- 원본 서식 보존 텍스트 패치, 날짜·금액·붙임 등 공문서 표기법 검수
- Markdown을 보고서·계획서·기안문 프리셋 HWPX로 생성

이 기능에는 [Node.js 18 이상](https://nodejs.org/ko/download)이 필요합니다. 고급 문서 도구 창의
**Node.js LTS 받기** 버튼에서 설치 페이지를 열 수 있으며, 설치 후 앱을 다시 실행해야 합니다.
앱은 `npx -y kordoc@^4`로 MIT 라이선스의
kordoc 엔진을 실행하며, Node가 없어도 기존 HWP/HWPX 편집 기능은 그대로 사용할 수 있습니다.
폐쇄망 배포 환경은 사전에 kordoc npm 패키지를 내부 저장소나 오프라인 캐시에 준비해야 합니다.
설정은 `%APPDATA%\HwpAutoDocFit\settings.json`에 저장됩니다.
보고서 표준서식은 `□`, `ㅇ`, `-`, `※` 등 문장부호로 시작하는 문단에만
적용됩니다. 기호 앞 들여쓰기는 행정안전부 개조식 보고서 작성 표준
(`□` 0칸 → `ㅇ` 1칸 → `-` 2칸 → `※`·`•` 3칸)을 기본값으로 씁니다.
각 작업의 전체 로그는 원본 문서 폴더에
`원본파일명(작업로그-YYYYMMDD-HHMMSS).log`로 저장됩니다.

## 기본 검증

```powershell
.\.venv\Scripts\python.exe -m py_compile hwp-auto-docfit.py docfit_core\__init__.py docfit_core\hwpx.py
.\.venv\Scripts\python.exe -c "import runpy; runpy.run_path('hwp-auto-docfit.py', run_name='import_check')"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

GitLab CI는 연결된 Linux `security-deploy` Runner에서 공통 소스와 HWPX 코어를 검사합니다.
Windows EXE는 Windows에서 전체 테스트 후 빌드한 `release-assets/HWP_AutoDocFit.exe`를 태그
파이프라인이 공식 Release 자산으로 게시합니다.
실제 문서 편집 검증에는 한글과 보안 모듈 DLL이 필요합니다.
