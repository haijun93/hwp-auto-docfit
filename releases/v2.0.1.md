# v2.0.1 — 2026-10-28

HWP AutoDocFit 2.0.1 긴급 핫픽스 릴리즈 안내입니다.
본 버전은 2.0.0 배포 후 보고된 초기 실행 시 흰 화면(White Screen) 멈춤 현상과 창 닫기(X 버튼) 불가 및 프로세스 잔존 버그를 해결한 긴급 패치입니다.

> 파일변환 탭은 kordoc 변환 화면으로 교체하는 동안 잠시 비활성(누르면 "준비 중")입니다. 교체 화면은 2.0.2에 넣습니다.

---

## 🛠️ 긴급 수정 사항 (Hotfix)

### 0. 변환 엔진(kordoc) 버전 불일치로 새 PC에서 변환 기능이 안 되던 문제
- **현상**: 2.0.0은 동봉 변환 엔진이 4.24.9인데 앱은 4.21.30을 찾아, 이전 엔진이 없는 PC에서는 엔진이 배포되지 않음.
- **해결**: 앱·시험·꾸러미 정의를 4.24.9로 맞추고 버전을 범위(^)가 아닌 정확한 값으로 고정.

### 1. 창 닫기 안전 탈출구 보장 (Close Watchdog & Force Termination)
- **현상**: 프론트엔드가 초기 로딩 실패/지연 상태이거나 무응답일 때, 창 닫기(X)를 누르면 `enable_close_guard`로 인해 JavaScript 응답을 영구 대기하며 창이 닫히지 않고 백그라운드 프로세스가 남는 결함.
- **해결**:
  - `desktop_web_ui.py`: 창 닫기 요청 시 5.0초 워치독 타이머(`_close_timer`) 적용. 5초 내 프론트엔드 무응답 시 자동으로 `_force_close()`를 호출하여 자식 한/글 프로세스(`kill_owned()`) 및 백엔드를 강제 정리하고 종료.
  - 닫기 대기 상태에서 사용자가 우측 상단 X 버튼을 다시 누르면(연속 클릭) 타이머 대기 없이 즉시 `_force_close(native_event=True)` 수행.
  - 프론트엔드가 정상 응답할 경우 `acknowledge_close` RPC를 통해 타이머를 즉시 해제하여 저장/폐기 확인 창에서 안전하게 사용자의 선택을 보장.
  - `tests/test_desktop_close_watchdog.py`: 닫기 안전장치 6대 핵심 시나리오(연속 클릭, 타임아웃, 폴링 유지, 라이브 다이얼로그 취소 후 재시도 등) 단위 테스트 추가.

### 2. 초기 구동 흰 화면 원인 규명 및 렌더링 게이트 강화
- **원인**: WebView2의 대용량 자산(`NotoSansKR.ttf` 10.4MB, `canvaskit.wasm`) 로컬 서빙 및 외부 폰트 폴백 요청 시의 첫 프레임(First Frame) 지연 상태에서, 기존 빌드/스모크 검증 파이프라인이 단순히 타이틀바(`MainWindowTitle`)만 감지하고 조기 종료하여 렌더링 실패를 걸러내지 못함.
- **해결**:
  - `flutter_ui/web/index.html`: `flutter-first-frame` 이벤트 리스너를 통해 첫 프레임 렌더링 완료 시 `window.docfitFirstFrame = true` 플래그 설정 및 `#loading` 오버레이 안전 제거.
  - `scripts/smoke_webview_content.py`: WebView2 CDP(Chrome DevTools Protocol)를 연결하여 실제 뷰포트 스크린샷 잉크 비율 검사(`ink_fraction >= 0.005`) 및 비응답 X 종료를 자동 검증하는 고도화된 스모크 스크립트 구축.
  - GitHub Actions 워크플로(`.github/workflows/build-windows-exe.yml`): 정규 빌드 및 무응답 스모크를 필수 게이트로 편입.
