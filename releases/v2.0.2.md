# v2.0.2 — 2026-10-29

HWP AutoDocFit 2.0.2 릴리즈 안내입니다.
파일변환 탭을 열고, 다이어그램·마인드맵 탭이 각자 바로 작동하도록 고쳤으며, 변환 포맷 선택을 숫자 키패드 모양으로 바꿨습니다.

> 시작 속도 측정(CI, 기록용): SPLASH_MS_PLACEHOLDER. 2.0.2는 기능을 먼저 배포하고(사용자 결정), 시작 속도 목표(첫 실행 스플래시 100ms·재실행 1.5초)는 2.0.3부터 다시 배포 조건으로 적용합니다.

## 바뀐 점

### 1. 파일변환 탭 사용 가능
- 2.0.1에서 "준비 중"으로 막혀 있던 **파일변환** 탭을 열었습니다.
- 탭 화면의 **"여기에 파일을 놓으세요"** 영역에 파일을 끌어 놓거나 **파일 선택**을 누르면 곧바로 변환할 포맷을 고르는 창이 뜹니다.
- 변환이 끝나면 따로 만든 화면이 아니라 앱의 **"4. 결과 확인"** 화면에서 결과 파일 열기·폴더 보기를 그대로 씁니다.
- 파일변환 탭에 들어오면 작업 방식이 자동으로 '파일 변환'으로 바뀝니다. 문서 목록은 문서편집 탭과 함께 쓰므로, 이미 들어 있는 문서가 있으면 함께 변환됩니다.

### 2. 변환 포맷 선택을 숫자 키패드 모양으로
- 원형 메뉴를 키보드 숫자패드와 같은 3×4 사각 배열로 바꿨습니다.

  | 7 HWPX | 8 DOCX | 9 EPUB |
  |---|---|---|
  | 4 HTML | **5 취소** (원본 파일) | 6 MD |
  | 1 PDF | 2 PDF 압축 | 3 PDF 합치기 |
  | 0 JPG | . PNG | + TXT |

- 칸 왼쪽 위의 숫자 키(윗줄 숫자·숫자패드 모두)를 누르면 바로 그 포맷으로 변환합니다. 5번 또는 Esc는 취소입니다.
- 숫자패드는 NumLock이 꺼져 있어도 키 위치대로 고릅니다.
- 선택 창 크기를 예전 원형 메뉴보다 약 30% 줄였습니다(창 540×640 → 380×440).
- 고를 수 없는 칸은 눌러도 변환하지 않고 아래에 그 이유를 보여 줍니다(예전과 같음).

### 3. 다이어그램 탭이 바로 작동
- 탭 **다이어그램**을 누르면 "도형 편집기는 Flutter Windows 앱에서만 사용할 수 있어요." 안내만 나오던 문제를 고쳤습니다. 이제 상단 메뉴의 다이어그램과 같은 편집기가 다이어그램 모드로 열립니다.
- 탭 **마인드맵**이 마인드맵이 아니라 다이어그램 모드로 열리던 문제도 함께 고쳤습니다.

### 4. 다이어그램·마인드맵 편집기 상단 줄 정리
- 편집기 위쪽의 제목("다이어그램·마인드맵"), 문서 이름("새 다이어그램·마인드맵"), 모드 전환 버튼(다이어그램·마인드맵·표 템플릿)을 없앴습니다. 모드는 탭이 정하고, 표 템플릿은 표템플릿 탭을 씁니다.
- 편집 도구 줄(새 문서·열기·삭제·저장·사본 저장·그림 복사·PNG 내보내기)이 맨 위에 옵니다. '사본 저장'은 편집 도구 줄로 옮겼습니다.
- 새 문서 이름은 탭에 맞게 "새 다이어그램" / "새 마인드맵"으로 정해지고, 마인드맵 탭에서 '새 문서'를 눌러도 마인드맵 모드가 유지됩니다.

## 시험

- Flutter 위젯 시험 전체 통과(키패드 배치·숫자 키 선택·취소, 6개 탭 이동, 다이어그램/마인드맵 탭 모드, 파일변환 탭 드롭 영역·파일 선택).
- 다이어그램 편집기 모델 시험(`diagram_editor`) 통과, 편집기 다시 빌드.
- Python 단위 시험 전체 통과.
- 실제 앱(소스 실행, WebView2) 화면 시험: 다이어그램·마인드맵·파일변환 탭 화면 확인, 파일변환 탭에서 HWPX 사본 추가 → 키패드 자동 표시 → 숫자패드 + 로 TXT 변환, 숫자패드 1(NumLock 꺼짐)로 한/글 PDF 변환 → 「4. 결과 확인」 표시까지 성공.
- 마우스로 파일을 끌어 놓는 동작 자체는 사람이 직접 확인해야 합니다(시험은 같은 백엔드 경로로 파일을 넣었음).
