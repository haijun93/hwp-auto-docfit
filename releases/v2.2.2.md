# v2.2.2 릴리스

HWP AutoDocFit 2.2.2 릴리스 안내입니다.

## 바뀐 점

### 서식 규칙

- 기호·번호 바로 뒤에 「가 오면 무조건 빈칸을 두지 않습니다(`ㅇ「법령」`, `2.「법령」`, `1)「법령」`). 뒤에 일반 글자가 오면 빈칸 1칸입니다.
- 내어쓰기: 저장 직후 기준 서식 값으로 덮어쓰던 단계를 없앴습니다. 한/글에서 잰 Shift+Tab 값이 결과 파일까지 그대로 남습니다. 부연설명 `*`, `**`와 `□` 줄, 서식 예시의 고정 값 문단도 같습니다.
- 붙임: `붙임: 1. 시행계획 1부`처럼 번호로 시작하면 줄 끝에 마침표가 없어도 붙임 목록입니다. 붙임 표 준말로 잘못 바꾸던 문제를 고쳤습니다.

Python 3.14 기반으로 빌드합니다.

---

## 배포 검증

- CI 실행 41363233466 통과(Python 3.14, 회귀 시험 포함). 첫 실행은 스플래시 106ms로 기준 100ms를 넘어 다시 실행했습니다. 통과한 실행의 시작 속도: 스플래시 49ms, 캐시 실행 747ms, 다시 켤 때 화면 1,480ms·1,377ms(기준 1,500ms).
- 소스 시험: Python 2,007건 실행, 실패 1건(`□` 줄을 0으로 초기화하던 옛 동작 검사)을 새 규칙에 맞게 고친 뒤 해당 시험 통과. CI 회귀 시험 통과.
- 배포 exe 시험: 내려받은 Portable·Setup의 SHA-256 일치, 화면 내용 시험 통과(화면 오류 0건), 탐색기 보내기 인자(`--rename`)가 새로 켤 때와 이미 켜져 있을 때 모두 파일명 일괄변경 목록에 들어감을 격리 환경에서 확인했습니다.
- 서식 복사 재연 시험(실제 한/글, 예시 5건): 불일치 0·0·0·2·0건. **아직 불합격입니다.** 남은 2건은 `내어쓰기 테스트(일괄적용)`의 표 높이·쪽 설정입니다. 판정 기준을 바꾸었습니다: 내어쓰기 값은 예시 값이 아니라 결과 문서의 실제 Shift+Tab과 비교하고(5건 모두 차이 0), 붙임 줄·빈 줄 정리는 규칙 결과로 봅니다. `내어쓰기 테스트(XML내어쓰기)`는 제목·개요를 표로 바꾸는 원고 예시라 재연 목록에서 뺐습니다.
- 마침표 없는 붙임 합성 시험(실제 한/글): 준말 변환 0건, 번호 뒤 본문 시작 121.8pt·121.7pt로 정렬 확인.

## 알려진 문제

- 표 높이(8082→5982)와 쪽 여백 재연 차이가 남아 있습니다.
- 이번 시험은 실제 탐색기 '보내기' 클릭, K클립보드 실제 복사 기록을 확인하지 않았습니다.
